# 硬件框图：7 个功能模块及输入输出

> 已更新为：[控制与数据分区：8 个模块输入输出](hardware_blocks_8.md)。请按新版画图；下面保留上一版归组供对照。

依据：2026-09-27 当前工作区的队列入口版 RTL。

这是**画图时的功能归组**，只调整文档，不修改硬件代码。加速器顶层画成包住以下 7 个模块的大框；CPU 和 RAM 画在框外。

每个模块的输入、输出放在同一张表中。方向相对于本节模块，位宽单位为 bit；并列信号注明“各”的表示每根信号的位宽。表中保留实际信号名，跨模块名称变化用箭头表示。

所有时序模块共用外部 `clk`（1 位时钟）、`rst_n`（1 位低有效复位），画图可统一标注，不必反复画线。表内的复位/清理信号是另行控制的同步清理信号。

## 模块归组

| 编号 | 框图名称 | 包含的元件或逻辑 |
|---|---|---|
| 1 | MMIO 寄存器组 | `accelerator_regs` |
| 2 | 任务调度模块 | `task_queue_controller`，含任务读取器 `task_descriptor_reader`、任务 FIFO `task_descriptor_fifo` |
| 3 | 卷积控制与地址生成模块 | `systolic_conv_controller` 的调度、数据选择与请求转接逻辑，加上 `conv_window_address`、`address_generator` |
| 4 | 数据读取缓存模块 | `systolic_read_cache`，含输入数据、权重/偏置两路整字缓存 |
| 5 | 脉动阵列计算模块 | `systolic_tile`，含 A/B/偏置缓冲、馈数控制、`systolic_array8` 和 64 个 `systolic_pe` |
| 6 | 结果量化与输出模块 | `quantizer`、`output_buffer` |
| 7 | RAM 访问模块 | `accelerator_mem_if`，加上顶层的两路请求选择、响应分配逻辑 |

**层级说明：**代码里模块 4、5、6 都实例化在 `systolic_conv_controller` 内部。这里为了表示功能关系，将它们展开为独立方框；第 3 个框只表示剩余的控制、地址生成和转接部分。任务读取器和 FIFO 则收进第 2 个框，不再单独占框。

## 1. MMIO 寄存器组

**功能：**接收 CPU 的任务表地址、任务数量和启动命令，向 CPU 返回运行状态。

| 方向 | 信号 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `mmio_addr` | 32 | CPU → 本模块 | 选择要访问的寄存器 |
| 输入 | `mmio_wdata` | 32 | CPU → 本模块 | 要写入寄存器的内容 |
| 输入 | `mmio_we`、`mmio_re` | 各 1 | CPU → 本模块 | 写请求、读请求 |
| 输入 | `accelerator_busy` | 1 | 模块 2 的 active、模块 3 的 busy、模块 7 的非空闲状态汇总 → 本模块 | 加速器是否仍在工作 |
| 输入 | `accelerator_done`、`accelerator_error` | 各 1 | 模块 2 的 done/error → 本模块 | 整个任务队列完成或失败 |
| 输出 | `mmio_rdata` | 32 | 本模块 → CPU | CPU 读取的寄存器内容 |
| 输出 | `mmio_ready` | 1 | 本模块 → CPU | 本次寄存器访问可以被接收 |
| 输出 | `accelerator_start`、`op_type` | 1、4 | 本模块 → 模块 2 的 start、op_type | 提交队列；此时 op_type 为 15 |
| 输出 | `input_addr`、`feature_size` | 各 32 | 本模块 → 模块 2 同名输入 | 任务表在 RAM 中的起始地址、任务数量 |
| 输出 | `accelerator_reset` | 1 | 本模块 → 模块 2 的 soft_reset、模块 3 的 clear、模块 7 的 cancel；模块 3 再清理 4/5/6 | 软件复位请求 |

**简释：**`mmio_addr` 决定“写哪个寄存器”，`mmio_wdata` 决定“写什么”。这里的 `input_addr` 是任务表地址，不是卷积输入数据地址；`feature_size` 在此处表示任务数量。

## 2. 任务调度模块

**功能：**读取任务表，暂存完整任务，按顺序交给模块 3 执行，并统计队列是否完成。读取器与 FIFO 之间的连线都留在本框内部。

| 方向 | 信号 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `start`、`op_type` | 1、4 | 模块 1 → 本模块 | 启动队列的命令 |
| 输入 | `input_addr`、`feature_size` | 各 32 | 模块 1 → 本模块 | 任务表起始地址、任务数量 |
| 输入 | `soft_reset` | 1 | 模块 1 → 本模块 | 清理队列、读取器和 FIFO 的状态 |
| 输入 | `exec_busy`、`exec_done`、`exec_error` | 各 1 | 模块 3 → 本模块 | 当前计算任务忙、完成、出错 |
| 输入 | `mem_idle` | 1 | 模块 7 → 本模块 | RAM 接口是否空闲 |
| 输入 | `fetch_ready` | 1 | 模块 7 → 本模块 | 本次任务读取请求可以被接收 |
| 输入 | `fetch_rsp_valid`、`fetch_rsp_data` | 1、32 | 模块 7 → 本模块内部任务读取器 | 从 RAM 返回的一段任务描述数据及有效标志 |
| 输出 | `fetch_phase` | 1 | 本模块 → 模块 7 | 当前处于读取任务表阶段，选择任务读取通路 |
| 输出 | `fetch_valid`、`fetch_addr` | 1、32 | 本模块内部任务读取器 → 模块 7 | 任务读取请求及地址 |
| 输出 | `exec_start` | 1 | 本模块 → 模块 3 的 start | 开始执行 FIFO 队首任务 |
| 输出 | `task_op` | 4 | 本模块 → 模块 3 的 op | 普通卷积或 DW 类型 |
| 输出 | `task_input`、`task_output`、`task_weight`、`task_bias` | 各 32 | 本模块 → 模块 3 的 ia、oa、wa、ba | 输入、输出、权重、偏置在 RAM 中的地址 |
| 输出 | `task_size`、`task_channels`、`task_param` | 各 32 | 本模块 → 模块 3 的 fs、ch、lp | 特征图尺寸、通道配置、卷积参数 |
| 输出 | `active`、`queue_base`、`queue_end` | 1、32、64 | 本模块 → 模块 3 的 queue_active、queue_base、queue_end；active 同时参与模块 1 的忙状态汇总 | 队列有效状态和任务表地址范围，供写入保护使用 |
| 输出 | `done`、`error` | 各 1 | 本模块 → 模块 1 | 整队列完成或失败 |

**简释：**`fetch_*` 用于从 RAM 取任务；`task_*` 是从 FIFO 中取出的任务配置。一次返回 32 位，读取器收齐 8 次后组成一条 256 位任务。FIFO 输出和出队控制都在本模块内部。

## 3. 卷积控制与地址生成模块

**功能：**接收一条任务，计算访问地址，安排数据加载、分块计算、结果选择与写回，完成后通知模块 2。

本表中的 `read_*`、`cache_*`、`tile_*`、`raw`、`out_value` 是现有控制器内部连线名，画成 7 个功能框后，它们就是框与框之间的连接。

| 方向 | 信号 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `start`、`op` | 1、4 | 模块 2 → 本模块 | 启动本条任务、选择卷积类型 |
| 输入 | `ia`、`oa`、`wa`、`ba` | 各 32 | 模块 2 → 本模块 | 输入、输出、权重、偏置基地址 |
| 输入 | `fs`、`ch`、`lp` | 各 32 | 模块 2 → 本模块 | 尺寸、通道、卷积参数 |
| 输入 | `queue_active`、`queue_base`、`queue_end` | 1、32、64 | 模块 2 → 本模块 | 检查输出区域是否会覆盖任务表 |
| 输入 | `clear` | 1 | 模块 1 → 本模块 | 清理当前任务状态 |
| 输入 | `read_ready`、`read_done`、`read_data` | 1、1、32 | 模块 4 → 本模块 | 缓存可接收请求、返回数据有效、返回数据 |
| 输入 | `cache_valid`、`cache_addr` | 1、32 | 模块 4 → 本模块 | 缓存未命中时需要转交 RAM 的读请求 |
| 输入 | `tile_busy`、`tile_done`、`sums` | 1、1、2048 | 模块 5 → 本模块 | 当前分块的计算状态、64 个 32 位累加结果 |
| 输入 | `out_value` | 8 | 模块 6 → 本模块 | 待写回 RAM 的量化结果 |
| 输入 | `cmd_ready`、`rsp_valid`、`rsp_data` | 1、1、32 | 模块 7 → 本模块 | RAM 请求被接收、事务完成、读回数据 |
| 输出 | `busy`、`done`、`error` | 各 1 | 本模块 → 模块 2；busy 同时参与模块 1 的忙状态汇总 | 整条计算任务的状态 |
| 输出 | `read_request`、`read_address` | 1、32 | 本模块 → 模块 4 的 req_valid、req_addr | 请求读取输入、权重或偏置 |
| 输出 | 缓存 `req_byte`、`req_bank` | 各 1 | 本模块 → 模块 4 | 选择字节/整字读取、输入/参数缓存 |
| 输出 | `cache_ready`、缓存 `rsp_valid`、`rsp_data` | 1、1、32 | 本模块转接模块 7 的响应 → 模块 4 | 将 RAM 读请求的接收与返回信息交给缓存 |
| 输出 | tile `start`、`accumulate`、`dw` | 各 1 | 本模块 → 模块 5 | 启动分块、是否继续累加、是否 DW |
| 输出 | `nr`、`nc`、`nk` | 各 4 | 本模块 → 模块 5 的 rows、cols、depth | 当前块有效行数、列数和累加长度 |
| 输出 | `a_we`、`b_we`、`bias_we` | 各 1 | 本模块 → 模块 5 | 将本次数据写入哪个缓冲 |
| 输出 | `row`、`col`、`kidx` | 各 3 | 本模块 → 模块 5 的 wr_row、wr_col、wr_k | 缓冲写入位置 |
| 输出 | tile `wr_value`、`wr_bias` | 8、32 | 模块 4 数据经本模块选择 → 模块 5 | 输入/权重字节或偏置；越界填充位置提供零 |
| 输出 | `raw`、量化 `shift`、输出暂存 `we` | 32、8、1 | 本模块 → 模块 6 | 选中的一个累加结果、右移位数、保存结果使能 |
| 输出 | 子模块 `clear` | 各 1 | 本模块 → 模块 4、5、6 | 软件复位或开始检查新任务时清理子模块 |
| 输出 | `cmd_valid`、`cmd_write`、`cmd_byte`、`cmd_addr`、`cmd_wdata` | 1、1、1、32、32 | 本模块 → 模块 7 | 转交缓存读请求，或发出结果字节写回请求 |

**简释：**本模块是执行一条卷积任务的协调者。它把缓存数据送到计算缓冲，再启动阵列；阵列返回整块结果后，它逐个选择结果送去量化，最后安排写回。`done` 表示整条任务结束，`tile_done` 只表示一个分块计算结束。

## 4. 数据读取缓存模块

**功能：**缓存最近读取的 32 位整字，同一整字中的多个字节可以重复使用，减少 RAM 访问。两路分别服务输入数据和参数（权重/偏置）。

| 方向 | 信号 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `clear` | 1 | 模块 3 → 本模块 | 清除缓存有效状态 |
| 输入 | `req_valid`、`req_addr` | 1、32 | 模块 3 → 本模块 | 请求读取数据及字节地址 |
| 输入 | `req_byte`、`req_bank` | 各 1 | 模块 3 → 本模块 | 返回一个字节还是整字；选择哪一路缓存 |
| 输入 | `cmd_ready` | 1 | 模块 7 经模块 3 → 本模块 | RAM 读请求被接收 |
| 输入 | `rsp_valid`、`rsp_data` | 1、32 | 模块 7 经模块 3 → 本模块 | RAM 返回的整字数据及有效标志 |
| 输出 | `req_ready` | 1 | 本模块 → 模块 3 | 可以接收新的读取请求 |
| 输出 | `response_valid`、`response_data` | 1、32 | 本模块 → 模块 3 | 本次所需数据及有效标志，再由模块 3 送入模块 5 |
| 输出 | `cmd_valid`、`cmd_addr` | 1、32 | 本模块 → 模块 3 → 模块 7 | 缓存未命中时发出的整字读取请求 |

**简释：**命中时直接返回已有数据；未命中时才读 RAM。`req_byte=1` 时，所需字节放在 `response_data[7:0]`；读取偏置时返回完整 32 位。缓存负责复用数据，模块 3 负责决定把数据装进哪个计算缓冲。

## 5. 脉动阵列计算模块

**功能：**把输入、权重和偏置存入分块缓冲，按时序送入 8×8 阵列，输出累加结果。缓冲、馈数控制、阵列和 PE 都在同一个框内。

| 方向 | 信号 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `clear` | 1 | 模块 3 → 本模块 | 清理计算控制状态 |
| 输入 | `ce` | 1 | 控制器内部常量 1 → 本模块 | 允许模块推进，画图可标常量 1 |
| 输入 | `start`、`accumulate`、`dw` | 各 1 | 模块 3 → 本模块 | 启动当前块、接着已有结果累加、选择 DW 模式 |
| 输入 | `rows`、`cols`、`depth` | 各 4 | 模块 3 → 本模块 | 本块有效的输出通道数、空间位置数、累加长度 |
| 输入 | `a_we`、`b_we`、`bias_we` | 各 1 | 模块 3 → 本模块 | 权重缓冲、输入缓冲、偏置缓冲写使能 |
| 输入 | `wr_row`、`wr_col`、`wr_k` | 各 3 | 模块 3 → 本模块 | 本次写入缓冲的位置 |
| 输入 | `wr_value` | 8，有符号 | 模块 4 返回值经模块 3 选择，或模块 3 生成的填充零 → 本模块 | 一份输入或权重数据 |
| 输入 | `wr_bias` | 32，有符号 | 模块 4 返回值经模块 3 → 本模块 | 一个输出通道的偏置 |
| 输出 | `busy`、`done` | 各 1 | 本模块 → 模块 3 | 当前分块正在计算、当前分块计算完成 |
| 输出 | `sums` | 2048 | 本模块 → 模块 3 | 64 个累加结果，每个 32 位有符号数 |

**简释：**`a_we/b_we/bias_we` 决定数据存入哪个缓冲，`wr_*` 决定存哪里、存什么。数据装好后才发 `start`。`accumulate=0` 从偏置开始，`accumulate=1` 接着上一段累加结果计算。

## 6. 结果量化与输出模块

**功能：**把一个 32 位累加结果转换为 8 位有符号数，再暂存，等待写回 RAM。

| 方向 | 信号 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | 量化器 `value`，连接 `raw` | 32，有符号 | 模块 5 的 sums 经模块 3 选择 → 本模块 | 本次要处理的一个累加结果 |
| 输入 | 量化器 `shift` | 8 | 模块 3 锁存的 lp[19:12] → 本模块 | 算术右移的位数 |
| 输入 | 输出暂存器 `we` | 1 | 模块 3 → 本模块 | 保存当前量化结果 |
| 输入 | 输出暂存器 `clear` | 1 | 模块 3 → 本模块 | 清理输出暂存值 |
| 输出 | 输出暂存器 `rdata`，连接 `out_value` | 8 | 本模块 → 模块 3 → 模块 7 → RAM | 本次准备写回的量化结果 |

**简释：**先按 `shift` 右移，再把数值限制在 −128～127，保存为一个字节。`we` 控制何时保存；保存后保持数据，供模块 3 发起写回。这里只有一个结果暂存寄存器。

## 7. RAM 访问模块

**功能：**在任务读取和计算读写之间选择当前请求，把请求转换为 RAM 访问，并把响应送回对应模块。结果按字节写入时，由本模块完成整字的读、修改、写回。

| 方向 | 信号 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `cancel` | 1 | 模块 1 的 accelerator_reset → 本模块 | 取消当前内部命令并收尾已经发出的 RAM 事务 |
| 输入 | `fetch_phase` | 1 | 模块 2 → 本模块内的请求选择逻辑 | 选择任务读取通路或计算通路 |
| 输入 | `fetch_valid`、`fetch_addr` | 1、32 | 模块 2 → 本模块 | 任务表读取请求 |
| 输入 | 计算侧 `cmd_valid`、`cmd_write`、`cmd_byte`、`cmd_addr`、`cmd_wdata` | 1、1、1、32、32 | 模块 3 → 本模块 | 计算所需的读请求或结果写回请求 |
| 输入 | `sx_busy` | 1 | 模块 3 的 busy → 本模块内的响应分配逻辑 | 使计算侧握手、响应只在执行器工作时有效 |
| 输入 | `mem_rdata`、`mem_ready` | 32、1 | 外部 RAM → 本模块 | RAM 读回数据、当前读写事务完成 |
| 输出 | `fetch_ready`、`fetch_rsp_valid`、`fetch_rsp_data` | 1、1、32 | 本模块 → 模块 2 | 任务读取请求接收标志和读回的数据 |
| 输出 | 计算侧 `cmd_ready`、`rsp_valid`、`rsp_data` | 1、1、32 | 本模块 → 模块 3，读响应再转模块 4 | 计算读写请求接收标志和完成响应 |
| 输出 | `idle`，顶层连接 `mem_idle` | 1 | 本模块 → 模块 2，同时参与模块 1 的忙状态汇总 | 当前没有未完成的 RAM 命令 |
| 输出 | `mem_addr`、`mem_wdata` | 各 32 | 本模块 → 外部 RAM | 外部访问地址、整字写入数据 |
| 输出 | `mem_read`、`mem_write` | 各 1 | 本模块 → 外部 RAM | 外部读请求、写请求 |

**简释：**`cmd_ready` 表示命令被接收，`rsp_valid` 才表示内部命令完成；`mem_ready` 是外部 RAM 对一次总线访问的完成反馈。一次结果字节写回可能需要先读一个整字，再修改对应字节并写回。

## 画图时的主要连接

下面是连接关系，箭头可以合并标注成总线，不必把表中每根握手线都画出来。

```text
CPU ⇄ [1 MMIO 寄存器组] ⇄ [2 任务调度模块] ⇄ [3 卷积控制与地址生成]
                                ⇅                    ⇅
                           [7 RAM 访问模块] ⇄────────┘
                                ⇅
                              外部 RAM

[3 卷积控制与地址生成] ⇄ [4 数据读取缓存]
[3 卷积控制与地址生成] ⇄ [5 脉动阵列计算]
[3 卷积控制与地址生成] ⇄ [6 结果量化与输出]
```

实际数据流分三条标注：

- **任务：**RAM → 7 → 2 内部读取器 → 2 内部 FIFO → 2 内部任务分发 → 3。
- **输入、权重、偏置：**RAM → 7 → 3 转接 → 4 → 3 选择/填充 → 5。
- **计算结果：**5 → 3 选择一个结果 → 6 → 3 发起写回 → 7 → RAM。

画数据流时，模块 2 到模块 3 的 `task_input/task_weight` 等标注为“地址与配置”，不要标成参与乘加的数据。时钟、复位和状态反馈可用统一标注或虚线表示。

逐个 RTL 模块的接口细节见：[硬件输入输出详细说明](hardware_inputs_outputs_queue_only.md)。
