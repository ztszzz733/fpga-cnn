# 硬件框图：控制与数据分区，8 个模块输入输出

依据：2026-09-27 当前工作区的队列入口版 RTL。本文只调整框图和说明，不修改代码。

**共 8 个模块，包含一个较小的输出模块。CPU、RAM 不计入数量。RAM 访问接口、请求选择和响应分配统一收进 RAM 框。** 图中的 RAM 框代表“RAM 及访问逻辑”，其中 RAM 本体负责存储。

每个模块的输入输出放在同一张表中，位宽单位为 bit，“各”表示每根信号的位宽。所有时序模块共用 `clk`（1 位）和 `rst_n`（1 位低有效复位），图边统一标注即可。

## 模块与布局

| 编号 | 框图名称 | 所属区域 | 包含内容 |
|---|---|---|---|
| 1 | MMIO 寄存器组 | 控制区 | 配置接收、状态返回 |
| 2 | 队列控制器 | 控制区 | 取任务调度、队首解析、执行调度 |
| 3 | 任务读取器 | 任务数据区 | 从 RAM 分次读取并组装完整任务 |
| 4 | 任务 FIFO | 任务数据区 | 暂存完整任务 |
| 5 | 卷积控制与地址生成 | 控制区 | 参数检查、地址生成、加载/计算/写回控制 |
| 6 | 数据读取缓存 | 计算数据区 | 输入数据与权重/偏置两路整字缓存 |
| 7 | 分块缓冲与脉动阵列 | 计算数据区 | 填充零选择、A/B/偏置缓冲、馈数控制、8×8 阵列及 PE |
| 8 | 输出处理（小模块） | 计算数据区 | 结果选择、量化、单字节输出暂存 |

上方放控制区，下方放数据区；RAM 放左侧，输出小模块放阵列右侧。实线表示任务内容和计算数据，虚线表示控制与状态反馈，地址和配置另行标注。

```text
控制区： CPU ⇄ [1 MMIO 寄存器组] ⇄ [2 队列控制器] ⇄ [5 卷积控制与地址生成]
                                      ⋮                     ⋮
                              启动读取、FIFO 出队      装载、计算、量化、写回

任务数据区： RAM ──32 位任务字──> [3 任务读取器] ──256 位任务──> [4 任务 FIFO]
                                                                    │
                                                   队首任务 → [2 队列控制器]

计算数据区： RAM ──32 位读回值──> [6 数据读取缓存] ──数据──> [7 分块缓冲与脉动阵列]
                                                                     │
                                                           64 × 32 位结果
                                                                     ↓
              RAM <──结果字节写回── [8 输出处理：选择 → 量化 → 暂存]
```

上图所有 RAM 标记表示同一个 RAM 框。控制区会接收任务配置和状态，但参与乘加的数值沿计算数据区流动。

**与代码的对应：**这是功能框图。代码中的 `task_queue_controller` 在图中展开成 2、3、4；`systolic_conv_controller` 展开成 5、6、7、8。为分开控制与数据，将现有控制器内的输入填充零选择归入 7、结果选择归入 8，读写请求与数据转接归入 RAM 框。纯接线中转省略，不改变实际行为。表中注明“内部连接”的信号是现有逻辑间连线，不是新增 RTL 端口。

## 1. MMIO 寄存器组

**功能：**接收 CPU 的任务表地址、数量和启动命令，向 CPU 返回状态。

| 方向 | 信号 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `mmio_addr`、`mmio_wdata` | 各 32 | CPU → 本模块 | 选择寄存器、写入配置内容 |
| 输入 | `mmio_we`、`mmio_re` | 各 1 | CPU → 本模块 | 写、读寄存器请求 |
| 输入 | `accelerator_busy` | 1 | 模块 2 的 active、模块 5 的 busy、RAM 访问忙状态汇总 → 本模块 | 加速器是否仍在工作 |
| 输入 | `accelerator_done`、`accelerator_error` | 各 1 | 模块 2 → 本模块 | 整队列完成或失败 |
| 输出 | `mmio_rdata`、`mmio_ready` | 32、1 | 本模块 → CPU | 读回内容、访问接收标志 |
| 输出 | `accelerator_start`、`op_type` | 1、4 | 本模块 → 模块 2 的 start、op_type | 启动队列，op_type 为 15 |
| 输出 | `input_addr`、`feature_size` | 各 32 | 本模块 → 模块 2 | 任务表起始地址、任务数量 |
| 输出 | `accelerator_reset` | 1 | 本模块 → 模块 2、5 和 RAM 框内访问逻辑；2、5 再清理子模块 | 软件复位 |

**简释：**`mmio_addr` 选择“哪个寄存器”，`mmio_wdata` 表示“写什么”。此处 `input_addr` 是任务表地址，`feature_size` 是任务数量。

## 2. 队列控制器

**功能：**决定何时取任务、何时允许 FIFO 出队、何时启动下一条计算任务。实际读取和暂存由模块 3、4 完成。

| 方向 | 信号/连接 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `start`、`op_type` | 1、4 | 模块 1 → 本模块 | 提交队列的命令 |
| 输入 | `input_addr`、`feature_size` | 各 32 | 模块 1 → 本模块 | 任务表地址、任务数量 |
| 输入 | `soft_reset` | 1 | 模块 1 → 本模块 | 清理队列状态 |
| 输入 | `reader_idle` | 1 | 模块 3 的 idle → 本模块 | 读取器可以开始下一条任务 |
| 输入 | `reader_valid`、`reader_ready` | 各 1 | 模块 3 的 descriptor_valid、模块 4 的 in_ready → 本模块 | 判断是否成功将一条任务放入 FIFO |
| 输入 | `head_data`、`head_valid` | 256、1 | 模块 4 的 out_data、out_valid → 本模块 | 队首完整任务、有效标志 |
| 输入 | `buffered` | 32 | 模块 4 的 level → 本模块 | FIFO 当前任务数 |
| 输入 | `exec_busy`、`exec_done`、`exec_error` | 各 1 | 模块 5 → 本模块 | 当前计算任务忙、完成、出错 |
| 输入 | `mem_idle` | 1 | RAM 框内访问逻辑 → 本模块 | 是否还有未完成的 RAM 命令 |
| 输出 | 读取器 start、base_address 的驱动连接 | 1、32 | 本模块 → 模块 3 | 开始读取及本条任务起始地址 |
| 输出 | `flush` | 1 | 本模块 → 模块 3、4 的 clear | 新队列开始或软件复位时清理旧状态 |
| 输出 | `head_ready` | 1 | 本模块 → 模块 4 的 out_ready | 允许接收并弹出队首 |
| 输出 | `exec_start`、`task_op` | 1、4 | 本模块 → 模块 5 的 start、op | 启动计算及普通卷积/DW 类型 |
| 输出 | `task_input`、`task_output`、`task_weight`、`task_bias` | 各 32 | 本模块 → 模块 5 的 ia、oa、wa、ba | 输入、输出、权重、偏置基地址 |
| 输出 | `task_size`、`task_channels`、`task_param` | 各 32 | 本模块 → 模块 5 的 fs、ch、lp | 尺寸、通道、卷积参数 |
| 输出 | `active`、`queue_base`、`queue_end` | 1、32、64 | 本模块 → 模块 5；active 同时参与模块 1 的忙状态汇总 | 队列有效状态和任务表范围，用于写入保护 |
| 输出 | `fetch_phase` | 1 | 本模块 → RAM 框内请求选择逻辑 | 当前让任务读取器使用 RAM |
| 输出 | `done`、`error` | 各 1 | 本模块 → 模块 1 | 整队列完成或失败 |

**简释：**本模块接收 FIFO 数据并解析任务，同时用 `head_ready` 控制出队。`reader_valid && reader_ready` 表示任务入队，`head_valid && head_ready` 表示任务出队并启动计算。读取器的 RAM 数据通路直接画到 RAM，省略经过队列模块端口的纯接线中转。

## 3. 任务读取器

**功能：**读取 8 个 32 位字，组装成一条 256 位任务。

| 方向 | 信号 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `start`、`base_address` | 1、32 | 模块 2 → 本模块 | 开始读取、本条任务首地址 |
| 输入 | `clear` | 1 | 模块 2 的 flush → 本模块 | 清理读取状态 |
| 输入 | `cmd_ready` | 1 | RAM 框 → 本模块 | 当前读请求被接收 |
| 输入 | `rsp_valid`、`rsp_data` | 1、32 | RAM 框 → 本模块 | 返回的一个任务字及有效标志 |
| 输入 | `descriptor_ready` | 1 | 模块 4 的 in_ready → 本模块 | FIFO 可以接收完整任务 |
| 输出 | `idle` | 1 | 本模块 → 模块 2 | 读取器空闲 |
| 输出 | `cmd_valid`、`cmd_addr` | 1、32 | 本模块 → RAM 框 | 读取请求、当前字地址 |
| 输出 | `descriptor_valid` | 1 | 本模块 → 模块 4 的 in_valid，同时供模块 2 统计入队 | 完整任务有效 |
| 输出 | `descriptor` | 256 | 本模块 → 模块 4 的 in_data | 完整任务描述 |

**简释：**`rsp_data` 是每次返回的片段，`descriptor` 是收齐后的任务。每读完一个字，地址增加 4 字节；FIFO 接收完整任务后读取器回到空闲。

## 4. 任务 FIFO

**功能：**按先入先出顺序暂存任务，当前默认最多存 4 条。

| 方向 | 信号 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `clear` | 1 | 模块 2 的 flush → 本模块 | 清空有效状态 |
| 输入 | `in_valid`、`in_data` | 1、256 | 模块 3 → 本模块 | 完整任务及有效标志 |
| 输入 | `out_ready` | 1 | 模块 2 的 head_ready → 本模块 | 允许队首任务出队 |
| 输出 | `in_ready` | 1 | 本模块 → 模块 3，同时供模块 2 判断/统计入队 | 仍有空间接收任务 |
| 输出 | `out_valid`、`out_data` | 1、256 | 本模块 → 模块 2 | 队首任务及有效标志 |
| 输出 | `level` | 32 | 本模块 → 模块 2 | 已暂存的任务数量 |

**简释：**`in_*` 对接读取器，`out_*` 对接队列控制器。FIFO 保存任务描述；特征和权重数值走模块 6、7 的计算数据通路。

## 5. 卷积控制与地址生成

**功能：**决定读什么地址、装载哪个缓冲、何时启动阵列、选择哪个结果，以及何时写回。

| 方向 | 信号/连接 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `start`、`op` | 1、4 | 模块 2 → 本模块 | 开始执行及卷积类型 |
| 输入 | `ia`、`oa`、`wa`、`ba` | 各 32 | 模块 2 → 本模块 | 输入、输出、权重、偏置基地址 |
| 输入 | `fs`、`ch`、`lp` | 各 32 | 模块 2 → 本模块 | 尺寸、通道、卷积参数 |
| 输入 | `queue_active`、`queue_base`、`queue_end` | 1、32、64 | 模块 2 → 本模块 | 检查输出区域是否覆盖任务表 |
| 输入 | `clear` | 1 | 模块 1 → 本模块 | 软件复位 |
| 输入 | `read_ready`、`read_done` | 各 1 | 模块 6 的 req_ready、response_valid → 本模块 | 可接收读取请求、所需数据已返回 |
| 输入 | `tile_busy`、`tile_done` | 各 1 | 模块 7 的 busy、done → 本模块 | 当前分块忙、完成 |
| 输入 | 写回时的 `cmd_ready`、`rsp_valid` | 各 1 | RAM 框 → 本模块 | 写回命令被接收、写回完成 |
| 输出 | `busy`、`done`、`error` | 各 1 | 本模块 → 模块 2；busy 同时用于模块 1 状态汇总和 RAM 响应分配 | 整条计算任务的状态 |
| 输出 | `read_request`、`read_address` | 1、32 | 本模块 → 模块 6 的 req_valid、req_addr | 读取输入、权重或偏置的请求及地址 |
| 输出 | 缓存 req_byte、req_bank 的驱动连接 | 各 1 | 本模块 → 模块 6 | 读字节/整字、选输入/参数缓存 |
| 输出 | tile start、accumulate、dw 的驱动连接 | 各 1 | 本模块 → 模块 7 | 启动分块、继续累加、选择 DW |
| 输出 | `nr`、`nc`、`nk` | 各 4 | 本模块 → 模块 7 的 rows、cols、depth | 当前块的行数、列数、累加长度 |
| 输出 | `a_we`、`b_we`、`bias_we` | 各 1 | 本模块 → 模块 7 | 权重、输入、偏置缓冲写使能 |
| 输出 | `row`、`col`、`kidx` | 各 3 | 本模块 → 模块 7 的 wr_row、wr_col、wr_k | 缓冲写入位置 |
| 输出 | 填充零选择条件（内部连接） | 1 | 本模块 → 模块 7 内的数据选择逻辑 | padding 位置写零 |
| 输出 | `row`、`col` | 各 3 | 本模块 → 模块 8 的结果选择逻辑 | 选择哪个累加结果 |
| 输出 | `clp[19:12]`、输出暂存 we 的驱动连接 | 8、1 | 本模块 → 模块 8 | 量化右移位数、保存结果使能 |
| 输出 | 写回请求、`output_address`（内部连接） | 1、32 | 本模块 → RAM 框 | 将模块 8 提供的一个字节写到指定地址 |
| 输出 | 子模块 clear 的驱动连接 | 各 1 | 本模块 → 模块 6、7、8 | 软件复位或新任务检查阶段清理状态 |

**简释：**模块 5 提供地址、位置和执行时机，计算数值沿下方数据区流动。`tile_done` 只结束一个分块，`done` 才结束整条任务。写回地址由模块 5 提供，写回数值由模块 8 提供。

## 6. 数据读取缓存

**功能：**复用从 RAM 读取的整字。输入数据一路，权重/偏置一路，每路暂存一个 32 位整字。

| 方向 | 信号 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `clear` | 1 | 模块 5 → 本模块 | 清除缓存有效状态 |
| 输入 | `req_valid`、`req_addr` | 1、32 | 模块 5 → 本模块 | 读取请求及所需地址 |
| 输入 | `req_byte`、`req_bank` | 各 1 | 模块 5 → 本模块 | 返回字节/整字、选择缓存路 |
| 输入 | `cmd_ready` | 1 | RAM 框 → 本模块 | 缓存未命中的读请求被接收 |
| 输入 | `rsp_valid`、`rsp_data` | 1、32 | RAM 框 → 本模块 | RAM 返回的整字及有效标志 |
| 输出 | `req_ready`、`response_valid` | 各 1 | 本模块 → 模块 5 | 请求可接收、所需数据已返回 |
| 输出 | `response_data` | 32 | 本模块 → 模块 7 的选择/缓冲写入通路 | 输入/权重用低 8 位，偏置用完整 32 位 |
| 输出 | `cmd_valid`、`cmd_addr` | 1、32 | 本模块 → RAM 框 | 缓存未命中时的整字读取请求 |

**简释：**命中则直接返回缓存值，未命中才访问 RAM。`response_valid` 通知模块 5 产生缓冲写使能，`response_data` 沿数据通路送到模块 7。

## 7. 分块缓冲与脉动阵列

**功能：**保存分块所需的输入、权重和偏置，再按时序送入 8×8 阵列完成乘加。

| 方向 | 信号/连接 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `clear` | 1 | 模块 5 → 本模块 | 清理计算控制状态 |
| 输入 | `ce` | 1 | 内部常量 1 → 本模块 | 允许时序推进，图上可标常量 1 |
| 输入 | `start`、`accumulate`、`dw` | 各 1 | 模块 5 → 本模块 | 启动本块、继续累加、选择 DW |
| 输入 | `rows`、`cols`、`depth` | 各 4 | 模块 5 → 本模块 | 有效输出通道数、空间位置数、累加长度 |
| 输入 | `a_we`、`b_we`、`bias_we` | 各 1 | 模块 5 → 本模块 | 写权重、输入、偏置缓冲 |
| 输入 | `wr_row`、`wr_col`、`wr_k` | 各 3 | 模块 5 → 本模块 | 缓冲写入位置 |
| 输入 | `read_data`（内部连接） | 32 | 模块 6 的 response_data → 本模块 | 输入、权重或偏置的返回值 |
| 输入 | 填充零选择条件（内部连接） | 1 | 模块 5 → 本模块 | 使用返回字节或填充零 |
| 输出 | `busy`、`done` | 各 1 | 本模块 → 模块 5 | 当前分块忙、完成 |
| 输出 | `sums` | 2048 | 本模块 → 模块 8 | 64 个 32 位有符号累加结果 |

**简释：**本框内部将 `read_data[7:0]` 或零作为 tile 的 `wr_value`，完整 `read_data` 作为 `wr_bias`，写使能决定实际保存哪种数据。装载完成后启动计算；`accumulate=0` 从偏置开始，`accumulate=1` 接着已有结果累加。

## 8. 输出处理（小模块）

**功能：**选择一个累加结果，量化为 8 位，再暂存等待写回。可在阵列右侧画一个小框。

| 方向 | 信号/连接 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|
| 输入 | `sums`（内部连接） | 2048 | 模块 7 → 本模块 | 整块 64 个累加结果 |
| 输入 | `row`、`col`（内部连接） | 各 3 | 模块 5 → 本模块 | 选择本次处理的 32 位结果 |
| 输入 | 量化器 `shift` | 8 | 模块 5 的 clp[19:12] → 本模块 | 算术右移位数 |
| 输入 | 输出暂存器 `we`、`clear` | 各 1 | 模块 5 → 本模块 | 保存量化结果、清理暂存值 |
| 输出 | `out_value`，即输出暂存器 rdata | 8 | 本模块 → RAM 框内写数据通路 → RAM | 待写回的一个结果字节 |

**简释：**内部选择一个 32 位结果作为 `raw`，右移并限制在 −128～127，保存到一个字节寄存器。模块 5 提供写回地址和时机，本模块提供数值；接现有 32 位写数据总线时高 24 位补零。

## 画线时的主要关系

- **控制主线：**CPU → 1 → 2 → 5；完成状态按 5 → 2 → 1 返回。
- **任务数据主线：**RAM → 3 → 4 → 2；2 将解析后的地址与配置送到 5。
- **计算数据主线：**RAM → 6 → 7 → 8 → RAM。
- **任务控制线：**2 → 3（启动、地址），2 → 4（出队），3/4 → 2（状态反馈）。
- **计算控制线：**5 → 6（读地址与请求），5 → 7（装载与启动），5 → 8（选择与量化），5 → RAM（写回地址与请求）。

握手信号可合并标注，每根信号的来源和去向以上表为准。当前按批次取任务后顺序执行，控制/数据分区不表示取任务与计算已经并行。

逐个 RTL 模块的接口细节见：[硬件输入输出详细说明](hardware_inputs_outputs_queue_only.md)。
