# 四大模块及 CPU、外部 RAM 的输入输出

依据：2026-09-29 当前工作区 `mobilefacenet_accelerator_top.sv` 的实际连接。

本文的四个模块是：**MMIO 寄存器组、队列控制器、阵列控制器、RAM 访问接口**。包含四个模块之间的有效接口，以及 CPU ↔ MMIO、RAM 访问接口 ↔ 外部 RAM 的全部接口。各模块内部连线不展开；CPU 和 RAM 作为外部连接对象，不计入四个大模块。公共 clk、rst_n 也列入各模块表。

每个模块的输入、输出放在同一张表内。方向相对于本节模块；位宽单位为 bit，“各”表示每根信号的位宽。相同名称在不同模块中可能代表不同接口，请结合来源、去向阅读。

顶层负责连接和少量选择逻辑。“经过顶层选择/门控”表示原代码确实经过逻辑处理，并不表示直接同名相连。

## 分类方法

按你提出的类别整理，并补上“输出地址”，共六类。每个模块仍用一张表，按类别排列，保留方向、位宽、来源和去向。

| 分类 | 本文含义 |
|---|---|
| 输入数据 | 从其他模块或外部 CPU/RAM 接收的内容，例如 RAM 返回的任务字或计算数据 |
| 输出数据 | 向其他模块或外部 CPU/RAM 发送的内容，例如计算结果或 RAM 读回值 |
| 输入地址 | 本模块从其他模块或 CPU 接收的访问地址或基地址 |
| 输出地址 | 本模块向其他模块或外部 RAM 提供的访问地址或基地址 |
| 控制信号 | 启动、复位、读写选择、valid/ready 握手，以及 busy/done/error/idle 等状态反馈 |
| 特殊信号 | 时钟，以及用于配置和保护的信息：操作类型、尺寸、通道数、任务数量、卷积参数及任务表保护范围 |

**“输入/输出”按本模块的端口方向判断。** 例如阵列控制器的 `oa` 虽然指定结果写到哪里，但它由队列送入，因此属于“输入地址”；阵列控制器发出的 `cmd_addr` 才属于“输出地址”。`cmd_wdata` 在阵列侧是输出数据，在 RAM 接口侧是输入数据。

**特殊信号只是本文件的整理类别，不是另一种硬件总线。** `queue_base/queue_end` 本质上也是地址，但在阵列侧用于范围保护，故归入特殊信号并在含义栏说明。没有某一类端口的模块不强行添加该类。

## 1. MMIO 寄存器组：accelerator_regs

| 分类 | 方向 | 本模块端口 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|---|
| 输入数据 | 输入 | `mmio_wdata` | 32 | CPU → 顶层同名端口 → 本模块 | CPU 本次准备写入寄存器的数据 |
| 输出数据 | 输出 | `mmio_rdata` | 32 | 本模块 → 顶层同名端口 → CPU | CPU 读取的配置或状态值 |
| 输入地址 | 输入 | `mmio_addr` | 32 | CPU → 顶层同名端口 → 本模块 | CPU 选择要访问的寄存器地址 |
| 输出地址 | 输出 | `input_addr` | 32 | 本模块 → 队列控制器 input_addr | 任务表起始地址 |
| 控制信号 | 输入 | `accelerator_busy` | 1 | 队列 active、阵列 busy、RAM 接口非空闲状态，经顶层汇总 → 本模块 | 任一部分仍在工作 |
| 控制信号 | 输入 | `accelerator_done` | 1 | 队列控制器 done → 本模块 | 整个任务队列完成 |
| 控制信号 | 输入 | `accelerator_error` | 1 | 队列控制器 error → 本模块 | 整个任务队列失败 |
| 控制信号 | 输出 | `accelerator_start` | 1 | 本模块 → 队列控制器 start | 提交任务队列的启动脉冲 |
| 控制信号 | 输出 | `accelerator_reset` | 1 | 本模块 → 队列 soft_reset、阵列 clear、RAM 接口 cancel | 软件复位/取消运行 |
| 控制信号 | 输入 | `mmio_we` | 1 | CPU → 顶层同名端口 → 本模块 | CPU 写寄存器请求 |
| 控制信号 | 输入 | `mmio_re` | 1 | CPU → 顶层同名端口 → 本模块 | CPU 读寄存器请求 |
| 控制信号 | 输出 | `mmio_ready` | 1 | 本模块 → 顶层同名端口 → CPU | 当前寄存器访问可以在本上升沿被接收 |
| 控制信号 | 输入 | `rst_n` | 1 | 外部系统复位 → 顶层 rst_n → 本模块 | 低有效全局复位；不同于软件复位命令 |
| 特殊信号 | 输出 | `op_type` | 4 | 本模块 → 队列控制器 op_type | 队列启动类型，当前合法值为 15 |
| 特殊信号 | 输出 | `feature_size` | 32 | 本模块 → 队列控制器 feature_size | 任务数量 |
| 特殊信号 | 输入 | `clk` | 1 | 外部系统时钟 → 顶层 clk → 本模块 | 公共时钟，各时序模块按时钟上升沿更新 |

**信号简释：**start 用于启动，reset 用于复位；busy/done/error 表示整体状态。此处 input_addr/feature_size 的含义是“任务表地址/任务数”。

|---|---|---|---|---|---|
| 输入数据 | 输入 | `fetch_rsp_data` | 32 | RAM 接口 rsp_rdata → 本模块 | 从 RAM 读回的一个任务字 |
| 输入地址 | 输入 | `input_addr` | 32 | MMIO input_addr → 本模块 | 任务表起始地址 |

| 控制信号 | 输入 | `exec_error` | 1 | 阵列控制器 error → 本模块 | 当前计算任务出错 |
| 控制信号 | 输入 | `mem_idle` | 1 | RAM 访问接口 idle → 本模块 | RAM 接口没有待完成命令 |
| 控制信号 | 输入 | `fetch_ready` | 1 | RAM 接口 cmd_ready，经顶层按 fetch_phase 门控 → 本模块 | 当前任务读取请求可以被接收 |
| 控制信号 | 输入 | `fetch_rsp_valid` | 1 | RAM 接口 rsp_valid，经顶层按 fetch_phase 门控 → 本模块 | 本次返回属于任务读取，数据有效 |
| 控制信号 | 输出 | `fetch_phase` | 1 | 本模块 → 顶层 RAM 请求选择、响应分配逻辑 | 为 1 时选择任务读取通路；不是 RAM 接口的独立端口 |
| 控制信号 | 输出 | `fetch_valid` | 1 | 本模块 → 顶层选择 → RAM 接口 cmd_valid | 发起任务字读取请求 |
| 控制信号 | 输出 | `exec_start` | 1 | 本模块 → 阵列控制器 start | 启动一条计算任务 |
| 控制信号 | 输出 | `active` | 1 | 本模块 → 阵列 queue_active；同时参与 MMIO accelerator_busy 的顶层汇总 | 队列正在处理任务 |
| 控制信号 | 输出 | `done` | 1 | 本模块 → MMIO accelerator_done | 整队列完成 |
| 控制信号 | 输出 | `error` | 1 | 本模块 → MMIO accelerator_error | 整队列失败 |
| 控制信号 | 输入 | `rst_n` | 1 | 外部系统复位 → 顶层 rst_n → 本模块 | 低有效全局复位；不同于软件复位命令 |
| 特殊信号 | 输入 | `op_type` | 4 | MMIO op_type → 本模块 | 提交队列的命令类型 |
| 特殊信号 | 输入 | `feature_size` | 32 | MMIO feature_size → 本模块 | 任务总数 |
| 特殊信号 | 输出 | `task_op` | 4 | 本模块 → 阵列控制器 op | 计算类型：0 普通卷积、1 DW |
| 特殊信号 | 输出 | `task_size` | 32 | 本模块 → 阵列控制器 fs | 特征图尺寸 |
| 特殊信号 | 输出 | `task_channels` | 32 | 本模块 → 阵列控制器 ch | 输入、输出通道数 |
| 特殊信号 | 输出 | `task_param` | 32 | 本模块 → 阵列控制器 lp | 核大小、步长、填充、量化参数 |
| 特殊信号 | 输出 | `queue_base` | 32 | 本模块 → 阵列控制器 queue_base | 整张任务表的起始地址 |
| 特殊信号 | 输出 | `queue_end` | 64 | 本模块 → 阵列控制器 queue_end | 整张任务表的结束边界，不包含该地址 |
| 特殊信号 | 输入 | `clk` | 1 | 外部系统时钟 → 顶层 clk → 本模块 | 公共时钟，各时序模块按时钟上升沿更新 |

**信号简释：**fetch_* 是任务表读取接口，exec_* 是计算任务调度接口；七个 32 位 task_* 是配置，task_op 是计算类型。queue_base/end 用于防止结果覆盖任务表。active/done/error 描述整队列状态。

## 3. 阵列控制器：systolic_conv_controller

| 分类 | 方向 | 本模块端口 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|---|
| 输入数据 | 输入 | `rsp_data` | 32 | RAM 接口 rsp_rdata → 本模块 | RAM 读回数据；读响应有效时使用 |
| 输出数据 | 输出 | `cmd_wdata` | 32 | 本模块 → RAM 接口 cmd_wdata | 写回数据；当前低 8 位为量化结果，高 24 位为零 |
| 输入地址 | 输入 | `ia` | 32 | 队列 task_input → 本模块 | 输入基地址 |
| 输入地址 | 输入 | `oa` | 32 | 队列 task_output → 本模块 | 输出基地址 |
| 输入地址 | 输入 | `wa` | 32 | 队列 task_weight → 本模块 | 权重基地址 |
| 输入地址 | 输入 | `ba` | 32 | 队列 task_bias → 本模块 | 偏置基地址 |
| 输出地址 | 输出 | `cmd_addr` | 32 | 本模块 → 顶层选择 → RAM 接口 cmd_addr | 计算侧本次读写地址 |
| 控制信号 | 输入 | `clear` | 1 | MMIO accelerator_reset → 本模块 | 软件复位 |

| 控制信号 | 输入 | `rsp_valid` | 1 | RAM 接口 rsp_valid，经顶层按非 fetch_phase 且本模块 busy 门控 → 本模块 | 本次计算侧读写命令完成 |

| 控制信号 | 输出 | `done` | 1 | 本模块 → 队列 exec_done | 当前一条任务完成 |
| 控制信号 | 输出 | `error` | 1 | 本模块 → 队列 exec_error | 当前一条任务失败 |
| 控制信号 | 输出 | `cmd_valid` | 1 | 本模块 → 顶层选择 → RAM 接口 cmd_valid | 计算侧读写请求有效 |
| 控制信号 | 输出 | `cmd_write` | 1 | 本模块 → 顶层选择 → RAM 接口 cmd_write | 0 为读取，1 为写入 |

| 控制信号 | 输入 | `rst_n` | 1 | 外部系统复位 → 顶层 rst_n → 本模块 | 低有效全局复位；不同于软件复位命令 |

**信号简释：**ia/oa/wa/ba 和 fs/ch/lp 是锁存的任务配置来源。cmd_* 发出 RAM 请求，rsp_* 接收完成响应；done/error 先回队列，由队列决定整体完成/失败。cmd_ready 表示命令可以被接收，rsp_valid 才表示该命令已完成。

## 4. RAM 访问接口：accelerator_mem_if

| 分类 | 方向 | 本模块端口 | 位宽 | 来源或去向 | 含义 |
|---|---|---|---|---|---|
| 输入数据 | 输入 | `cmd_wdata` | 32 | 阵列 cmd_wdata → 本模块 | 本次写入值，只在写命令时使用 |
| 输入数据 | 输入 | `mem_rdata` | 32 | 外部 RAM → 顶层同名端口 → 本模块 | 外部 RAM 读回的一个 32 位整字 |
| 输出数据 | 输出 | `rsp_rdata` | 32 | 本模块 → 队列 fetch_rsp_data 和阵列 rsp_data | 同一条返回数据总线；各自用有效标志判断是否接收 |
| 输出数据 | 输出 | `mem_wdata` | 32 | 本模块 → 顶层同名端口 → 外部 RAM | 实际写往 RAM 的整字；字节写回时包含保留的相邻字节 |
| 输入地址 | 输入 | `cmd_addr` | 32 | 顶层从队列 fetch_addr 或阵列 cmd_addr 中选择 → 本模块 | 本次读写地址 |
| 输出地址 | 输出 | `mem_addr` | 32 | 本模块 → 顶层同名端口 → 外部 RAM | 外部 RAM 本次读写的 4 字节对齐地址 |
| 控制信号 | 输入 | `cancel` | 1 | MMIO accelerator_reset → 本模块 | 取消内部命令并收尾已发出的总线事务 |
| 控制信号 | 输入 | `cmd_valid` | 1 | 顶层从队列 fetch_valid 或阵列 cmd_valid 中选择 → 本模块 | 当前选中请求方的命令有效 |
| 控制信号 | 输入 | `cmd_write` | 1 | 顶层选择：任务读取时固定 0，否则取阵列 cmd_write → 本模块 | 选择读或写 |
| 控制信号 | 输入 | `cmd_byte` | 1 | 顶层选择：任务读取时固定 0，否则取阵列 cmd_byte → 本模块 | 选择整字或字节访问 |
| 控制信号 | 输出 | `cmd_ready` | 1 | 本模块 → 顶层门控 → 队列 fetch_ready、阵列 cmd_ready | 告诉被选中的请求方可以接收命令 |
| 控制信号 | 输出 | `rsp_valid` | 1 | 本模块 → 顶层门控 → 队列 fetch_rsp_valid、阵列 rsp_valid | 告诉相应请求方命令已完成 |
| 控制信号 | 输出 | `idle` | 1 | 本模块 → 队列 mem_idle；同时取反参与 MMIO accelerator_busy 汇总 | 当前没有未完成命令 |
| 控制信号 | 输入 | `mem_ready` | 1 | 外部 RAM → 顶层同名端口 → 本模块 | 当前外部读或写事务在本上升沿完成 |
| 控制信号 | 输出 | `mem_read` | 1 | 本模块 → 顶层同名端口 → 外部 RAM | 外部 RAM 读请求，保持至完成 |
| 控制信号 | 输出 | `mem_write` | 1 | 本模块 → 顶层同名端口 → 外部 RAM | 外部 RAM 写请求，保持至完成 |
| 控制信号 | 输入 | `rst_n` | 1 | 外部系统复位 → 顶层 rst_n → 本模块 | 低有效全局复位；不同于软件复位命令 |
| 特殊信号 | 输入 | `clk` | 1 | 外部系统时钟 → 顶层 clk → 本模块 | 公共时钟，各时序模块按时钟上升沿更新 |

**信号简释：**RAM 接口只有一套 cmd/rsp 端口，两方通过顶层选择来共享。读命令返回数据；写命令返回完成标志。返回数据线同时连到两方，但有效标志按阶段分配。

## 顶层连接关系与画图标注

```text
CPU ── mmio_addr、mmio_wdata、mmio_we、mmio_re ──→ MMIO
CPU ←── mmio_rdata、mmio_ready ───────────────── MMIO

RAM访问接口 ── mem_addr、mem_wdata、mem_read、mem_write ──→ 外部RAM
RAM访问接口 ←── mem_rdata、mem_ready ─────────────────── 外部RAM

MMIO ── 启动、任务表地址、任务数、op_type ──→ 队列控制器
MMIO ── 软件复位 ──→ 队列控制器 / 阵列控制器 / RAM访问接口

队列控制器 ── start、7×32位配置、4位op、任务表范围 ──→ 阵列控制器
队列控制器 ←── busy、done、error ─────────────────── 阵列控制器

队列控制器 ── 任务读请求 ──┐
                          ├─ 顶层选择 ──→ RAM访问接口
阵列控制器 ── 计算读写请求 ─┘

队列控制器 ←── 返回数据、有效/就绪/空闲 ── RAM访问接口
阵列控制器 ←── 返回数据、有效/就绪 ────── RAM访问接口

队列 done/error ──→ MMIO；各模块的忙/空闲状态经顶层汇总 ──→ MMIO
```

图中队列到阵列的配置线可以标成 **7×32＋4＋32＋64**，但还需要 start、queue_active 两根 1 位控制线；反方向是 busy、done、error 三根 1 位线。

顶层忙状态汇总为：队列 active 或阵列 busy 或 RAM 接口非 idle。RAM 请求选择由队列 fetch_phase 控制：1 选任务读取，0 选计算读写。这些是连线之间的组合逻辑，不是第五个大模块。


## CPU 和 RAM 连线的画法

- **CPU → MMIO**：32 位地址、32 位写数据、2 根读写控制线。
- **MMIO → CPU**：32 位读回数据、1 根 ready。
- **RAM 接口 → 外部 RAM**：32 位地址、32 位写数据、2 根读写控制线。
- **外部 RAM → RAM 接口**：32 位读回数据、1 根 ready。
- **clk、rst_n**：图边统一标注“连接四个时序大模块”，不必把线横穿整个图。

MMIO 侧和 RAM 侧是两套不同接口，不直接将它们的同类信号短接。CPU 提前向 RAM 放入任务表、输入及权重的系统通路，在当前加速器顶层中没有实现；如需表示数据准备，可以画一条虚线并注明“外部系统预装数据”。
