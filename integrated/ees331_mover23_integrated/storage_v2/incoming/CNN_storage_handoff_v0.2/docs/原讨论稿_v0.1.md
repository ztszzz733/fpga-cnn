## 1. 当前基线与本次要补的内容

本地最新CNN配置为K3×4、K1×6、Post×3，DW7/Add/Pad各1，共16个算子。十张112×112 RGB合成测试图已完成独立全网RTL仿真，1310个任务和最终1280字节输出与整数参考一致。

该验证使用32MiB实验SRAM、十个有限上下文、40个工作槽。尚未接入新的DATA MOVER、跨层本地tile缓冲或EES331整机。当前40个工作槽不能直接理解为40个片内tile缓冲；16算子也未确定为最终上板配置。

下一阶段需要补两项交付：

1. **代表性tile任务包**：给出一组能够实际搬入、计算、搬出并逐值核对的数据和任务。
2. **CNN→MOVER适配定义**：规定CNN如何提出搬运请求、等待完成、启动算子、发布结果和释放缓冲；确认后再据此实现适配RTL。

## 2. 代表性tile任务包是什么

tile是从某层特征图中取出的一小块。卷积输入除了有效输出所需的中心区域，还可能需要周围的halo数据。

首轮样例应覆盖以下完整闭环：

```text
DDR中的输入、权重、量化参数和残差旁路
                    ↓ MOVER搬入
               本地tile RAM
                    ↓
             卷积 → Post量化 → Add
                    ↓
               本地结果就绪
                    ↓ MOVER搬出
             DDR结果可见 → 核对参考值
```

样例的目的，是同时验证搬运、数据格式、算子计算和生命周期。它不是完整网络已经完成tile化的证明。

### 2.1 首轮建议样例

建议先选普通3×3卷积、stride=1、输入/输出通道均为32，输出tile为8×8×32，再接量化及同形状残差Add。

| 区域 | 形状与格式 | 字节数 |
|---|---|---:|
| 卷积输入，含halo | 10×10×32，UINT8 | 3200 |
| 卷积权重 | 32×3×3×32，INT8，O_KY_KX_I | 9216 |
| 卷积原始输出 | 8×8×32，INT32 | 8192 |
| Post量化输出 | 8×8×32，UINT8 | 2048 |
| 残差旁路输入 | 8×8×32，UINT8 | 2048 |
| Add输出 | 8×8×32，UINT8 | 2048 |
| Post参数 | 32通道×20字节 | 640 |
| Add参数 | 32通道×20字节 | 640 |
| **全部独立保留时的净数据合计** | — | **28032字节（27.375KiB）** |

10×10输入经过无额外padding的3×3、stride=1卷积，得到8×8输出。输入的halo需从上游特征图取得；超出整张特征图边界的位置应填入输入量化零点，不能一律填字节0。

该样例尚未生成数据或运行新RTL测试。实际数值应由CNN侧生成，量化尺度、零点、乘数、移位和截断范围必须写入任务包，不能由接收方自行猜测。

28032字节不包含算子内部RAM、控制表、FIFO、复制缓冲和端口实现开销，不能据此直接确定最终本地RAM容量。

### 2.2 建议的本地地址样例

以下仅为该样例的**本地RAM相对地址**，不是DDR物理地址，也不是已冻结的系统地址表。所有起址按64字节对齐，各区域不重叠。

| 区域 | 本地起始偏移 | 字节数 |
|---|---:|---:|
| 输入，含halo | 0x0000 | 3200 |
| 权重 | 0x0C80 | 9216 |
| Post参数 | 0x3080 | 640 |
| Add参数 | 0x3300 | 640 |
| 残差旁路 | 0x3580 | 2048 |
| 卷积原始输出 | 0x3D80 | 8192 |
| Post量化输出 | 0x5D80 | 2048 |
| Add输出 | 0x6580 | 2048 |
| **区域结束，右开边界** | **0x6D80** | — |

首轮保守地分开存放各份数据。后续若要原位覆盖或复用区域，需要重新证明所有消费者已完成，并验证不会破坏残差旁路。

### 2.3 任务包应包含哪些文件

```text
cnn_tile_case_v1/
  README.md
  manifest.json
  layout.json
  moves.csv
  tasks.json
  input_with_halo.bin
  weights.bin
  post_params.bin
  add_params.bin
  residual.bin
  golden_conv_int32.bin
  golden_post_uint8.bin
  golden_add_uint8.bin
```

| 文件 | 必须说明或包含的内容 |
|---|---|
| README.md | 样例目的、步骤、依赖、核对方法、已验证范围与待验证项 |
| manifest.json | 版本、生成方式、文件长度和SHA256、参考计算方式 |
| layout.json | 地址域、区域长度、形状、布局、行跨度、halo、尺度及零点 |
| moves.csv | 搬运序号、方向、DDR偏移、本地地址、字节数、前置条件 |
| tasks.json | 卷积/Post/Add命令、输入输出地址、参数和依赖关系 |
| 输入数据文件 | 实际搬入的输入、权重、参数和残差数据 |
| golden文件 | 独立整数参考生成的三个阶段结果 |

参考结果只能用于核对，禁止预加载到待计算的结果区代替真实运算。建议结果区先填入固定poison值，以检查漏写、越界和非法提前读取。

### 2.4 已有算子的数据布局

| 数据 | 当前格式 |
|---|---|
| 输入与量化特征、残差输入 | UINT8，HWC，通道连续 |
| 卷积原始输出 | INT32，小端，HWC |
| 普通卷积权重 | INT8，O_KY_KX_I |
| DW3权重 | INT8，C_KY_KX |
| DW7权重 | INT8，KY_KX_C |
| Post/Add参数 | 每通道5个32位字，小端，共20字节 |

每通道五个参数字依次为：bias、multiplier A、multiplier B、零点/移位配置、上下限配置。具体位定义、数值和舍入规则应随数据包给出，并与当前Post实现一致。

当前算子按紧凑布局寻址：UINT8特征行跨度为W×C字节，INT32特征为W×C×4字节。不能直接把带任意行间空洞的DDR矩形当作紧凑本地输入。

首轮建议MOVER只支持一维线性命令：已经打包连续的数据可以整块搬运；从完整特征图提取跨行tile时，由CNN适配层按行生成多条命令，将其放入紧凑本地布局。halo坐标和边界补值由CNN侧规划，MOVER只负责合法地址范围内的数据复制。

## 3. CNN→MOVER适配定义是什么

适配层连接的是两类接口：

- 算子通过本地访存接口读取输入、权重和参数，写入计算结果。
- MOVER通过业务命令接口在DDR与本地RAM之间搬运数据。

CNN适配层负责协调两者。16个算子访存客户端不等于要求16条DDR搬运命令并发。

### 3.1 需要共同确认的业务接口

以下是建议的逻辑定义，尚不是已实现或已冻结的RTL端口表。

| 项目 | 建议含义 | 状态 |
|---|---|---|
| cmd_valid / cmd_ready | 同拍有效表示一条搬运命令被接受 | 原则建议 |
| src / dst / bytes / flags | 各32位；源、目标、字节数、方向及控制项 | 逐位编码待确认 |
| rsp_valid | 命令真正完成，成功或失败已确定 | 原则建议 |
| rsp_ready | 建议增加完成响应的消费握手，避免响应丢失 | 待双方确认 |
| 响应状态/错误码 | 区分成功、非法参数、范围/对齐错误、总线错误、超时等 | 位宽与编码待确认 |

现有算子本地访存口为每路32位地址、32位数据，包含valid/ready和response；现有接口没有response_ready。新增MOVER业务响应接口与该接口不是同一条通道，不能未经适配直接替换。

必须共同写清：

1. DDR字段表示保留区偏移，本地字段表示本地RAM地址；两个地址域如何由方向区分。
2. flags每一位的含义，未使用位、未知控制项怎样处理。
3. 合法起始对齐、尾字节处理、零长度、地址加法溢出与越界规则。
4. 命令被反压时字段保持稳定；响应如何保持、消费及清除。
5. 错误、超时、停止新请求、事务排空与复位的衔接规则。

DDR物理基址、保留长度及PS缓存维护方式由相应责任方另行确认，CNN侧不在本文代为分配或回签。

### 3.2 首轮建议执行顺序

```text
准备任务与地址
  → 搬入输入、权重、Post/Add参数和残差数据
  → 等待所有搬入命令成功完成
  → 启动卷积，等待原始结果本地写完
  → 启动Post，等待量化结果本地写完
  → 确认两路输入均就绪，启动Add
  → 等待Add结果本地写完
  → 请求最终结果写回DDR
  → 等待写回成功
  → 发布DDR结果完成
  → 外部消费确认后允许复用最终结果区域
```

首轮不要求搬运与计算重叠。后续可以增加本地中间结果直接复用、双缓冲或多tile并行，但需重新核对依赖和所有权。

### 3.3 必须区分的完成与释放状态

| 状态 | 能够说明什么 | 不能据此直接说明什么 |
|---|---|---|
| 命令接受 | MOVER已经接下命令 | 数据已经搬完 |
| 搬入成功 | 对应输入真实写入本地RAM | 其他必需输入也已就绪 |
| 算子本地完成 | 该任务输出真实写入本地RAM | 输出已经写回DDR |
| DDR写回成功 | 该结果范围的DDR写入已成功完成 | 外部消费者已经读完 |
| 缓冲可释放 | 所有消费者及必要写回已完成 | 其他仍在途区域可以一起复用 |

本地生产者完成后，下游本地消费者可以按依赖使用结果，不必一律先写回DDR。是否需要写回由任务清单明确；只有真正完成写回的结果才能发布为DDR可见。

对于MOVER，DDR→LOCAL只能在本地数据实际写完后报告完成；LOCAL→DDR只能在相关写响应全部成功后报告完成。发生超时时，未返回事务不能被自动视为已取消，相关区域不得立即复用。

## 4. 如何补交与分工

| 阶段 | CNN侧交付 | 存储侧/联合工作 | 通过条件 |
|---|---|---|---|
| 1：文档确认 | 样例形状、布局、halo、生命周期、接口草案 | 确认MOVER能力、地址域、握手、对齐和错误语义 | 形成双方认可的版本化接口表 |
| 2：任务包生成 | 输入/权重/参数、搬运清单、任务表、独立整数参考、文件哈希 | 检查容量和布局可实现性 | 数据、长度、地址及参考结果可独立复核 |
| 3：搬运验证 | 核对布局和数据，提供检查脚本 | 实现MOVER与本地RAM测试台，测试往返及反压 | 字节一致、无越界、完成语义正确 |
| 4：真实算子联调 | 实现CNN→MOVER适配RTL与算子启动控制 | 接入真实MOVER、本地RAM及错误路径 | 卷积/Post/Add逐阶段结果与参考一致 |
| 5：扩展 | 多tile调度、halo边界、通道分块及依赖 | 双缓冲、资源/带宽评估、多批验证 | 同一目标顶层的正确性和资源证据 |

首轮建议限制为一条搬运命令在途、一个计算tile。最终tile容量、算子数量、同时在途命令数和并行tile数，由联合验证与资源评估后确定。

## 5. 最低验收清单

- [ ] layout中的长度、地址范围、对齐和区域不重叠检查通过。
- [ ] 输入、权重、参数、halo及量化格式与参考计算一致。
- [ ] 结果区没有预加载golden，所有目标字节均由真实计算写出。
- [ ] DDR↔LOCAL往返、跨行复制、短尾字节和随机反压通过。
- [ ] 卷积INT32、Post UINT8、Add UINT8逐阶段逐值核对通过。
- [ ] 输入尚未搬完时不启动对应算子。
- [ ] Add两路输入均就绪，残差旁路未被提前覆盖。
- [ ] 本地完成与DDR完成分别记录，写回成功前不发布DDR结果可见。
- [ ] 尚有消费者、写回或未排空事务时，不提前复用相关区域。
- [ ] 非法命令、错误和超时按约定锁存或上报，不让旧响应污染新任务。
- [ ] 报告记录源码/配置/数据哈希、实际测试范围和未验证项。
