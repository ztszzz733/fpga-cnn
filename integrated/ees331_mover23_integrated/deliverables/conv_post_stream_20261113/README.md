# 卷积直接流水到后处理：第一版小规模验证

后续资源综合已完成：[LUT/FF实测对照](../conv_post_stream_resources_20261113/README.md)。FIFO本体169 LUT；完整PW8/后处理组合新增1387 LUT，K3/后处理新增1417 LUT，均未新增BRAM或DSP。仍未做新版布局布线。

## 本次状态

已实现并通过独立RTL算子对试验：真实3×3/DW3或PW8卷积 → 8项寄存器FIFO → 原后处理计算流水 → 最终存储。

**尚未接入整套SoC的共享算子池和任务调度器。现有fixed_schedule_compact没有改动，完整网络仍按原方式调度。** 自动判断目前在这个“算子对入口”内完成，不是从任意CPU指令推断网络，也没有实现任意算子路由。

## 怎么工作

旧路径：卷积写INT32中间结果 → 卷积结束 → 后处理读中间结果 → 量化/激活 → 写最终UINT8结果。

直连路径：卷积写请求被转入小FIFO，入队成功即响应卷积；数据带着元素位置和通道号交给后处理，后处理复用原有参数RAM、偏置/缩放/舍入/限幅流水，按最终地址写回。并没有新增一套后处理乘法器。

当前卷积按微块/通道产生结果，不是连续HWC顺序。因此每项FIFO携带32位数据、32位元素索引、10位通道号。后处理按通道选参数，按索引写回，最终存储布局保持HWC，不需要完整特征图重排RAM。

8项FIFO满时停止接收卷积结果。后处理写回阻塞时暂停自身流水；反压最终传回卷积。FIFO入队成功不代表最终数据已写入存储。入口done必须等卷积排空、FIFO排空、所有最终写响应完成。

## 自动判断和回退

入口锁存描述符并用串行尺寸计算检查形状，约160周期的准入开销在新旧两种模式中相同。满足以下全部条件才启用直连：

- request_stream=1，且中间结果仅一个消费者；
- 下一步为本后处理模块支持的INT32卷积结果到UINT8量化/激活路径，不是Add；
- 后处理元素数等于卷积输出元素数，后处理通道数等于卷积输出通道数；
- 最终输出不会覆盖仍在使用的输入、权重、参数区；地址范围合法。

decision_reason：0直连；1请求关闭；2多个消费者；3Add；4数量/通道不匹配；5输出与仍在使用的数据重叠。后四类合法但不支持直连的描述符继续走原中间存储方式。非法卷积/地址/参数则报错，不伪装成可执行回退。

同一入口一次只处理一对算子，物理上已拥有一个卷积和一个后处理实例，不存在全局共享池里的资源争抢。之后接入共享池时，调度器还必须同时预留两个算子和通路，更新中间缓冲租约、完成计数、错误取消；本次没有实现这些全局机制。

## 验证和收益

56组卷积+后处理组合逐字节匹配128位整数软件参考，并与相同描述符的存储路径对比；包括1×1、3×3、DW3、步长1/2、输入通道至512、非对齐地址、边缘微块、PW8 panel复用、强访存暂停与即时响应。另有4项自动回退、6项清空重启、2项描述符锁存、6项非法配置、4组带波形复跑。

所有56组直连试验均没有INT32中间结果的存储读写，每个输出元素省4字节写入和4字节读取。最终输出仍然写回。

| 输入与卷积 | 存储方式周期 | 直连周期 | 周期减少 | 中间读写节省/字节 |
|---|---:|---:|---:|---:|
| 7×5×3，1×1，Co=9，s=1 | 4156 | 2277 | 45.21% | 2520 |
| 7×5×3，3×3，Co=9，s=1 | 4156 | 2718 | 34.60% | 1080 |
| 11×9×64，1×1，Co=64，s=1 | 116358 | 78594 | 32.46% | 50688 |
| 11×9×128，1×1，Co=128，s=1 | 356178 | 280653 | 21.20% | 101376 |

本次56组小实验的周期减少范围为0.19%～51.09%，最小算例及计算占比高的算例收益可能很小。

以上为具有两个独立请求端口、可控等待的测试存储模型，统计的是算子访存接口流量。**不是DDR实测带宽，也不是完整网络加速比例。** 本版直连为保持任意输出顺序，最终每个UINT8结果发一笔字节写；旧后处理可以合并成32位写，所以请求数收益与字节收益不同。后续可用小块打包缓存减少字节写开销。

现有整机入口face_soc_ees331_mover_top还通过了语法和连接展开检查，仅说明默认接口兼容，不是整机仿真或时序验证。

默认路径兼容回归：Post/Add 40个主数值场景与修改前快照周期/请求数完全相同，并通过尾部、即时响应、清空、非法配置、重叠地址等额外场景；PW8 129项、K3/DW3 216项及其协议测试也通过。原批量回归收集器曾因同时创建波形运行目录而断言失败，三个实际测试均PASS；这里独立核对指定目录和哈希，不修改原FAIL记录，见[核验记录](verification.json)。

横轴按100MHz条件换算，每周期10ns；不是新设计已满足板级100MHz的证明。PNG以提交后的相对周期绘制，VCD时钟周期为10000ps，CSV周期0对应VCD约40ns。

放大控制事件看[k3_zoom.png](k3_zoom.png)、[pw8_zoom.png](pw8_zoom.png)。全部来自本次RTL逐周期记录，没有用busy代替计算事件。

| 信号 | 看什么 |
|---|---|
| conv_work | 卷积MAC累加结果生效，不含纯访存等待 |
| raw_push | 一项INT32卷积结果被8项FIFO接收 |
| raw_pop | 后处理接收一项FIFO数据 |
| fifo_level | FIFO占用，满8项时上游可能因下游暂停而等待 |
| post_work | 仅直连模式：一项量化/限幅结果离开计算流水；存储模式该调试信号为0，不表示后处理不工作 |
| final_write_ack（CSV/PNG） | 最终结果写请求收到响应，不能与raw_push混淆 |
| conv_finished | 卷积本层结果已全部交出；直连时不代表后处理已全部写回 |
| mem_valid/write/ready/response（GTKWave） | 两位向量：bit0卷积端，bit1后处理端；先看bit1的valid+write+ready写请求，再看它对应的response；write可能在等待响应时已拉低，不能直接把write与response相与 |
| done | 整个组合完成且最终写回收到响应 |

GTKWave会话：[k3_direct.gtkw](k3_direct.gtkw)、[pw8_direct.gtkw](pw8_direct.gtkw)；对应memory会话也保留，每个会话16个唯一顶层信号。验证脚本随文件提供，四个会话已由本地GTKWave实际加载验证，每个16根唯一信号，日志另存。

## 成本和限制

- 8项原始数据FIFO的有效数据位数为8×(32+32+10)=592位；不含指针、控制逻辑和选择器。
- 后处理另需位置标签沿7级计算流水传递，PW8写队列另带通道标签。参数RAM复用原模块，没有新增整张特征图RAM。
- 上述是结构位数。最初功能试验时尚未综合，后续实际综合已完成，结果见文首资源报告；**仍未做新版布局布线**。也不能沿用此前PW8单模块的+0.025ns裕量作为新版时序结论。
- 流水会把卷积与后处理实例一起占用。全局场景可能与其他图片争抢后处理，净收益必须在接入共享调度后重新测量。
- 仅支持当前两种卷积接口接现有后处理能力，不新增PReLU、下一层卷积直连、分支广播或Add双流对齐。
- 未跑完整图片/网络、CPU/UART、真实DDR、板级资源或时序验证。

本次最终波形运行编译125.982s、执行4.428s。前一次数值试验已通过，最终复跑仅把波形统一为10ns时钟和顶层关键信号；最早一次FST编译因缺少zlib头文件失败，改用VCD，无需安装软件。
