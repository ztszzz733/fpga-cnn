# 1×1卷积连续像素分组试验（2026-11-15）

已修改生产PW8，使8路MAC处理8个连续输出像素，允许跨图像行边界；小图功能、协议检查和生产SoC接入检查通过。7×7、14×14代表场景减少约8%～11%的卷积周期；28×28的改善很小。用户决定先交付功能，LUT、FF及10ns时序稍后补测，目前没有新版有效资源/时序结果。

## 改了什么

旧版将像素分成4列×2行的微块；边缘不足4列或2行时，部分MAC空闲。新版按输出像素序号连续取8个，例如7×7图第一组是第0行7个像素＋第1行第0个像素。1×1卷积各像素独立，跨行分组不改变数值含义。步长为2时，输出像素连续，但输入仍按步长跳取，行尾使用寄存的行地址换行。

7×7从8个微块减少到7个，14×14从28个减少到25个；28×28仍为98个。7×7末组只有1个有效像素，填充的7个位置不计算、不写回。分组数量减少不等于整层/整网同比加速。

保留8路MAC、512×64位输入RAM、1KiB权重RAM、原有内部8项写队列，以及输入预取、权重双缓冲和整层/面板复用。面板按输入通道限制为8/4/2/1组，继续使用原RAM容量，多个通道共享已经载入的像素；整层权重放不下时，较紧凑的面板也可能减少重复读取权重的次数。

新增连续像素计数、跨行输入地址和面板输出地址控制，复用原串行乘法器增加32拍描述符准备来计算输出像素总数。没有新增乘法器数量、算子实例或算子间FIFO；寄存器和控制电路成本须等综合确认，不能将“RAM容量不变”理解成资源完全不变。

## 小图实测

同一个测试程序依次运行三份设计：独立保存的修改前源码、新连续分组，以及新源码的`LINEAR_GROUPS=0`原分组。测试采用同样的确定性应答延迟/反压，逐字节比对标量卷积参考；下表包含描述符准备、输入和权重读取、MAC及所有输出写应答。

| 图像空间尺寸与通道 | 原周期 | 新周期 | 周期减少 | 总读字节：原 → 新 |
|---|---:|---:|---:|---:|
| 7×7，Ci=64，Co=64 | 41,074 | 36,879 | 10.21% | 7,232 → 7,232 |
| 7×7，Ci=128，Co=128 | 147,785 | 131,168 | 11.24% | 39,040 → 39,040 |
| 14×14，Ci=64，Co=64 | 146,922 | 135,091 | 8.05% | 28,928 → 28,928 |
| 14×14，Ci=128，Co=64 | 278,091 | 253,982 | 8.67% | 90,624 → 82,432 |
| 28×28，Ci=64，Co=64 | 528,085 | 527,690 | 0.07% | 115,712 → 103,424 |
| 28×28，Ci=128，Co=128 | 1,861,895 | 1,861,087 | 0.04% | 559,104 → 509,952 |

所有行均为1×1、stride=1、对齐的UINT8输入×INT8权重，输出INT32。读字节包括输入和权重，不含写字节；每层输入所需的字节各读一次，减少的字节来自权重重复读取。输出个数、输出字节数和有效MAC总量不变。按假定100MHz换算，周期÷100000为毫秒；新版100MHz时序尚待验证，不能把该换算当上板频率保证。

28×28能明显少读部分权重，但总周期变化仍很小，原因是原分组已经填满8路、MAC数量未增加，而且权重预取原本就能和计算重叠。减少访存不一定等比例缩短运行时间。此次测试未涉及DDR/MOVER的完整SoC运行，不能据此声称整张人脸或整网加速比例。

极小图和分组没有变少的部分场景存在固定准备开销。在165个数值场景中，71个变慢，最大增加35拍，最大相对增加12.73%；这主要发生在原本只有少量工作的小场景。没有只选择加速的场景隐藏退化；全部指标见[逐例结果](regression_metrics.json)。
