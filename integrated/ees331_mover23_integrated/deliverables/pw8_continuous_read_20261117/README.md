# PW8连续读取试验（2026-11-17）

**连续读取原型完成并通过真实bank的小图验证。常用14×14×64→64通道1×1卷积，单层周期88,079→86,153，减少2.19%。这是bank侧隔离原型，尚未接入正式SoC或DDR路径。**

## 实现了什么

- PW8算术、16路MAC、输入RAM布局、权重缓存和逐笔输出写回保持原样。整字装填与整笔写回均关闭，单独评估连续读取。
- 算子旁增加四槽有序预取单元。它根据当前输入像素/权重装载段的边界产生连续地址；上一笔未返回时即可发下一笔。每笔4字节，最多4笔未返回。
- 四槽同时保存未返回请求和已返回但尚未消费的数据，先保留槽位再发请求；返回端不需要ready，也不会因消费慢而覆写数据。
- 数据本体16字节，另有4个地址标签、生产/消费指针、边界和计数；不是增加整张图片缓存。
- 输入/权重只有连续段内的对齐32位访问使用预取。字节访问和仅剩一个字的短段走原有逐笔方式。
- 遇到输出写回，先排空未返回的读取，再按原方式写回；已经预取到的数据保留。本试验不合并输出写事务。
- bank前端允许每拍接受一笔32位请求，返回保持顺序；物理存储仍用原392KiB四bank RTL。新旧方案共用同一bank前端，带宽和响应延迟一致。

## 为什么代表层只减少2.19%

权重加载原本就能与MAC重叠，因此缩短权重传输不一定缩短最终完成时间。输入收到一个32位字后仍按原布局分拍写入内部输入RAM；输出仍为逐笔握手。连续读取解决请求往返的空泡，没有改变这些限制。

## 验证

- 两种延迟各16组新旧配对（32组），每组检查全部INT32输出、真实RAM读回、写地址/数据、重复和漏写、头尾保护区、有效MAC与输入字节。
- 覆盖奇数通道、stride2、未对齐输入/权重、尾像素、输出跨bank、请求背压；另分别执行读取在途时clear并重启、start后改变外部描述符。
- 验证请求在背压时保持稳定、响应按序、4槽信用不溢出、done不提前于最终bank完成。
- 独立原版保留为original_engine.sv。新增self_pw8_read_source.sv只导出连续读取段的末地址；算术与状态推进不变。对外封装self_pw8_continuous_engine.sv已实测，逐项复现此前原型结果。
- 初版曾发现字节小段额外开销和读请求背压时无效写数据未保持的问题，已改为短段回退并固定读请求写数据。最终两组证据均来自修正后的同一源码，不把初版当PASS。

## 对接接口与限制

| 接口 | 含义 |
|---|---|
| valid/ready | 每次握手接受一笔32位或字节请求；允许多笔读取未返回 |
| write、byte_access、addr、wdata | 保留原PW8的读写、字节、地址、写数据含义 |
| response、rdata | 每笔请求恰好一个响应，严格按接受顺序；无response_ready |
| clear | 算子、预取单元与bank/互连必须一起取消在途事务，不能有清除前的迟到响应 |
| busy/done/error、phase、mac_fire | 保留算子状态含义；封装会等待适配器排空，并汇总错误 |

该原型要求不可变的输入/权重，输出与输入/权重不重叠；单客户端最多4笔读取在途。读响应至少晚一拍，本次bank前端验证的是2拍和6拍。多客户端互连需要为每笔请求保留客户端归属、维持各客户端顺序和响应槽信用。当前正式cnn_plan_storage等路径仍需适配其单在途客户端逻辑，不能直接替换后就认为已支持四笔读取。
