# K3读取次数小规模优化（2026-11-13）

已修改生产RTL并通过单元及8任务SoC验证；没有减少算子，没有运行完整MobileFaceNet，没有重新综合。

## 改了什么

当前K3×2、K1×6、Post×2、Add×1、Pad×1、DW7关闭及392KiB共享RAM保持原样。本次仅修改`rtl/cnn_self/self_conv_spatial4_engine.sv`，增加默认开启的`READ_WORD_BUFFER=1`；置0可回到原始直通读接口，用于同一版本内比较。

每个K3实例加入输入和权重各一个32位最近读取字缓冲。按字节取数据时，若整个对齐32位字均在该命令声明的输入/权重地址范围内，就只向外读取一次；后续命中该字的字节直接返回。原有32位读响应也可填充缓冲。未对齐的张量首尾仍按需要读字节，不能越过合法范围。

示例：原来依次请求地址A、A+1、A+2、A+3四个字节；当A对齐且四字节都属于合法张量时，新版读取一个32位字并复用其四个字节。不要求四个请求一定连续，但中途读取另一个字会替换对应缓冲。

有效数据仅8字节/实例，加上两个30位地址标记、有效位及少量在途控制。采用小寄存器，没有新增BRAM数组；未强制映射LUTRAM，也未测量新增LUT/FF。如此小的容量暂不值得引入大LUTRAM缓存。命中响应无外部请求；未命中仍只允许一笔在途事务，原接口的反压和返回握手不变。

复位、clear及每条新命令都会失效缓冲，写到匹配字时也会失效。输入及权重在命令执行期间须保持不变。clear仍要求外部一起取消在途事务，这是原接口已有约束。

原有内部输入tile缓存、四空间MAC和DW3权重跨tile复用继续使用。本次没有改变计算公式、MAC数量、输出布局、调度与MOVER，也没有实现加载/计算双缓冲。

## 测量结果

同一个单元顶层同时包含开关关闭和开启的K3，使用相同数据、标量参考模型及相同确定性存储响应模型。表中读请求在算子对外端口统计，排除了输出写请求；读字节为外部返回有效字节总量。周期仅是该单元测试条件下的结果，不是全网或DDR板级性能。

| 用例 | 外部读请求次数 | 外部读字节 | 周期 |
|---|---:|---:|---:|
| 16: 5×5, Ci=3, Co=3, 普通3×3 | 399 → 133 | 471 → 511 | 2365 → 1541 |
| 163: 6×6, Ci=64, Co=8, 普通3×3 | 5632 → 5632 | 22528 → 22528 | 42981 → 42981 |
| 164: 6×6, Ci=64, Co=64, DW3 | 1168 → 1168 | 4672 → 4672 | 12642 → 12642 |

RGB例子读请求399→133，减少66.7%；周期2365→1541，减少34.8%；但读字节471→511，增加8.5%。原因是32位预读可能带入本轮未使用的相邻字节。减少请求次数不等于总流量下降，也不等于DDR事务一定同比减少；DDR实际由分页RAM/MOVER管理。

168个数值用例全部通过：151个请求减少、151个周期减少、0个变慢；86个读字节增加。已对齐的高通道层大多不受益。

注意：`input_reads/weight_reads`继续统计核心逻辑请求的字节，命中时也会累加。它们不代表优化后对外读取量；物理统计应在valid&&ready的外部端口按byte_access计数。本次表格按这一口径测量。`mac_fire`含义不变。

## 后续更值得尝试的方向

1. 普通3×3目前仍会为不同空间tile重新读取对应输出通道的权重。增加有容量上限的权重块缓存，可针对高通道层减少重复读取；必须先统计权重流量和命中率，不能直接缓存全层权重。
2. 相邻tile的输入窗口存在重叠。小行缓存/条带缓存可复用重叠输入，比仅合并字节读取更直接减少数据量，但要处理步长、边界、各任务失效和算子本地RAM布局。
3. 当前MOVER已支持突发。若主要时间花在分页装入及单请求序列化，应继续从页命中率、请求队列和预取/计算重叠分析；仅在算子端加大缓存不保证解决该瓶颈。
