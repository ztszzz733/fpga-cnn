# 卷积DSP映射验证

仅调整1×1和3×3的乘法综合映射，保留现有缓存、8路/4路并行、流水级和外部接口。补边、Add读取合并、Post分组16、PW8面板复用、K3窗口/权重复用保持。没有启动整图、整机综合或布局布线。

## 单模块综合结果

Vivado 2025.2，XC7Z020-CLG484-1，10ns独立综合。同一参数、相同保留端口，对照已有且源码哈希一致的修改前报告。

| 模块 | LUT旧→新 | 节省LUT | FF旧→新 | DSP旧→新 | BRAM36等效旧→新 |
|---|---:|---:|---:|---:|---:|
| 3×3/DW3单套 | 3125 → 2739 | 386 | 1794 → 1726 | 0 → 4 | 5.5 → 5.5 |
| 1×1单套 | 3073 → 2593 | 480 | 1722 → 1588 | 0 → 8 | 1.5 → 1.5 |

按当前2套K3、6套PW8估算：LUT变化-3652，FF变化-940，DSP变化+56，BRAM变化+0。这是独立模块差值按数量相加，不是整机净增量，不给出未经整机验证的总资源或上板保证。

本次实际DSP48E1数量：每套K3 4个、每套PW8 8个；不是仅添加属性后推测。各DSP的寄存器配置可查evidence/*/dsp_cells.tsv。

## 实现细节与第一版问题

乘法结果及其流水寄存器增加use_dsp=yes属性，乘法的UINT8×INT8符号扩展、INT32累加规则和有效拍不变。不是增加MAC数量，也不是减少卷积周期，而是用DSP资源替代一部分LUT算术。

第一版PW8虽然映射到8个DSP，却因输入读寄存器被DSP吸收，将原像素块RAM变成分布式RAM，导致总LUT反而增加。最终版把完全相同的512×64同步像素RAM封装成保留层级的内部模块，保留读边界；容量和读写时序不增加。修正后才采用本报告最终结果，首轮错误方向的报告仍保留在原目录，不当成节省LUT的版本。

## 验证范围

- PW8共129个主数值用例、K3共216个主用例，以及已有非法配置、尾块、反压、立即返回、clear重启、同地址换数据等检查通过；逐例周期、请求数、读字节和MAC数与修改前完全一致。
- 不只使用忽略综合属性的RTL功能仿真。还用Vivado XSim运行实际综合功能网表和厂商DSP/BRAM模型，每类3个用例，逐字节核对输出、覆盖、越界和MAC数。包含255/128无符号输入、-128/127权重、3×3/DW3、stride2，以及PW8多小块面板和512通道。
- 所有时钟周期结果只说明功能和延迟没有改变；没有宣称DSP映射使整个网络周期减少。

## 综合时序

10ns约束下，K3 WNS -1.719ns，PW8 WNS -1.502ns。PW8映射前为-1.087ns，映射后裕量略差；当前收益是资源减少，未证明物理运行频率提高。存在负裕量，不能保证当前模块或整个SoC上板100MHz。综合后的功能网表仿真没有回标布线延迟，不能代替时序收敛。
