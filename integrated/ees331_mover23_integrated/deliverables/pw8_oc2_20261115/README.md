## 改动

此前一个MAC工作拍计算8个空间位置的同一个输出通道。现在同一份64位像素RAM读结果供两组权重使用，同拍计算相邻两个输出通道：8×2=16路UINT8×INT8乘加。每通道各有8个INT32累加器，奇数Co的最后一个通道只使用第一组。

输入仍为HWC，权重仍为OHWI，输出仍为HWC/INT32。CPU任务格式、外部32位请求/应答接口、算子实例数、现有8项内部写队列保持不变；没有引入算子间直连/FIFO。一次只存在一笔外部未完成事务。

输入RAM容量仍为512×64位=4KiB。权重逻辑RAM从1KiB增加到2KiB：整层权重不超过原1KiB阈值时，将其镜像供两个独立读口使用；更大的层按两个输出通道分开存放，各自有计算/预取乒乓槽位。未扩大整层缓存复用阈值，外存读请求数量和字节数因此可以保持同口径。每个MAC工作拍读取两组不同的权重，增加8路乘法、8个32位累加器及对应乘积寄存器/控制；这不是综合后的LUT或DSP数量。

一个输出通道对的两个通道依次进入原写队列。16个结果仍需经过原来的32位存储端口写回，因此总耗时不会减半。计算更快后，写队列和权重预取等待会更突出。

生产有6套PW8，默认都会使用16路结构：RTL乘法通路总共增加48路。输入/输出接口不变不代表资源成本不变；BRAM物理块粒度、LUT、FF、DSP推断和10ns时序尚未测量，不能保证上板频率或资源容纳。

## 小规模性能

这里的原版是刚才934.5ms整图实验采用的“连续8像素、单输出通道”版本，已经包含此前的输入预取、面板复用及地址寄存器优化。新旧使用完全相同的确定性应答延迟与反压；周期包含初始化、读入、乘加、排队及最终写回应答。

以上均为1×1、stride=1、对齐地址。每一例的有效乘加总数、输出值、外部请求总数和读取字节数完全相同；减少的是同时计算两个输出通道所需的工作拍。偶数Co的工作拍减半，奇数Co为原工作拍÷Co×ceil(Co/2)，213例全部核验。

这只是单算子测试存储模型下的结果。不能把25%～38%直接套用到整网，也不能据此宣布此前934.5ms已降到某个新数值。DDR换页、后处理、K3、Add、Pad尚未在新版本下运行完整129任务网络。

213例里有11例总周期变慢，最多增加238拍，最大相对增加2.26%，多为低通道数/小任务。完整结果见[逐例指标](unit_metrics.json)，没有只保留加速样例。

## 功能核验

- 213组几何/通道/对齐参数，每组运行5种设计：独立原版线性、双通道线性、回退单通道线性、独立原版4×2、双通道4×2；均与标量整数参考逐字节比对，共1065次正常数值运行。
- 覆盖Ci=1～512，Co=1、奇数、偶数及512，输入/权重非对齐，stride=1/2，跨行及尾部、面板阈值、整层权重缓存边界。
- 检查请求在反压时保持、最多一笔未完成事务、越界保护、写覆盖/重复写、输入/权重读计数、总MAC数及done晚于最后写回应答。
- 原有9次clear/restart、运行中描述符变化、13类非法配置、即时应答、同地址更换图像/权重后再启动的额外回归通过。
- `OUTPUT_PAR=1`的213例周期、请求数、读取字节数精确复现独立原版；`LINEAR_GROUPS=0`也验证双通道数值正确。默认`OUTPUT_PAR=2`、`LINEAR_GROUPS=1`。
- 8任务SoC门槛：17,964字节中间结果及最终输出均匹配；真实CPU配置/片上RAM/MOVER双向DDR访问、结果fence和复位通过。此小门槛用于核对接入，不代表整网加速。

K3、Post、Add、Pad、调度器、CNN接线、存储控制器和MOVER源码哈希保持不变。`simulation/rtl`里的历史副本未同步覆盖，生产与此次测试仍使用根目录`rtl`。
