# UART 图像桥协议与使用（IMIO v1）

日期：2026-10-08。RTL：`rtl/soc/image_bridge.sv`；板级顶层：`face_soc_top`。
这是本次实际实现的 SRAM 分块传输协议。旧 `fpga_fixed_firmware_image_io_plan.md` 中 IMG0 整帧头只是草案，不是当前 UART 硬件协议。原始图像可分多包传输，但本模块不解码 JPEG/PNG，不生成 CNN 描述符、不自动启动 CNN。

## 1. 串口参数

默认 115200 baud、8 数据位、无校验、1 停止位（8N1），空闲为高，低位先发，无硬件流控。
时钟默认 50 MHz；每位使用整数 `CLOCK_HZ/BAUD` 个时钟。两端频率误差需满足串口采样要求，参数应确保除数至少为 4。
**发送一包、等待完整回复，再发下一包**。桥处理访存/回复期间不接收下一包，没有无限队列。

## 2. 请求包：电脑 → FPGA

| 字节偏移 | 长度 | 内容 |
|---|---:|---|
| 0..3 | 4 | ASCII `IMIO`，十六进制 49 4D 49 4F |
| 4 | 1 | 操作码：1=写 SRAM，2=读 SRAM |
| 5 | 1 | tag，0..255，回复原样带回 |
| 6..7 | 2 | length，1..256，低字节在前 |
| 8..11 | 4 | SRAM 字节地址，低字节在前 |
| 12 起 | length 或 0 | 写请求带 length 字节原始数据；读请求不带数据 |
| 最后 4 字节 | 4 | CRC32，低字节在前 |

CRC 覆盖前面完整包头和写数据，不包括 CRC 自己。算法为 CRC-32/ISO-HDLC：反射多项式 `0xEDB88320`、初值 `0xFFFFFFFF`、最终异或 `0xFFFFFFFF`，与 Python `zlib.crc32()` 一致。
写包长度 `16+length`，读包长度 16。地址允许非 4 字节对齐，桥内部拆成对齐 RAM 访问和字节使能；整段地址必须在配置的 SRAM 范围内，不能跨越末尾或 32 位地址溢出。

## 3. 回复包：FPGA → 电脑

| 字节偏移 | 长度 | 内容 |
|---|---:|---|
| 0..3 | 4 | ASCII `IMOR`，49 4D 4F 52 |
| 4 | 1 | status，见下表 |
| 5 | 1 | 请求 tag |
| 6..7 | 2 | 数据长度：成功读为请求 length，其余为 0 |
| 8..11 | 4 | 原请求地址 |
| 12 起 | 0 或 length | 成功读回的数据，按连续字节地址排列 |
| 最后 4 字节 | 4 | 对回复头和回复数据计算同样的 CRC32 |

| status | 含义 | 后续处理 |
|---:|---|---|
| 0 | 成功 | 可发下一包 |
| 1 | 请求 CRC 错误 | 未访问 SRAM，重新准备数据后再发 |
| 2 | 未知命令、长度为零或超过上限 | 不访问 SRAM；接完整包头后立即拒绝，剩余非法包内容丢弃 |
| 3 | SRAM 地址范围错误 | 整包不写入，不会先写合法部分再发现越界 |
| 4 | SRAM 返回 error，包括 CPU A 口冲突 | 停止本包；之前成功写入的字节不回滚；修复所有权后重新传输/校验 |
| 5 | 等待 SRAM 接收/读返回超时 | 回包后桥停机，需整体复位；不能把迟到读数据当作下一包数据 |

所有错误置 `bridge_error`，直到系统复位才清除。status 1..4 回包后仍可收新请求。内存超时可能已写入前一部分，不保证整个写包事务原子性。
串口帧错误或收包中断超过 `TIMEOUT_CYCLES` 时丢弃不完整包、亮错误灯，不回包（可能连 tag 都没收到），恢复寻找 `IMIO`。默认超时为 1 秒；本次仿真使用更短参数验证。
CRC 错误或回包丢失后不要盲目重发可能触发固件动作的 mailbox 写入；主机不能仅凭超时断定写入没有发生。

## 4. 电脑上的操作

工具：`scripts/uart_image_transfer.py`，协议单元测试不需要串口。真实串口使用 `pyserial`，如环境缺少需自行安装 `python -m pip install pyserial`。

```powershell
# 先确认板卡固件允许使用 0x1000 这块 SRAM，再上传原始图像并逐包读回校验。
python scripts/uart_image_transfer.py --port COM5 --address 0x1000 write image.raw --verify

# 从同一地址取回 4096 字节到文件。
python scripts/uart_image_transfer.py --port COM5 --address 0x1000 read image_readback.raw --length 4096
```

COM5 和地址只是示例，不能据此断言已冻结图像地址。脚本自动拆成最多 256 字节的小包，检查回复 magic/tag/address/length/CRC/status；不会自动重试失败写入。
上传过程中 CPU 和 CNN 必须不访问正在修改的数据区。桥可以写 SRAM 中的约定 mailbox，但本次没有编造新的 mailbox 地址或配套人脸识别固件。CNN MMIO 不能经本协议直接访问，IEM 也不能经本协议下载程序。

## 5. 实现边界

- UART RX 两级同步、起始位确认、8 位采样、停止位校验；UART TX 独立完整 8N1 帧。
- 请求数据先缓存在桥内，整包 CRC 和地址检查通过后才写 RAM。默认最多 256 字节，不缓存整张图像。
- 读回每次取一个 SRAM 字，再选中对应字节，优先正确性和清晰性，不宣称最大带宽优化。
- 数据 RAM、图像桥和 CNN 同一时钟，无跨时钟 SRAM CDC。
- 真实板卡尚需引脚、电平、时钟参数与固件配置；当前结果是 RTL 串口波形仿真，不是物理串口上板验收。
