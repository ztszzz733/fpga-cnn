# 完整 MobileFaceNet 顺序验证入口

本入口先验证一张112×112 RGB图片从输入到128维特征的完整数值路径。它是隔离的CNN实验入口，不替换已有双NEureka、多槽、残差调度器，也不修改CPU、UART或生产DATASRAM。

## 数据路径

`quant_network_sequential` 从存储读取命令表，依次启动真实NEureka、`dw7_cached_engine`、`quant_post_engine`和`pad_hwc_engine`。卷积、逐元素激活/量化、残差Add以及补边均由RTL执行。测试平台只承担时钟、SRAM响应、仲裁和结果核对。

固定模型有51层卷积、12处Add；ReLU/ReLU6融合在对应卷积的后处理参数中。末端7×7逐通道卷积之后仍有512→128的1×1投影；模型最后的reshape只是读取顺序变化，不需要计算算子。本模型输出未经L2归一化的128维向量；比较和归一化不在当前硬件范围内。

前处理由软件将已经裁剪的人脸RGB归一化、量化，预加载到SRAM。浮点ONNX用于产生独立对照和本次诊断量化尺度；整数参考从量化图片逐层计算，不向RTL中间区域注入参考答案。所有中间区初始填0xA5，后续层读取硬件真正写出的数据。

## 为什么另做顺序入口

现有并行入口一次32节点、输出通道最多128；完整网络需要更多命令、256/512通道、7×7算子、边界填充。先用简单的命令表验证这些配置与数值链，再把同一网络映射到并行调度，便于区分算子错误和调度错误。本入口不会自动并行执行不同命令，不能用于宣称多图流水已经完成。

命令表最多65535条，每条16个32位字，占64字节。控制器经存储端口逐字读取，只在算子最后写响应完成后推进。命令类型：0 NEureka寄存器配置；1 INT32后处理；2 双输入Add；3 DW7；4 一像素补边。命令字段由 `gen_mobilefacenet_full.py` 输出；第10/11字的核对地址/长度只由测试平台使用，RTL不会读取金标准。

| 字序号 | 含义 |
|---|---|
| 0 | 类型0～4 |
| 1 | NEureka配置地址或输入A地址 |
| 2 | Add输入B或DW7权重地址 |
| 3 | 输出地址 |
| 4 | 后处理逐通道参数地址 |
| 5 | 后处理元素总数 |
| 6 | 通道数 |
| 7/8 | DW7或补边输入宽/高 |
| 9 | 补边数值，取低8位量化零点 |
| 10/11 | 测试核对地址/字节数，硬件不使用 |
| 12 | 网络节点编号，便于观察 |
| 13～15 | 保留 |

NEureka仍按每组32输出通道发任务，跨输入通道的卷积累加由真实NEureka完成。DW7输出512个INT32，随后通过原后处理。所有层保持原始空间尺寸和通道数，没有通过缩小网络替代全网。

## 实验入口接口

| 端口 | 方向 | 当前语义 |
|---|---|---|
| `descriptor_base / command_count` | 调用方→CNN | SRAM命令表首地址/命令条数；空闲时随start锁存 |
| `start` | 调用方→CNN | 单周期启动；本入口无在线追加命令接口 |
| `busy / done / error` | CNN→调用方 | 执行中/全表完成/错误；done和error保持到clear或复位 |
| `clear / cancel` | 调用方→CNN / CNN→存储 | 中止任务并取消在途请求；存储必须丢弃旧响应 |
| `memory_fault` | 存储→CNN | 置位后中止并进入错误态；不自动重试 |
| `mem_valid / mem_ready` | CNN↔存储 | 每客户端的请求握手；等待期间保持地址和数据 |
| `mem_write / mem_byte` | CNN→存储 | 写使能；整字32位或低字节访问 |
| `mem_addr / mem_wdata` | CNN→存储 | 14路×32位，字节地址，小端数据 |
| `mem_response / mem_rdata` | 存储→CNN | 每个已接受读/写均返回完成，读返回数据；每路最多一笔在途 |
| `command_index / command_kind / layer_index` | CNN→观察端 | 当前命令编号、类型与网络节点标签，不是CPU已有MMIO寄存器 |
| `operator_start / command_done` | CNN→观察端 | 单命令发射/完成事件；后者晚于结果写响应 |

14个实验客户端分别为：0～8 NEureka宽访存拆分的9路、9 NEureka配置读取、10后处理、11 DW7、12补边、13命令表读取。这不是对生产DATASRAM端口数量的修改；后续对接可以由CNN内部汇聚接口。表中配置与权重在任务运行期间不得改写，调用方负责地址合法性、容量和不危险重叠。

## 存储和仿真边界

本次为可定位问题而保留每层输入/原始INT32/量化输出和权重，实验存储约20MiB。C++实现四bank、每bank每拍最多一笔事务、下一拍响应的SRAM模型，可附加反压。它不是生产256KiB/512KiB SRAM的容量证明；真正部署还需要条带、地址复用以及权重分批加载，不能照搬本次静态地址图。

补边由硬件完成：实数零用该层量化零点表示，不固定写字节0。通道数为4倍数时使用32位读写，否则使用字节读写。边界外补一圈，后续NEureka使用valid配置。

为了降低仿真开销，取消SV大数组SRAM与每拍文本输出，使用C++存储模型，只记录变化的控制信号。在非NEureka任务期间，顺序入口通过下降沿锁存的时钟使能停住卷积核；此门控未经综合/板级时序验证，最终应采用目标工艺的标准时钟门控或等价时钟使能实现。

平坦模型实测第一步补边192,271周期耗时44.326秒，未达到预期仿真速度，已主动停止该运行，不能视为全网PASS。后续尝试用Verilator的`hier_block`将`neureka_conv_engine`分开建模，控制文件只影响仿真编译，不修改算子逻辑。方法依据[Verilator分层编译说明](https://verilator.org/guide/latest/verilating.html#hierarchical-verilation)；是否降低运行开销仍以实际测试为准。原平坦编译缓存保留，分层缓存使用`.neureka_full_hier_build`。

分层模型第一步补边耗时18.427秒，仍有大量输入未变化时的重复求值。`cache_neureka_eval.py`仅在生成的DPI适配器中比较所有非时钟输入，时钟/复位变化仍必须求值；没有延迟事件且输入不变时，复用已稳定的输出。保留未改驱动程序，`check_full_eval_cache.py`用真实前三层和Add边界向量进行对照：21,792字节、70,824周期、55,524读/8,736写和完整控制VCD均相同；耗时21.412秒与14.816秒。该对照为有限测试，不是任意模型的形式等价证明。

全图第一步补边在缓存驱动中仍为192,271周期、耗时0.140秒。驱动优化只减少电脑重复求值，没有减少模拟硬件时钟，也没有替算任何卷积。运行记录另存原始/修改后DPI源、可执行程序及修改脚本哈希；缓存输入约束限于当前无延迟RTL模型，不能直接移植到包含定时事件的模型。

## 复现与判定

Windows Python运行 `scripts/gen_mobilefacenet_full.py build/mobilefacenet_full_data`。WSL运行 `python3 scripts/run_mobilefacenet_full.py --data build/mobilefacenet_full_data`；之后使用 `--reuse`，脚本核对源码和头文件哈希，不匹配时拒绝复用。

每次在独立 `build/runs/*_mobilefacenet_full` 目录保存结果、编译/仿真日志、实际控制VCD、逐命令完成事件与最终向量。只有全部命令完成、逐层结果和保护区都通过，`result.json` 才记录PASS。生成整数参考不等于RTL通过；完整单图通过也不等于人脸识别准确率或多图吞吐验证。

量化尺度从本次图片的浮点结果确定，只用于贯通诊断，没有独立校准集或识别测试集。输出与浮点向量的相似度只用于发现明显数值偏差，不作为识别率。
