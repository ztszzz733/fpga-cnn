# 23 路 CNN 新存储路径接口约定（本方暂定 v0.1）

日期：2026-11-11。适用入口：`rtl/soc/ees331/face_soc_ees331_mover_top.sv` 与 `rtl/filelists/system_ees331_mover23.f`。此约定由存储侧先行冻结，用于 RTL 开发和仿真；板级 PS 配置与最终资源收敛仍须集成验证。

## 结构与容量

新顶层固定采用 `POOL23=1`：K3×4、K1×12、Post×4、Add/DW7/Pad 各一，共 23 个 CNN 访存客户端。其请求经 `cnn_paged_mover` 仲裁进入 32 KiB `tile_local_ram`，只有 `data_mover` 驱动 HP0；旧 `cnn_cache` 和旧 `cnn_ddr_bridge` 不参与这个顶层。旧顶层和原 filelist 保留作回归对照。

32 KiB 本地 RAM 分为 32 个 1 KiB 页，元数据全相联查找。命中时访问本地计算端口；未命中时先找空页，否则按轮转指针选择牺牲页，脏页通过 MOVER 写回 DDR，再由 MOVER 搬入目标页。全局只接受一笔 CNN 请求或一个页搬运，先保证协议正确。该结构是透明的按需分页适配，不依赖 CNN 先提供完整 tile 调度表；独立的 `tile_row_dma` 保留给后续显式逐行搬运方案。

CNN 逻辑地址窗口为 64 MiB，默认 HP0 物理基址 `0x10000000`，均通过模块参数给出。地址以字节计；32 位字访问须 4 字节对齐，8 位访问可取任意字节位置，读取结果按有符号字节扩展到 32 位。写入支持字或指定字节。地址越界、未对齐的字请求、只读区写入均产生 `cnn_mem_fault`，不返回伪数据。23 路采用轮转仲裁，响应只送回原请求者。请求取消时停止新的计算访问，已开始的 DDR 搬运仍排空，取消请求不再产生 CNN 响应。

MOVER 一次处理一个 1 KiB 页命令，使用 64 位 AXI3 HP0 的单拍传输；写完成以 AXI B 响应为准。MOVER 的错误、超时、完成字节数不符都会锁定 CNN 存储故障。恢复须在空闲后通过 CSR 清错，板级系统性故障可要求整机复位。`tile_local_ram` 的 DMA 口与计算口保持原冲突优先级；新适配器在页搬运期间停发计算访问。

## 与现有 CPU 固件的 CSR 兼容

`image_control_bridge` 的缓存寄存器窗口仍保留。状态 `0x00`，命令 `0x04`，范围起点/长度 `0x08/0x0c`，模型只读边界/使能 `0x10/0x14`，统计 `0x20` 至 `0x3c`。命令 1 清写、命令 2 清写并失效、命令 3 空闲时清错。范围命令可在一笔 CNN 请求尚未结束时排队一条；执行时检查 32 个本地页，把范围内脏页写回，供 CPU/PS 在完成栅栏后读取 DDR。`0x3c` 返回本地页 RAM 容量 32 KiB。现有 CPU mailbox 固件无需为此路径改写。

CPU 仍有固定一拍的 16 KiB 本地 RAM。新顶层使用 `download_ram` 的 CPU 端口，但下载端口暂时关闭；IMEM 仍为 8 KiB ROM。程序下载/安全停机是另一项待集成接口，不由本约定的 CNN 存储路径宣称完成。

## 验证边界与后续

真实 CPU、23 客户端 CNN、tile RAM、DATA MOVER、模拟 PS DDR 的四组顶层样例已通过；覆盖短行、8×8×32、一致数据四帧并发、四帧六类算子诊断图。逐字节结果与旧缓存路径一致。详见 `docs/storage_mover23_integration_report_20261111.md`。

此版本优先保证功能：32 页全相联和按需换页可能产生额外 DDR 流量。四图测试不等于完整 131 步 MobileFaceNet 或真实板级 DDR 联调。PS 方仍需确认物理保留区、初始化、DDR 可见性和缓存一致性。XC7Z020 整机综合虽完成，但 LUT 超额，仍需算子/存储资源收敛及带约束的实现测试。
