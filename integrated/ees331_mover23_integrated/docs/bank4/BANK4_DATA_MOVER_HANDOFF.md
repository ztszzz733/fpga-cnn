# 4 bank 缓存与 DATA MOVER 并行开发对接协议

日期：2026-11-15  
适用范围：EES331 缩减版 SoC 的 CNN 分页缓存、392 KiB `tile_local_ram` 和 `data_mover`。

## 1. 共同基线和目标

- GitHub `ztszzz733/fpga-cnn` 的 `zhang` 分支提交为 `695c5a9de38f4d9408530c1c1877661f93129ffb`。本地共同工作基线现固定为 `bank1_ref/`：它在上述提交上加入了 `cnn_paged_mover.patch` 中的命中流水及缺页期间命中服务。`optimized/` 是本侧 4 bank 候选，`mover_side/candidate/` 是另一侧 MOVER 候选；本侧 `optimized/storage_v2/rtl/data_mover.sv` 与 `bank1_ref/` 对应文件相同。
- 当前顶层参数：12 个 CNN 客户端、4 个帧上下文、392 KiB 共享 RAM、1 KiB 页、单个 DATA MOVER、单条 64 位 AXI3 HP0 通道。每帧同一时刻最多运行一个任务。
- 目标是让不同 bank 中的驻留页命中请求能够同拍被接收，同时保持单算子速度和缓存容量；MOVER 侧独立改进 DDR 与本地搬运效率。两组修改分别验证后再合并。
- 本文是**开发接口约定**；4 bank 的独立实测见 `BANK4_RESULT.md`。此前全 SoC 综合为 137/140 块 BRAM36 等效、47,486/53,200 LUT；该报告早于本地分页器优化和本轮两项修改，资源余量只能作风险提示。
- bank 请求标签、少量排队和返回流水可以使用寄存器；页号比较、地址选择不需要专门占用 DSP。两侧均需报告新增的 BRAM、LUT、FF、DSP，尤其要提前同步任何打算新增 BRAM 缓冲的改动。

## 3. 固定的模块边界

### 3.1 分页器 ↔ MOVER 命令

| 信号/规则 | 对接约定 |
|---|---|
| `cmd_valid && cmd_ready` | 命令在该时钟沿被接收。对外维持一次最多一条未完成命令。 |
| `cmd_flags[0] == 0` | `cmd_src` 是 DDR 逻辑偏移，`cmd_dst` 是本地 RAM 字节偏移；方向为 DDR → RAM（填页）。 |
| `cmd_flags[0] == 1` | `cmd_src` 是本地 RAM 字节偏移，`cmd_dst` 是 DDR 逻辑偏移；方向为 RAM → DDR（脏页写回）。其余标志位保持为 0。 |
| `cmd_bytes` | 当前 CNN 分页器固定发送 `PAGE_BYTES == 1024`；一条命令只处理一页。DDR 物理地址由 MOVER 加 `cfg_ddr_base` 得到。 |
| `cfg_local_bytes` | 固定为 `LOCAL_BYTES == 401408`，即本地有效字节地址 `[0, 401407]`。MOVER 仍只见线性地址，不接收 bank 编号。 |
| `rsp_valid && rsp_ready` | 响应完成握手。成功时 `rsp_status == 0` 且 `rsp_bytes_done == 1024`；响应不得早于该命令所有本地写入及必要的 AXI 写应答完成。错误为非零状态，保留现有故障锁定/排空/恢复含义。 |
| `recover`、`fault_locked`、`drained` | 维持现有外部语义。当前 MOVER 仅在空闲时接受 `recover`，`drained` 在 IDLE 或等待响应的 RESPONSE 状态为高。 |

MOVER 可改变内部状态机、缓冲组织与合法的 AXI3 突发安排，但不能让分页器需要识别 bank，也不能在成功响应之前留下尚未提交的数据。

### 3.2 MOVER ↔ 本地 RAM 的 DMA 端口

| 信号/规则 | 对接约定 |
|---|---|
| `local_valid && local_ready` | 一笔 32 位字访问在该时钟沿被接收；最多接受一笔/拍。`local_ready == 0` 时 MOVER 保持待发请求，不能按已完成计算。 |
| `local_addr[31:0]` | 本地**字节地址**，请求时按 4 字节对齐；由 bank 适配层解码为 bank 与 bank 内地址。不得把局部 bank 地址直接回传给 MOVER。 |
| `local_write`、`local_wdata[31:0]`、`local_wstrb[3:0]` | `local_write == 1` 为写；`wstrb[k]` 控制地址 `local_addr + k` 的字节。保留现有字节序和无效字节不改写的行为。 |
| `local_rsp_valid`、`local_error`、`local_rdata[31:0]` | 对每笔被接收的请求返回一次响应，顺序与接收顺序一致；当前 RAM 在接收后的下一拍给出响应。读数据及错误与有效脉冲同时有效。不要返回未握手请求的响应。 |
| 吞吐时序 | 保留“上一笔响应出现的同一拍可接收下一笔请求”的能力；当前 MOVER 的 `lookahead` 依赖这一点来连续搬运。正常、无冲突且地址有效时不要人为插入 bank 切换气泡。 |
| 越界/非对齐 | 不能静默截断到另一 bank；维持错误响应语义。MOVER 自身仍按 `cfg_local_bytes` 检查命令范围。 |

当前接口无事务 ID，因此不得引入乱序 DMA 响应、同拍两笔 DMA 请求或多条对外并行命令。若 MOVER 优化需要 64 位本地口、多 DMA 口、乱序返回或改变请求/响应拍数，属于接口变更，须先共同评审。

## 4. 4 bank 的线性地址映射

共享容量不变，物理页仍是 392 个 1 KiB 槽。为避免 98 KiB 等分在 32 位双端口 BRAM 上留下半块容量，建议采用下表的不等 bank 容量；每页完整落在一个 bank 中。

| Bank | 槽号 | 全局本地地址（包含首尾） | 容量 | 估算 RAMB36 |
|---|---|---|---:|---:|
| 0 | 0–95 | `0x00000–0x17FFF` | 96 KiB | 24 |
| 1 | 96–191 | `0x18000–0x2FFFF` | 96 KiB | 24 |
| 2 | 192–291 | `0x30000–0x48FFF` | 100 KiB | 25 |
| 3 | 292–391 | `0x49000–0x61FFF` | 100 KiB | 25 |
| 合计 | 0–391 | `0x00000–0x61FFF` | 392 KiB | 98 |

`global_local_addr = slot * 1024 + page_offset`；适配层先按上述范围选 bank，再减去该 bank 的基址。命令起始页地址按 1 KiB 对齐，因此当前分页器的一条 1 KiB 搬运命令不会跨 bank。bank 数是物理端口分区，**不得把一个算子固定限制在一个 bank 的容量内**：页表和替换策略仍应允许单算子使用全部 392 个槽。需要按 bank 轮转分配或用等效机制分散热点；仅把现有 RAM 数组拆成四份、仍只选一路计算请求，没有并行收益。

## 5. 并发、冲突与一致性

1. 每个 bank 保留一条 32 位计算访问通路和一条 32 位 DMA 通路。不同 bank 的命中请求可同拍进入；同一 bank 的多个计算请求由该 bank 仲裁，并保持公平和正确的请求者响应归属。
2. DMA 与计算口访问不同字时可并行。访问**同一个字**时延续当前规则：计算口优先，`local_ready` 对 DMA 拉低，DMA 只能在真正握手后收到响应。不得依赖 FPGA BRAM 同地址双口读写的未定义结果。
3. 正在写回或填充的物理页槽上锁；其他驻留页，包括同 bank 的不同页，仍可命中。页表旁路/最近页寄存器在换页后必须复核标签或代数，避免指向已复用槽。
4. 脏页写回完成后才能复用其槽；新页填充完成后才能对计算口标记有效。`fence`、失效、取消和故障时，等待相关在途请求和 MOVER 事务按原协议排空，不得丢失写入或提前报完成。
5. bank 数增加只扩大片上命中端口；MOVER 和 HP0 仍是共享的一条搬运路径。MOVER 优化可能增加 DMA 活跃率，因此必须实测组合后的 bank 冲突、缺页等待与单算子延迟。

## 6. 两侧独立交付与集成顺序

### 4 bank 侧交付

- RTL 及地址映射说明；保持第 3 节 MOVER 接口不变。
- 四 bank 同拍独立命中、同 bank 仲裁、边界地址、全部字节写使能、同字 DMA 冲突、缺页锁槽、清刷/取消/错误恢复的仿真结果。
- 统计至少包括每 bank 的请求数、冲突等待周期、各客户端响应数、命中/缺页、DDR 读写字节。给出单客户端和四客户端的周期对照。

### MOVER 侧交付

- RTL 及独立回归；保持第 3 节命令和本地 RAM 接口不变。
- 覆盖 1 KiB 双向搬运、4/2/1 字节尾部、非对齐本地起点、AXI/本地反压、4 KiB DDR 边界、错误/超时/恢复；核对最终字节内容和 AXI 合法性。
- 统计每页搬运周期、DDR 有效数据拍/空拍、MOVER 忙碌周期与额外缓冲资源。

## 7. 需要双方同步的接口变更

出现以下任一情况时，暂停仅依赖文件分工的独立合并，先共同更新接口约定：本地口宽度或每拍请求数改变；DMA 响应延迟/顺序改变；对外多命令在途；`cmd_src/dst/flags` 语义改变；页大小或 `LOCAL_BYTES` 改变；新增占用 BRAM 的缓冲；改变 `recover/drained/fault_locked` 或完成响应的含义。其余内部优化可继续并行。
