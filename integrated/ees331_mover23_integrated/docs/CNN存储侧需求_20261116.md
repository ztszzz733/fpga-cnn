# 给存储同学的交付需求：支持任务图并行执行

日期：2026-11-16。配套：[软件侧需求](CNN软件侧需求_20261116.md)。

## 1. 交付目标

**软件提前把约50个算子任务编译成并行执行计划。存储模块要支持多个算子访问本地数据、计算时预取后续数据，并正确写回DDR，不能因一次搬运暂停全部算子的本地访问。**

支持同一图片的独立任务并行，以及不同图片之间并行。任务依赖由CNN计划执行器处理，存储侧只接收已就绪的搬运命令，负责搬运、访存仲裁和完成通知。

以下接口是待实现合同；当前自动分页路径还不能直接完成这些功能。

## 2. 需要实现的功能

| 功能 | 必须实现什么 |
|---|---|
| 显式LOAD | 将指定DDR范围搬到指定本地缓冲，不等待算子触发缺页 |
| 显式STORE | 将指定本地范围写回DDR，收到写响应后报告完成 |
| 本地地址窗口 | CNN访问本地地址时直接访问本地RAM，不执行DDR页标签查找或替换 |
| 计算/搬运重叠 | 算子访问A时允许DMA访问不冲突的B；共享DDR上的LOAD/STORE可以仲裁串行，不要求同时独占带宽 |
| 多客户端仲裁 | 多个卷积/后处理访问本地存储时公平服务，响应不能串到其他实例 |
| 队列和身份 | 命令满时背压，完成记录保留至被取走；支持图片、批次和命令编号 |
| 保护和恢复 | 检查范围、对齐和只读区；错误与超时报告明确；在途访问安全排空 |
| 能力与统计 | 返回真实可用容量/端口/并行限制，提供等待、流量和重叠计数供软件规划 |

先沿用当前392KiB共享本地RAM预算和共享搬运器；不要求为每个算子复制DMA。软件负责缓冲分配和生命周期，硬件负责实际访问与冲突处理。

## 3. 计划执行器→存储：搬运命令接口

| 信号 | 位宽 | 方向 | 含义 |
|---|---:|---|---|
| `cmd_valid/cmd_ready` | 各1 | 执行器→存储／存储→执行器 | 两者同时为1才接受命令 |
| `cmd_epoch` | 32 | 执行器→存储 | 批次编号 |
| `cmd_frame_id` | 32 | 执行器→存储 | 图片编号 |
| `cmd_id` | 32 | 执行器→存储 | 该图片计划内的唯一命令编号，LOAD/RUN/STORE统一编号 |
| `cmd_direction` | 1 | 执行器→存储 | 0=DDR→LOCAL，1=LOCAL→DDR |
| `cmd_ddr_offset` | 32 | 执行器→存储 | DDR合法窗口内的字节偏移 |
| `cmd_local_offset` | 32 | 执行器→存储 | 本地RAM字节偏移，不含本地窗口基址 |
| `cmd_bytes` | 32 | 执行器→存储 | 有效长度，必须大于0 |

未接受时保持命令稳定；接受不等于完成。物理DDR地址由存储侧基址加偏移得到，不能重复加基址。存储侧不接收未满足依赖的命令，不负责解析整个任务图。

可复用现有MOVER：LOAD映射为 `cmd_src=ddr_offset, cmd_dst=local_offset, cmd_flags=0`；STORE反过来，`cmd_flags=1`。新增身份字段可由外层队列保存，不要求直接改内部AXI ID。

## 4. 存储→计划执行器：完成接口

| 信号 | 位宽 | 方向 | 含义 |
|---|---:|---|---|
| `rsp_valid/rsp_ready` | 各1 | 存储→执行器／执行器→存储 | 完成记录有效/被接收；背压时保持字段稳定 |
| `rsp_epoch/rsp_frame_id/rsp_id` | 各32 | 存储→执行器 | 对应已接受命令的批次、图片和命令编号 |
| `rsp_kind` | 32 | 存储→执行器 | 0=LOAD完成，2=STORE完成；1留给CNN的RUN完成 |
| `rsp_status` | 32 | 存储→执行器 | 0成功，非0错误码 |
| `busy/drained/fault` | 各1 | 存储→执行器 | 忙、已排空、故障状态 |

- LOAD成功：有效数据已写入本地RAM，后续RUN可以使用。
- STORE成功：对应DDR写响应已收到；CPU读取仍须按协议完成PS缓存维护。
- 每条已接受命令只返回一次终态记录；失败即使已部分写入，目标内容也视为无效。
- 超时但仍有在途请求时保持故障/未排空，不假报安全完成；迟到响应不能归给新批次。

## 5. CNN算子→存储：保留请求接口，增加本地地址解码

| 信号 | 位宽 | 方向 | 含义 |
|---|---:|---|---|
| `valid/ready` | 各1 | 算子→存储／存储→算子 | 请求有效/接受 |
| `write/byte_access` | 各1 | 算子→存储 | 读写；单字节或32位字 |
| `addr/wdata` | 各32 | 算子→存储 | 字节地址/写数据 |
| `response/rdata` | 1/32 | 存储→算子 | 请求完成/读数据，保留当前无response-ready的契约 |
| `cancel/mem_fault` | 各1 | CNN→存储／存储→CNN | 取消/故障，沿用在途处理约定 |

地址约定：DDR数据使用 `addr=ddr_offset`；本地数据使用 `addr=LOCAL_BASE+local_offset`。本地窗口不得与DDR逻辑窗口重叠，保留当前字节返回与对齐语义。`LOCAL_BASE`为新增映射，需由存储侧实现并通过能力接口提供。

同一RAM只有有限端口，软件不能保证永不冲突，硬件仍需仲裁；不要求所有客户端每拍都拿到数据。若尚有自动分页副本，同一数据的显式访问必须隔离或同步，不能读到旧副本。

## 6. 存储能力查询接口

通过软件的 `hw_get_caps()` 返回以下字段；CPU查询寄存器地址由控制封装同学提供。

| 字段 | 必须说明什么 |
|---|---|
| `protocol_version` | 命令及完成接口版本 |
| `local_base/local_bytes` | 本地地址窗口及可分配容量 |
| `ddr_bytes` | 实际获准访问的DDR范围 |
| `alignment` | 地址、长度、尾字节的支持限制 |
| `queue_depth` | 搬运命令队列容量 |
| `local_access_limits` | 本地计算/DMA端口数、服务宽度及冲突规则 |
| `overlap_supported` | 支持哪些计算/搬运重叠组合 |

当前RTL部分配置的逻辑范围为64MiB，已有PS服务可能只放行16MiB；交付前统一实际保留区与软件权限，不能只改一个参数。

## 7. 验收和交付物

1. 交付上述端口、CPU命令/状态寄存器说明、实现和短测试；官方IP或现有模块能复用就复用，给出完整适配后的资源。
2. 搬运测试覆盖对齐、尾字节、跨4KiB、越界、保护字节、背压、错误、超时及排空。
3. 两个算子同时访问本地，DMA同时操作不冲突缓冲；波形证明实际服务与重叠，不能只展示busy。
4. 接入软件约50任务的分支/汇合计划；同一图片独立任务可并行，两张图片也可交错；输出和整数参考一致。
5. 注入DDR延迟和争用，仍不丢请求/完成事件、不覆盖在用缓冲、不串图片编号。
6. 报告DDR读写字节、纯等待/重叠周期、总周期，以及LUT/FF/BRAM/DSP与时序。与旧路径比较时保持算子、数据和约束相同。

当前实现参考：`storage_v2/rtl/data_mover.sv`、`storage_v2/rtl/tile_local_ram.sv`、`rtl/cnn_ddr/cnn_paged_mover.sv`。现有页管理器全局串行服务请求/页搬运，需要修改访问路径才能达到本目标；底层RAM有两个口不代表上层已实现重叠。

CNN同学负责计划依赖执行和解除同图单活动任务限制；存储同学负责本文件功能，软件同学负责编译计划。三方接口一致后先跑短测试，再安排整网仿真。本次仅重写文档。
