# 第一次运行测试

第一次使用只做下面四步，不需要改代码或填写一堆参数。

## 1. 打开命令窗口

在文件资源管理器中打开 `D:\cpu_control`。点击上方地址栏，输入 `powershell`，按回车。

这台电脑已有 Python 和 Vivado。Python 负责运行脚本，Vivado 负责模拟硬件；不用先打开 Vivado，也不用新建工程。换电脑时先看 [测试设置说明](测试设置说明.md)。

## 2. 运行测试

复制下面两行到窗口中，按回车：

```powershell
cd D:\cpu_control
python scripts/run_tests.py --plot
```

程序会自动编译代码、运行检查、生成图片。等待命令结束即可。这里只需记住 `--plot` 表示“生成图片”，其余使用项目默认设置。

## 3. 看最后一行

成功时会类似这样：

```text
PASS D:\cpu_control\build\runs\某次运行\result.json
```

“某次运行”实际是一串日期和编号。PASS 表示本次测试和绘图通过；FAIL 或 ERROR 表示有失败或流程没有完成。中间的英文先不用逐行看。

如果窗口还没回到可以输入命令的状态，程序可能仍在运行，先等它结束。

## 4. 打开结果

复制 PASS 后面的路径，粘贴到文件资源管理器的地址栏，删除最后的 `\result.json`，再按回车。这样就进入了本次结果文件夹。

| 先看这三个位置 | 用途 |
|---|---|
| `figures` | 双击其中的 PNG 图片看波形 |
| `result.json` | 用记事本查看总结果和检查数量 |
| `simulation.log` | 用记事本查看测试过程和失败位置 |

每次运行都会产生新文件夹，以这次终端给出的路径为准。已有示例图片不会自动被你的新测试替换。

## 四张图片分别看什么

| 图片 | 中文理解 |
|---|---|
| `decode.png` | 换一条指令时，控制输出是否跟着改变 |
| `forwarding.png` | 后一条指令能否及时用上前一条的计算结果 |
| `load_use.png` | 读取数据时先等一拍，再继续计算 |
| `branch_flush.png` | 跳转后取消错误路径上的指令 |

上表对应完整测试。使用 `--test decode --instruction 指令名` 只测指定译码指令时，应查看 `decode.png`；这张图显示 D 级机器码和译码输出，不应使用 E/M/W 冒险信号判断 ADD 是否译码成功。

如果想让一条或多条指定指令进入测试流水线，并单独查看 F、D、E、M、W 或全部阶段，请按 [指定指令阶段测试](硬件接口与完整指令说明.md#选择取指译码执行访存写回或全部阶段) 使用 `--test instruction --stage ...`。

先看第三张：内存读出 42，再加 7，结果是 49。控制模块安排了一次等待，避免后一条指令读到旧数据。“一拍”就是一个时钟周期。看图方法见 [波形来源说明](波形来源说明.md)。

## 出错时怎么处理

| 现象 | 第一步 |
|---|---|
| 找不到脚本文件 | 确认项目在 `D:\cpu_control`，重新执行上面的两行命令 |
| `python` 不是命令，或打开了应用商店 | 当前 Python 命令不可用，按 [工具准备](测试设置说明.md) 检查 |
| 提示缺少模拟器或绘图库 | 按 [工具准备](测试设置说明.md) 补齐工具 |
| 代码编译失败 | 打开本次结果目录的 `compile.log` |
| 测试运行失败 | 打开本次结果目录的 `simulation.log` |
| 没有图片 | 确认命令带 `--plot`、最后为 PASS，并打开本次的 `figures` |

请保留完整结果文件夹和终端最后的报错，便于排查。若还没生成文件夹，就保留终端报错。不要通过修改“预期答案”把失败变成通过。

修改代码并保存后，再运行同一条命令。脚本会重新编译，无需手动删除旧结果。
