# 简化CNN接口与使用边界

本版本只实例化两套K3（含DW3模式）和两套普通K1。软件明确指定单元、输入/权重/输出地址与尺寸，硬件没有旧任务模板RAM、帧PC、依赖图、缓冲区租约管理或自动选择空闲算子的逻辑。每个算子仍有执行卷积所需的局部状态机。

## 算子与数值

| 单元编号 | 功能 | 本地计算并行度 |
|---|---|---|
| 0、1 | 3×3普通卷积；或3×3 depthwise | 最多4个空间位置MAC/拍 |
| 2、3 | 1×1普通卷积 | 最多8个空间位置MAC/拍，单输出通道 |

步长1或2；输入/输出通道1～512；HWC布局；普通权重OHWI，DW权重按`[C,KY,KX]`；valid卷积，不自动补边。输入UINT8，权重INT8，输出原始INT32，采用原有32位累加语义。没有偏置、ReLU、量化、Add、Pad、DW7或池化。

特别注意：INT32输出不能直接按UINT8当作下一层输入。软件或后续新增的后处理模块必须完成正确的量化/激活。这个简化版本不能执行旧完整MobileFaceNet的PLAN.BIN。

保留moon的局部缓存、窗口/权重复用和同步RAM计算结构。K3缓存取字节与乘法之间增加一级寄存，最后一个结果标记同步延迟，MAC推进吞吐不变，每个输出通道块增加一拍排空。K3启动时的端地址计算与范围比较也分为两拍。K1关闭输入预取和外部连续读，输出通道并行由2改为1；内部原有写队列/权重缓存仍属于算子本体。

## CPU侧MMIO

`cnn_simple_top`的地址为CNN窗口内偏移；总线基地址由SoC地址译码方决定。`mmio_ready=1`，读数据组合返回。写请求每拍表示一次写，外部CPU适配器必须保证一次软件写只提交一次。

在所附SoC接线中，RISC-V的0x40000000窗口先进入`image_control_bridge`。CPU应向0x40000008写入`0x1000+CNN偏移`，再通过0x4000000c读写该CNN寄存器；不能直接把CNN偏移加到0x40000000当成直连寄存器。PS通过邮箱请求CPU访问，不能直接控制CNN。I/O回调由软件负责人实现该间接访问与屏障。

全局只读：

| 偏移 | 内容 |
|---|---|
| 0x000 | 版本ID `0x53434e31` |
| 0x004 | [3:0] busy、[7:4] done、[11:8] error，均按单元编号对应 |
| 0x008 | 配置标识`0x00000202`，表示K3×2/K1×2 |

单元u的页基地址`P=(u+1)*0x100`，分别0x100/0x200/0x300/0x400。

| 页内偏移 | 读/写 | 功能 |
|---|---|---|
| 0x00 | W | 写1启动，写2清除done/error，写4中止并排空本端口 |
| 0x04 | R | bit0 busy，bit1 done，bit2 error，bit3 abort/drain |
| 0x08 | R | 错误码：1算子参数/执行错误；2忙时修改/启动；3软件中止；4非法寄存器/命令；5存储故障 |
| 0x0c | R | 本单元累计成功完成次数 |
| 0x10 | R | [3:0]算子阶段，[6:4]访存桥阶段 |
| 0x14 | R | 当前任务累计实际MAC数量，按推进的有效位置累加 |
| 0x20～0x5c | RW | 16个描述符字；仅空闲时允许写入，运行中写入被拒绝 |

描述符按0-based字索引：

| 字 | 功能 |
|---|---|
| 0 / 1 / 2 | 输入 / 权重 / 输出逻辑地址 |
| 3 / 4 | 输入宽 / 高 |
| 5 / 6 | 输入通道 / 输出通道 |
| 7 | 步长1或2 |
| 8 | depthwise标志；仅K3支持，DW时输入输出通道相同 |
| 9 | K3输入行字节数`width*ci` |
| 10 | K3每输出通道权重字节数：普通`9*ci`，DW为9 |
| 11 / 12 | K3输入张量 / 权重张量总字节数 |
| 13 | K3计划标志：bit31版本有效，bit8输入整字读，bit9权重整字读，bit10整层权重缓存，bit0 depthwise |
| 14 / 15 | 软件标签暂存 / 保留；硬件不解析帧或任务依赖 |

`software/cnn_simple.h`提供描述符计算与校验、提交接口。它不安排网络依赖，也不分配存储。I/O回调的offset仍是CNN窗口偏移；`io_fence`必须使用目标CPU真实的I/O屏障。

软件执行顺序：准备并同步输入/权重，确认单元空闲，写描述符，执行I/O屏障，启动，轮询完成/错误，确认输出对其他使用者可见后再提交依赖任务。四个单元可同时执行独立任务；同一任务依赖由软件负责。

## 四路存储端口

`mem_*`按u逐路对应，32位地址/数据的u路位段为`[u*32+:32]`。

| 信号 | 方向 | 含义 |
|---|---|---|
| mem_valid[u] | CNN→存储 | 一笔已寄存的请求，等待接受期间保持 |
| mem_write[u] | CNN→存储 | 1写、0读 |
| mem_byte[u] | CNN→存储 | 1单字节、0完整32位字；字访问需4字节对齐 |
| mem_addr / mem_wdata | CNN→存储 | 请求逻辑地址 / 写数据 |
| mem_ready[u] | 存储→CNN | 本拍接受请求 |
| mem_response[u] | 存储→CNN | 本路前一笔请求完成，读和写都必须回复 |
| mem_rdata | 存储→CNN | 读返回；字节访问的有效字节放在[7:0] |
| memory_fault | 存储→CNN | 全局故障，寄存后中止四个单元；由存储负责人恢复存储端状态 |

每路最多一笔外部请求在途，四路总计最多四笔。外部可在接受请求同拍回复，也可延后回复；不允许没有已接受请求的回复。同一请求不能重复接受；无响应ID、无response_ready，存储必须保证回复不会丢失。

桥接阶段：IDLE=0，OFFER=1，WAIT_REPLY=2，RETURN=3，QUIET=4。请求地址、写数据和控制先寄存；外部接受/回复只修改桥的寄存状态。回复再寄存后同时向算子给出ready和response。没有外部ready直接贯穿算子并形成下一笔valid的组合链。

中止不会直接撤销共享存储中已缓冲/已接受的请求，而会排空它再释放本单元，因此中止后可能完成最后一笔写。busy归零前不得复用其输出区。硬复位要求整个存储互连同时复位、丢弃旧回复；不得只复位CNN却继续向它送旧回复。存储故障导致永不回复时，需要系统级恢复，本版不会假装超时后可以安全复用无ID端口。

## SoC接线版本

`rtl/face_soc_ees331_simple_top.sv`连接现有CPU、图像控制桥、两bank缓存和MOVER，CNN客户端固定为4；该接线版本不实例化旧CNN调度器或Post/Add/Pad。`soc.f`是对应清单；原moon的顶层和清单保留为基线，不能用于构建新CNN。

本轮SoC只做静态连线检查。原ROM/ARM `schedule.c`及旧PLAN协议不能驱动新MMIO，需要CPU/软件负责人按本接口更新。没有修改或验证完整启动软件，也没有生成可上板的新bitstream/BOOT.BIN。

## 小回归波形

`small_control.vcd`来自第一组四个独立小任务的真实RTL状态采样，非完整网络。聚合信号每位对应一个单元：busy包含计算/等待，actual_mac为实际MAC推进，request/ready/response观察请求接受和完成，write判断读写。operator_state每4位、memory_state每3位对应一个单元。

相同一拍actual_mac有两个及以上位为1才证明实际算术重叠；仅busy同时为1包含访存等待。时间轴按10ns周期生成，只是100MHz条件换算，不代表布局布线时序已签核。
