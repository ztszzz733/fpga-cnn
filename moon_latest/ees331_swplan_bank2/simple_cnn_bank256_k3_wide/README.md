# 3×3 与 1×1 共用 256 位写口

3×3 每组依次产生 2×2 个像素的同一输出通道结果。写回单元根据像素位置暂存结果。凑齐同一像素中 8 个连续、32 字节对齐的 INT32 后，向原有写口提交一笔 256 位写入。页内地址计算、bank 仲裁和 MOVER 与 FIFO 版逐文件一致。输出开头、结尾和短通道分组按 32 位写。所有写回应答回来后，算子才报告完成。

## 实测对照

| 指标 | 3×3 32 位单字写 | 3×3 256 位整笔写 |
| --- | ---: | ---: |
| 大用例整批拍数 | 1,828,016 | 1,824,359 |
| 每路 3×3 写请求 | 44,160 | 5,520 |
| LUT | 26989 | 28447 |
| FF | 19208 | 19934 |
| BRAM36 等效 | 84 | 84 |
| WNS (ns) | 0.387 | 0.272 |
| WHS (ns) | 0.028 | 0.033 |

放大窗口是整批第 45,800 拍到 48,400 拍。

两组使用相同的四个卷积任务、地址布局和 DDR 仿真模型。逐项核对 383,232 个输出。八组配置含非对齐输入和输出、深度卷积、步长 2、512 通道、页驱逐压力和中止重启。单独的混合写用例同时触发了 32 位写和 256 位写。

时序和资源报告来自 CNN、分页器、两块 96 KiB bank 和 MOVER 的独立布线。坐标轴按 100 MHz 模拟条件换算。整机接口已通过 Verilator 展开检查。

## 四个算子的波形

[逐拍放大图](wave/four_ops_zoom.png)和[全程图](wave/four_ops_full.png)的四组共用时间轴。每组最上面是算子状态，下面分别是读路忙、实际 MAC、写路忙和 256 位写请求被分页器接受。写路忙包含等待应答，可以和算子计算重叠。

在 GTKWave 打开 [放大会话](wave/four_ops_zoom.gtkw) 或 [全程会话](wave/four_ops_full.gtkw)，数据文件是 [four_ops.vcd](wave/four_ops.vcd)。垂直游标对应同一拍，可以查看四个算子的状态。

| 状态 | 3×3 | 1×1 |
| --- | --- | --- |
| 输入读取 | 5、6 | 4 |
| 权重读取或等待 | 7、8 | 5 |
| MAC 状态 | 9、A | 6 |
| 结果入队 | B、C | 7、8 |
| 等待积压结果写完 | F | 9 |
| 完成 / 空闲 | D / 0 | A / 0 |

MAC 线表示这一拍实际累加。256 位写脉冲表示分页器接收请求。DDR 分页器状态 3、4 是写回脏页，5、6 是从 DDR 补页。

## 复现

在 WSL 下运行 `bash run_wide.sh 1`，改用 `0` 可复现 3×3 单字写的对照。新建 Vivado 工程时将 `EES331_CNN_VARIANT` 设为 `bank256_k3_wide`。
