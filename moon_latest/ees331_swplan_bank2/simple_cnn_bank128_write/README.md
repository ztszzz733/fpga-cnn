# 128 位 bank 写回与 8,192 项 1×1 结果缓存

## MOVER 连续搬页

采用 Bai 分支提交 `f0f8e7c` 的 [data_mover.sv](https://github.com/ztszzz733/fpga-cnn/blob/f0f8e7cc7ae5310d73628457bcfdd54ac2aaa0b8/versions/ees331_bank2_stream_v1_20261122/project/source/storage_v2/rtl/data_mover.sv)。MOVER 的本地请求与响应分别计数，每次搬 1 KiB 页时最多四笔有序在途。DDR→bank 的填页和 bank→DDR 的取数都可连续发出本地请求；向 DDR 写入时可连续发送 16 拍 AXI 数据。每页仍按 8 个 128 字节的 AXI3 burst 搬运。

对照使用相同的双 96 KiB、64 位算子读、128 位算子写及每个 1×1 的 8,192 项结果缓存。只有 MOVER RTL 替换为该提交。Bai 的 32 位算子桥支持多笔写在途；本版本沿用宽数据接口，该桥的成绩与本实验使用的任务不同。

| 对照指标 | 旧 MOVER | 连续 MOVER |
|---|---:|---:|
| 1 KiB DDR 填页（拍） | 1211 | 467 |
| 1 KiB bank 写回 DDR（拍） | 1059 | 459 |
| 最长连续本地请求（拍） | 1 | 32 |
| 最长连续 AXI 写数据（拍） | 1 | 16 |
| 四路主用例（拍） | 175,292 | 100,272 |
| 跨容量压力用例（拍） | 822,673 | 525,651 |
| LUT | 23,927 | 23,925 |
| FF | 17,296 | 17,326 |
| BRAM36 | 76 | 76 |
| DSP | 18 | 18 |
| WNS | +0.389 ns | +0.236 ns |
| WHS | +0.024 ns | +0.018 ns |

微测在 DDR 无额外等待、本地 1 拍应答时统计。两版各通过 Bai 提供的 82 项 DMA 回归，涵盖读写两向、背压、错误和超时后的恢复。双 bank 集成测试校验了四路主用例的 20,416 个 INT32 输出，以及跨容量、未对齐和取消后重启。主用例两版都搬入 112 页，算子侧读写字节与宽写笔数一致。计时截止到最后一个算子的 bank 写回应答，后续验证用缓存刷新另计。

10 ns 和资源结果来自 XC7Z020 的 CNN＋分页器＋MOVER＋双 bank 布线。整机源文件清单通过静态检查。使用 `bash run_bank.sh 1 192` 可复现当前集成测试；`bash tests/mover_stream/run.sh baseline` 和 `bash tests/mover_stream/run.sh stream` 可复现 DMA 对比。

四路主用例校验了 20,416 个 INT32 输出。在 96 KiB 压力用例中，访问的页数超过驻留容量，一部分脏页在任务结束前就被换回 DDR。两版均在最后一笔 bank 写回应答后停止计时，随后的验证用缓存刷新另计。每个算子的输出结果、读写字节数及宽写笔数保持一致。带 CPU 的整机文件清单通过静态检查；时序和资源数字来自 CNN、分页器、MOVER 与双 bank 子系统。

复现这个容量对照时，在工程副本用 tests/mover_stream/reference/data_mover.sv 还原原 MOVER，然后用 WSL 执行 `bash run_bank.sh 1 192` 复现，`bash run_bank.sh 1 392` 可对照原容量。Vivado 测量用 `vivado_compare.py 1`。板级可选入口 `EES331_CNN_VARIANT=bank128_write` 默认每块 96 KiB；如有 `local_kib.txt`，其中填的是**两块总容量**，填 `192` 即可明确选择本配置，填 `392` 可复现原容量。

适用于 moon 工程里的两套 3×3、两套 1×1 CNN。每个共享 bank 有四条 32 位 BRAM 分路。16 字节对齐的宽写在一次 bank 操作中写入四个连续 INT32。3×3 走原有窄写协议。1×1 的非对齐头尾走 32 位写。两种读请求和 32 位 DMA 继续按相同字节地址访问存储。

每个 1×1 有独立的 **8,192 个 INT32 结果位置，共 32 KiB**。计算仍以输出通道为外层遍历。为使写入连续，算子根据 HWC 输出地址把结果放进缓存，写回端按地址递增读出。每个像素块只保存一次首地址和结果数量。缓存采用两个 **4,096 项**槽，先完成的块优先写回。一个槽收集下一块时，另一个槽可排空上一块。算子在两个槽都占用时等空槽，任务在全部写回应答后完成。

每槽最多容纳 4,096 个结果。因此像素块尺寸也受输出通道数限制，例如 128 输出通道时最多 32 个像素一块。当前写回桥在同一路等一笔应答再发下一笔。128 位宽写以四个结果共享一次物理写回应答。

## 原容量每块 196 KiB 时的写口对照

两个版本都使用 64 位读，下面比较 32 位旧写回与 128 位新写回。四项同批提交，输入按 8 字节对齐。计时包含分页搬入、计算及 bank 写回应答，验证输出时另外执行缓存刷新并从 DDR 模型逐项比对。

| 用例 | bank 写笔数，旧 → 新 | 算子周期，旧 → 新 |
|---|---:|---:|
| RGB 3×3 → 8 | 1,760 → 1,760 | 72,929 → 69,379 |
| 64→8 3×3 | 224 → 224 | 81,063 → 89,578 |
| 16→128 1×1 | 16,384 → 4,096 | 313,654 → 175,290 |
| 64→16 1×1 | 2,048 → 512 | 94,425 → 73,809 |
| **整批** | **20,416 → 6,592** | **313,656 → 175,292** |

对齐版整批耗时降 **44.1%**，4 字节对齐的旧地址版耗时 315,437 → 175,972 周期。主场景两版各校验 20,416 个输出。压测增加了输入输出不对齐、奇数通道、步长 2、DW3、512 输出通道、跨页和随机 AXI 等待。两个压测各版分别校验 969 和 79,296 个结果。另在一笔宽写在途时取消任务，排空后在新地址重启并校验 16,384 个结果。

较重的 16→128 任务因分为四块而重新装填部分权重，算子 bank 读入从 6,144 B 增为 10,240 B。四路整体访问和仲裁节奏也随之改变。64→8 的 3×3 有单项回退，整批仍由 16→128 的 1×1 决定。两版主场景的 DDR 模型搬入量都是 114,688 B。

## 复现和启用

WSL 中在本目录运行 `bash run_bank.sh 0 392` 和 `bash run_bank.sh 1 392`，分别复现 32 位写回与 128 位写回。Windows 用 Python 运行 `vivado_compare.py 1` 测量当前 96 KiB/块的 128 位写回子系统布线。两版均以 XC7Z020 上 10 ns 的时钟约束测量。

用仓库 `build.tcl` 对新建的 Vivado 工程运行综合时，如需选择本版本，在启动 Vivado 前将环境变量 `EES331_CNN_VARIANT` 设为 `bank128_write`。整机文件清单是本目录 `soc.f`。同一个 Vivado 工程一次只加载一套 CNN 文件。
