# 四算子 CNN 的突发读取实验

1×1 卷积在步长为 1、像素及其通道连续存放时，已能用一条命令申请 64 个像素。真实双 bank 和 MOVER 的 RTL 仿真中，两个 3×3 和两个 1×1 同时运行，整批从 **324,961 降到 315,529 周期（减少 2.90%）**。两版都通过了 20,416 个 INT32 输出及输出区边界校验。

## 如何读取

| 输入 | 发出的命令 | 这一批实测 |
|---|---|---|
| 1×1 输入，步长 1 | 起始地址和当前像素块的字节数。沿连续地址装入已有的本地输入 RAM，卷积按原来的 8 个位置一组计算 | 16 通道时 64 像素一条命令，1,024 B。64 通道时同样一条，4,096 B |
| 1×1 输入，步长 2 | 每条覆盖当前像素的连续通道，下一采样位置重新发命令 | 数值回归覆盖步长 2 |
| 3×3 输入 | 对当前计算块的每一行，只申请还需装入的一段。能复用左侧重叠列时，只读新列 | RGB 算例第一段为 4 个像素即 12 B，复用两列后的一段为 6 B。64 输入通道算例最长 256 B |
| 3×3 和 1×1 权重 | 对本地权重 RAM 本次要装入的连续权重发一条命令。整层能缓存时可一次申请整层，否则按输出通道等现有计算分块装入 | 3×3 有一条 4,608 B 命令。1×1 的两项分别是 16 B 和 1,024 B |

例如输入是 16×8、64 通道的连续 UINT8 特征图，每个像素占 64 B。前 64 个像素从地址 A 开始，一条命令覆盖 A 到 A+4,095，后 64 个像素再发一条。读控制器在本例对齐地址上把每条命令展开成 1,024 笔 32 位传输。每路有 4 个有序返回槽，bank 接受请求时可以继续送下一笔。返回数据可以分拍到达，bank 仲裁可在不同算子之间切换。首尾未对齐时按字节处理，读区间不会越过描述符指定的段。

当前配置 MAX_CHANNELS=512 时，步长 1 的 1×1 按输入通道数确定一块有多少空间位置。1–64 通道最多 64 个，65–128 最多 32 个，129–256 最多 16 个，257–512 最多 8 个。尾块取剩余位置数。扩展的是搬运范围，MAC 并行度仍为每个 1×1 算子 8 个空间位置。分页和 DDR 原有的 AXI 传输由 MOVER 负责。结果写回使用原单笔写通路。

## 四个算子同时运行时

| 算子、输入和输出通道 | 原周期 | 突发读周期 | 耗时减少 | 原 / 新 bank 读笔数 | 新输入 / 权重命令 |
|---|---:|---:|---:|---:|---:|
| K3_0，24×12，3→8 | 84,151 | 64,347 | 23.53% | 1,494 / 714 | 220 / 1 |
| K3_1，9×6，64→8 | 109,272 | 89,878 | 17.75% | 2,304 / 2,304 | 32 / 1 |
| K1_0，16×8，16→128 | 324,959 | 315,527 | 2.90% | 1,536 / 1,536 | 2 / 256 |
| K1_1，16×8，64→16 | 96,927 | 92,045 | 5.04% | 2,304 / 2,304 | 2 / 1 |
| **四项整批** | **324,961** | **315,529** | **2.90%** | **7,638 / 6,858** | **256 / 259** |

原版需要单独发起 7,638 笔读访问。实验版让 515 条段命令驱动 6,858 笔 bank 读访问。RGB 的短字节读能合并成对齐的 32 位读，其他三项的原始访问已按字读取。两版拿到的算子读数据都为 26,232 B，DDR 模型读入缓存的数据量均为 114,688 B。

四项在相邻周期提交，所以各行周期不能相加。最晚完成的 K1_0 产生 16×8×128 个结果，仍需 16,384 笔写回。它决定了本次整批耗时。100 MHz 下按周期换算，整批为 3.24961 ms → 3.15529 ms，节省 94.32 µs。

## 测量边界和资源

测试使用真实 CNN、两 bank 的 392 KiB 缓存、分页器和 MOVER RTL，外接 AXI DDR 仿真模型。由测试台通过 MMIO 提交四项卷积。计时从开始提交到四项全部完成，包含冷页搬入、bank 竞争、计算及算子写回应答。随后单独刷新输出页，对模型 DDR 中的全部结果逐个比对，验证用刷新耗时不计入上表。四项工作中每项对应一层卷积，整网、CPU、UART 和板上实测带宽均不在本次测量范围。

| XC7Z020，CNN 单模块 | 原版 | 实验版 | 变化 |
|---|---:|---:|---:|
| 布线后 LUT | 10,204 | 11,047 | +843 |
| 布线后 FF | 9,346 | 9,658 | +312 |
| BRAM36 等效块 | 14 | 14 | 0 |
| DSP | 16 | 18 | +2 |
| 布线后 10 ns 建立余量 WNS | +0.589 ns | +0.370 ns | −0.219 ns |
| 布线后保持余量 WHS | +0.042 ns | +0.032 ns | −0.010 ns |

两次采用相同的芯片、CNN 顶层和 10 ns 时钟约束。新版本布线后建立与保持失败端点均为 0。表内资源为整个四算子 CNN。作为另一统计口径，综合后、布线前的 LUT 为 10,399 → 11,262。整机接线通过静态检查，整机布局布线和板测仍需单独验证。

## 使用与复现

同目录的 `cnn.f` 和 `soc.f` 分别是 CNN 独立入口和带 CPU、存储的整机源文件清单。新 CNN 顶层 `BURST_READ` 默认为 1，设 0 可测原版行为。沿用当前四算子 MMIO 与 `software/cnn_simple.h`。现有板级构建默认选 `simple_cnn`。试用本版时在独立构建中使用这里的 `soc.f` 及其相对路径；两个目录中有同名模块，每次构建只需一份清单。

在此目录的 WSL 终端执行：

```sh
bash run_bank.sh 0
bash run_bank.sh 1
bash run_trial.sh 0
bash run_trial.sh 1
bash lint_soc.sh
```

前两个命令复现上表。后两个回归各检查 160 项数值任务和 12 项 K1 地址边界，实验版另测四个端口在有未返回请求且有请求受阻时的取消、排空和重启。独立 CNN 测试用简化内存模型，与双 bank 数据分开存放。Windows 下在本目录用 Python 先运行 `synth.py` 再运行 `route.py` 可复现 Vivado 2025.2 的单模块测试。
