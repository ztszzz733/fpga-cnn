# 完整网络命令调度入口：两图小数据验证

2026-10-22。隔离入口 `quant_network_parallel`，不改生产 CPU、IMAGE_BRIDGE、DATASRAM，也不替换旧 `quant_residual_scheduler`。本次把完整网络已有的五种命令连接到自动调度框架，完成小数据真实 RTL 回归与完整命令表容量验证。完整两图数值仿真尚未运行。

## 为什么增加入口

旧残差调度器只有32任务、128通道以及固定8KiB临时槽，其任务把卷积和后处理绑定为一个整体。全网顺序入口已验证373条显式命令，包括512通道、硬件补边和DW7。新入口直接复用这套命令格式和真实算子，避免为扩容而改动旧版已经通过的条带和残差释放逻辑。

新入口包含两套4×4 NEureka、一套共享量化/激活/Add后处理、一套7×7逐通道算子、一套补边单元。RTL正常使用原始 `neureka_conv_engine`；仿真链接先前已编译且校验哈希的真实NEureka DPI库，两个实例各有独立内部状态。没有用软件卷积或延迟模型代替小数据数值回归中的NEureka。

## 调度规则与规模

`network_dispatch`默认1024条命令，指针10位、计数11位。每条命令最多两个前驱，前驱必须是编号更小的节点，因此禁止自依赖和环。多于两个前驱时，需在编排阶段建立完成屏障，当前没有独立屏障指令；本轮生成器采用每帧严格串行依赖，因此无需多前驱屏障。

每拍检查一个候选任务，扫描到表尾后回到表头。只有依赖完成且相应算子空闲才发射，最多每拍发射一项。两个NEureka都空闲时轮换优先；只有一个空闲则选它。帧号仅用于标记，不绑定硬件实例。后处理、DW7和补边各一个实例，资源不足时等待。

完成位在算子报告写回已结束后才置位；多个实例同拍完成可以同时更新位图与计数。`busy`包含访存和等待，不能当作每拍乘加证据。表扫描最多带来一轮命令数的选择延迟，尚未优化为就绪队列。该命令表约64KiB有效载荷，另有依赖和状态位；未做综合，不宣称面积小或能够直接映射到当前板卡。

## 编程接口

先复位或clear，等待 `program_ready`。按索引0、1、2…连续写入任务，不允许跳号或覆盖。每个 `program_valid && program_ready` 的上升沿接收一条。写完后撤销program_valid，再给start。运行中不能改表。完成或出错后需要clear才能装下一批。

| 信号 | 方向 | 功能 |
|---|---|---|
| program_valid / program_ready | 配置方→CNN / CNN→配置方 | 表项写握手 |
| program_index[9:0] | 配置方→CNN | 连续写入的索引 |
| program_command[511:0] | 配置方→CNN | 16个32位字，word0位于最低32位 |
| program_dep_valid[1:0]、program_dep0/1[9:0] | 配置方→CNN | 两个可选前驱；RTL使用这组端口判断依赖 |
| task_count[10:0] | 配置方→CNN | 与已装载数量一致，1～1024 |
| engine_enable[1:0] | 配置方→CNN | 启用的NEureka实例，在start锁存，至少一个 |
| start / clear | 配置方→CNN | 启动 / 取消并清空任务状态 |
| busy / done / error | CNN→配置方 | 运行 / 全部完成 / 错误，done/error保持到clear |
| cancel | CNN→存储适配器 | clear或错误时取消旧事务；禁止旧响应污染重启任务 |

这里的配置方在测试中是仿真驱动。尚未定义CPU寄存器映射，也未让CPU直接访问512位端口。可由同学后续通过32位寄存器或表项DMA适配，内部命令格式不要求外部物理总线512位。

| 命令字 | 功能 |
|---|---|
| 0 | kind：0 NEureka、1量化/激活、2Add、3DW7、4补边 |
| 1 | NEureka配置地址，或其它算子的输入A地址 |
| 2 | Add输入B，或DW7权重地址 |
| 3、4 | 输出地址、后处理参数地址 |
| 5、6 | 元素数量、通道数 |
| 7、8、9 | 宽、高、补边量化零点 |
| 10、11 | 测试检查地址/字节数，不参与算子计算 |
| 12、13 | 网络层标记、帧标记 |
| 14、15 | 文件里的两个前驱索引，0xffffffff表示无；驱动解码到依赖端口 |

命令格式来自已通过全网顺序测试的16字记录。NEureka读取24字配置表；每组输出32通道，512通道可展开为多条配置命令。共享后处理可处理512通道；DW7当前实例限定输入宽7，适用网络末端7×7×512→1×1×512，不是任意宽度的大核引擎。

## 存储接口

23路客户端，每路valid/write/byte、32位addr/wdata、ready/response、32位rdata。0～8和10～18分别是两个NEureka的9路存储字访问；9和19为各自的配置读取；20后处理；21 DW7；22补边。沿用请求被ready接受、response完成的语义。全局memory_fault导致取消和失败。测试台为四bank，每bank每拍最多接受一笔，返回延迟一拍并提供周期性反压；生产DATASRAM未修改。

这次不带旧三槽分配器和release_pulse。各帧分配独立地址区、保留所有中间数据，避免在调度验证中混入生命周期分配问题。完整双帧计划复制了同一个已通过的全网输入，约39.5MiB实验存储；这不是生产容量要求，也不是两张不同图的完整网络数值证明。当前小数据测试用两张不同人脸。

## 验证范围

数值回归运行 `20261022_215648_network_parallel`：两张真实人脸ROI分别经过已验证的前三层卷积及后处理；另外加入独立Add边界向量、真实7×7×512输入特征的DW7+后处理、不同数据的补边探针。DW7输入来自软件前缀，不能把它解释为这条三层ROI链继续走到了网络末端。共26条命令、每项检查48,884字节；后层ROI读取前层真实RTL输出，所有写入受可写范围检查。

正常双核、仅启用实例1、实例0限速叠加存储反压、中途clear后复位/重载四项全部PASS，输出SHA256相同。正常分配6/6，限速分配4/8；测试独立检查启动依赖、任务类型、禁止重复发射/完成、最终没有悬挂存储事务。重启测试会清掉旧内存事务并重装原始输入，不是断点续算。

完整命令容量测试使用746条实际全网命令的类型和依赖，但算子用延迟模型，只检查调度。完成分配292/292/126/2/34，另测双输入汇合、clear重启、自依赖拒绝、memory_fault取消。它不证明完整网络两图数值通过。

复现：Windows Python `scripts/gen_network_parallel.py build/network_parallel_data`；WSL `scripts/run_network_parallel.py --data build/network_parallel_data/small`，复跑可加`--reuse`；独立调度测试 `scripts/run_network_dispatch.py`。结果和波形见[交付说明](../deliverables/network_parallel/README.md)。
