# 八位置1×1与DW3有限优先调度

这一轮解决两个问题：普通3×3后已就绪的DW3排队过久，以及1×1在忙碌期约92%的周期已经在MAC，单纯降低控制开销不够。完整六图旧记录用于定位；本轮验证范围为单层及六图小网络，不重跑完整网。

## 八位置结构

`self_pw8_engine.sv`沿用`self_pw4_overlap_engine.sv`的存储协议、权重双缓冲和八字输出FIFO，将输出块由2×2扩成4×2。8个像素银行各保存最多512通道的输入，每拍各读一个通道，与同一INT8权重相乘。每个位置独立INT32累加，数值顺序和原参考相同。

横向块边界以4步进，纵向以2步进；右/下边界依据tile_w/tile_h屏蔽无效位置。输入和输出地址按HWC增量产生，stride2只改变取输入的位置间隔。对齐32位装载、非对齐字节回退、带地址输出队列、接受请求当拍返回、反压保持、最后写响应后done均保留。clear仍要求互连一起取消旧事务。

实际MAC数用`conv_mac_count`增量统计，`operator_work`一拍高可能代表1～8次MAC，不能按一拍一个MAC计数。最大空间只有1×1时额外位置无用，不能保证每层都加速。每个输入块跨输出通道复用，权重跨最多8个位置复用，大空间层减少反复加载权重的次数；没有缓存整层权重或做跨图片权重保持。

本轮曾试“四位置×双输入通道”，但测得供给瓶颈，未选为最终实现。相关早期PASS只是数值通过，不能误称吞吐提升。最终源为八空间位置。

## 有限优先调度

`stream_dispatch`新增`DW_PRIORITY=0`、`DW_BURST=2`。为1时，在K3有空闲实例期间扫描任务表，先选择已满足依赖、输入提交和缓冲预约的DW3；最多连续优先发射两项后切换为普通3×3优先。扫描一整轮仍无当前优先类别可发射，则回退另一类。对持续就绪的普通任务提供发射机会，避免无限偏向DW3；无法满足依赖/缓冲条件的任务不承诺固定等待上限。

K1/Post/Add/DW7/Pad的发射仍照常，不会被K3类别搜索统一阻塞。当前不是抢占式任务调度，也没有将一层任务拆成可抢占的条带。K3实例内的输入/权重装载时间仍算在占用中。完整786任务的一轮扫描最多786拍（条件100MHz为7.86微秒），与前图等待约数百毫秒属于不同量级。

优先推进前图可让它较早进入1×1池，但同时会改变K3负载和后处理排队。本次小回归显示首图延迟改善、整批略有退化，所以将策略保留为可选项。不能用首图延迟降低替代整批吞吐提升的结论。

## 接入

`self_stream_top`、`self_fixed_network_top`和仿真顶层透传`PW8=0`、`DW_PRIORITY=0`。运行器`--pw8`启用八位置核及前三轮优化；`--dw-priority`启用有限优先。两者均为编译/例化参数，不是现有CPU能运行时写的寄存器。实例数仍K3×2、K1×4，其余各1。

独立缓存分别为`.self_six_pw8_build`、`.self_six_pw8_build_priority`、`.self_six_wide_build_priority`。全网依然必须使用同配置小门槛与哈希匹配的程序，不能混用旧gate。本轮未启动全网、没有定时检查。

数值、等待时间、资源、所有运行目录见[验证报告](../deliverables/pw8_priority/README.md)。当前建议先选八位置1×1；有限优先可用于偏重首图响应的配置，全网吞吐效果尚待验证。
