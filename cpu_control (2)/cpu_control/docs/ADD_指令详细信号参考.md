# 一条加法指令怎样走完图中的五级流水线——新手报告

日期：2026-09-17。讲解依据：本轮用户提供的系统架构图、当前项目代码，以及本次单独执行加法指令得到的新仿真结果。

## 1. 本次真的运行了什么

本次运行 **ADD（加法指令）x6, x1, x2**，含义是：读取 1 号和 2 号寄存器中的数，把两者相加，再把结果写入 6 号寄存器。

| 项目 | 本次实际设置或结果 |
|---|---|
| 指令所在的字节地址 | 0 |
| 指令机器码 | 十六进制 `0x00208333`，32 位 |
| 1 号寄存器初值 | 1 |
| 2 号寄存器初值 | 2 |
| 6 号寄存器初值 | 0 |
| 执行级实际输入 | 1、2 |
| 执行级实际结果 | 3 |
| 最终 6 号寄存器 | **3，已直接读取仿真寄存器确认** |
| 寄存器写入次数 | 1 |
| 数据存储器写入次数 | 0 |
| 暂停次数、重定向次数 | 均为 0 |
| 五级阶段测试 | 1 个场景、23 项检查、0 失败 |

本次使用真实 CPU Control（中央处理器控制器）与 Datapath stub（数据通路验证模型）连接运行。图中数据通路的行为由模型表示，真实生产 Datapath（数据通路）和 CNN（卷积神经网络）尚未提供；本报告证明的是当前控制器与验证模型中的指令过程。

报告中的“信号发出与接收”按你给的图来解释。“图中信号名”与“代码实际信号名”不一样时，会明确给出对应关系。图没有给出芯片器件型号，因此这里讲的是硬件功能块及信号，而不是具体厂商器件。

## 2. 先认识图上的几个名称

| 图上的英文名称 | 中文名称 | 可以怎样理解 |
|---|---|---|
| CPU（中央处理器） | 执行指令的处理器 | 按程序要求读数、计算、写回 |
| CPU CONTROL（中央处理器控制器） | 控制部分 | 决定“做什么、选哪路、是否允许写” |
| CPU DATAPATH（中央处理器数据通路） | 数据处理部分 | 真正保存数值、传输数值和执行运算 |
| PC（程序计数器） | 当前取指地址寄存器 | 保存下一次要读哪条指令的地址 |
| PC MUX（程序计数器多路选择器） | 下一取指地址选择器 | 在顺序地址、分支地址、间接跳转地址中选择一路 |
| IF（取指阶段） | 读取指令 | 从指令存储器拿到机器码 |
| ID（译码阶段） | 解释指令 | 确定操作、来源和去向，读取寄存器 |
| EX（执行阶段） | 运算 | 本例在这里得到 1 + 2 = 3 |
| MEM（访存阶段） | 访问数据存储器的阶段 | 本例不读写数据存储器，只传递结果 |
| WB（写回阶段） | 结果写入阶段 | 把结果写进目标寄存器 |
| IR（指令寄存器） | 保存当前机器码 | 图中位于取指/译码流水寄存器里 |
| Register File（寄存器堆） | 32 个 32 位寄存器 | 保存本例的两个输入数和最终结果 |
| ALU（算术逻辑单元） | 加减、逻辑和移位运算硬件 | 本例把 1 和 2 相加 |
| LSU（加载存储单元） | 数据存储器访问硬件 | 加载或存储指令才需要它发起访问 |
| SRAM（静态随机存取存储器） | 图中的数据存储器 | 保存图片、权重和普通程序数据等 |
| MUX（多路选择器） | 从多条输入中选一条 | 类似由控制信号决定位置的开关 |
| RAW（先写后读相关） | 后一条指令等待前一条结果 | 前递或暂停用于处理这类依赖 |

图中的 IF/ID（取指/译码流水寄存器）、ID/EX（译码/执行流水寄存器）、EX/MEM（执行/访存流水寄存器）、MEM/WB（访存/写回流水寄存器）都是阶段之间的“暂存站”。它们在时钟上升沿保存数据，让下一阶段在随后一个周期使用。

**寄存器编号与寄存器数值是两回事。** 本例的源编号为 1、2，读出的数值恰好也是 1、2；这个相同只是测试设置。真实运行时，1 号寄存器完全可以保存 100。目标编号 6 也不是计算结果，结果是 3。

## 3. 32 位机器码怎样说明“谁与谁相加，写给谁”

ADD（加法指令）属于 R-type（寄存器型指令），本例的完整机器码分解如下。方括号中的位置从最低位 0 开始编号。

| 字段 | 位位置 | 本例二进制值 | 中文含义 | 接收者 |
|---|---|---|---|---|
| funct7（七位功能字段） | [31:25] | `0000000` | 配合其他字段区别加法和减法等操作 | ALU Decoder（算术逻辑译码器） |
| rs2（第二源寄存器编号） | [24:20] | `00010`＝2 | 从 2 号寄存器取第二个数 | Register File（寄存器堆）、Hazard / Forward（冒险检测与前递单元） |
| rs1（第一源寄存器编号） | [19:15] | `00001`＝1 | 从 1 号寄存器取第一个数 | Register File（寄存器堆）、Hazard / Forward（冒险检测与前递单元） |
| funct3（三位功能字段） | [14:12] | `000` | 配合七位功能字段选择加法 | ALU Decoder（算术逻辑译码器） |
| rd（目标寄存器编号） | [11:7] | `00110`＝6 | 将来把结果写入 6 号寄存器 | 沿流水寄存器送往写回端 |
| opcode（操作码） | [6:0] | `0110011`＝十六进制 `0x33` | 说明这是一条寄存器运算指令 | Main Decoder（主译码器）、ALU Decoder（算术逻辑译码器） |

拼接顺序为：`0000000 00010 00001 000 00110 0110011`，也就是十六进制 `0x00208333`。

**为什么要拆字段？** 指令存储器只保存一串位，不会直接告诉硬件“这是加法”。处理器把不同位段接到相应硬件，才能同时确定运算种类、源寄存器和目标寄存器。数据通路负责把字段取出来，控制器负责解释字段代表什么。

## 4. 先看按时间排列的完整过程

本次时钟周期是 10 ns（纳秒），上升沿发生在 75.001、85.001、95.001、105.001、115.001 ns（纳秒）等位置。小数 `.001` 来自测试平台的时钟起始偏移，不是硬件多花了一个阶段。

| 顺序 | 本次仿真时间，单位 ns（纳秒） | 本条指令所在位置 | 发生的事情 |
|---|---|---|---|
| 准备 | 70.001 之前 | 复位期间 | 清流水状态，装入指令，设置两个源寄存器 |
| 1 | 70.001～75.001 | IF（取指阶段） | 地址 0 指向指令存储器中的本条机器码 |
| 2 | 75.001 上升沿 | IF/ID（取指/译码流水寄存器） | 保存机器码与本条指令地址，进入译码 |
| 3 | 75.001～85.001 | ID（译码阶段） | 拆字段、产生控制信号、读取两个源寄存器 |
| 4 | 85.001 上升沿 | ID/EX（译码/执行流水寄存器） | 保存 1、2、目标编号 6，以及加法控制字 |
| 5 | 85.001～95.001 | EX（执行阶段） | 选择两个寄存器输入，执行加法，输出 3 |
| 6 | 95.001 上升沿 | EX/MEM（执行/访存流水寄存器） | 保存结果 3、目标编号 6和后续控制 |
| 7 | 95.001～105.001 | MEM（访存阶段） | 不发起数据存储器访问，把结果向后传 |
| 8 | 105.001 上升沿 | MEM/WB（访存/写回流水寄存器） | 结果 3与目标编号 6进入写回级 |
| 9 | 105.001～115.001 | WB（写回阶段） | 写回数据、目标编号、写使能都已有效 |
| 10 | 115.001 上升沿 | Register File（寄存器堆） | 6 号寄存器真正保存 3，写入次数变为 1 |

本例在时钟下降沿解除复位，因此第一个取指区间只有半个时钟周期；后续各级区间都是 10 ns（纳秒）。这属于本次测试启动方式。

**下面按信号因果关系一步步讲解。同一个阶段内的拆字段、读寄存器、译码等组合逻辑可以并行工作；文字顺序不表示它们各自额外占一个时钟周期。**

## 5. 第 0 步：复位与准备，让旧状态不影响本条指令

经过的图中硬件：PC（程序计数器）、Register File（寄存器堆）、四组流水寄存器、CPU CONTROL（中央处理器控制器）。

| 信号或数据 | 发出者 → 接收者 | 本次作用 |
|---|---|---|
| clk（时钟信号），代码 `clk`（时钟输入） | 测试平台时钟源 → 数据通路中的流水寄存器和寄存器堆；也接入控制器公共端口 | 周期 10 ns（纳秒），上升沿推进流水状态 |
| rst_n（低有效复位），代码 `rst_n`（复位输入） | 测试平台复位源 → 控制器和数据通路 | 0 表示复位，1 表示正常运行 |
| 复位地址 0 | 数据通路复位参数 → PC（程序计数器） | 下一次从地址 0 取指 |
| 寄存器初值 1、2 | 测试平台 → Register File（寄存器堆）的 1、2 号位置 | 作为本条加法指令输入 |
| 机器码 `0x00208333` | 测试平台 → Instruction Memory（指令存储器）的地址 0 | 作为本次要执行的指令 |

**为什么这样做？** 如果流水寄存器里还留有上一条指令的写使能或有效位，就可能意外写寄存器、写存储器。复位清除流水状态，测试平台随后设置输入，才能单独观察一条指令。测试平台直接设置寄存器是实验准备，不是说真实处理器每条指令都会先复位。

控制器自身是组合逻辑，`clk`（时钟输入）不在控制器内部保存状态；数据通路才负责跨周期保存数据。控制器在复位时立即输出安全控制，数据通路在上升沿清状态。

## 6. 第 1 步：程序计数器给出地址，指令存储器给出机器码

所在阶段：IF（取指阶段）。

硬件顺序：PC（程序计数器）→ Instruction Memory（指令存储器）→ IF/ID（取指/译码流水寄存器）的输入。

| 信号或数据 | 位宽 | 发出者 → 接收者 | 本次值 |
|---|---:|---|---|
| 取指地址，代码 `pc_f`（取指级程序计数器） | 32 | PC（程序计数器）→ Instruction Memory（指令存储器）的地址端 | 0 |
| 指令读出数据 | 32 | Instruction Memory（指令存储器）→ IF/ID（取指/译码流水寄存器）的 IR（指令寄存器）输入 | `0x00208333` |
| 当前指令地址 | 32 | PC（程序计数器）→ IF/ID（取指/译码流水寄存器）的地址保存输入 | 0 |

模型中地址 0 对应指令数组第 0 项。模型没有单独命名“指令存储器读出总线”，它在上升沿把查表结果保存到 `instr_d`（译码级机器码）中；上表的读出数据是图中的逻辑连接含义。

**为什么这样做？** 程序计数器保存的是“到哪里读”，不是指令内容。必须先用地址读指令存储器，才知道本次应该做什么。图采用 Harvard（哈佛式指令与数据存储分离）结构，取指不需要经过图中的 Data SRAM（数据静态存储器）。

## 7. 第 2 步：顺序地址加四，选择下一次取指地址

与上一小步处于同一个取指阶段，可以并行发生。

硬件顺序：PC（程序计数器）→ PC + 4（程序计数器加四加法器）→ PC MUX（程序计数器多路选择器）→ PC（程序计数器）下一状态输入。

| 信号或数据 | 位宽 | 发出者 → 接收者 | 本次值和作用 |
|---|---:|---|---|
| 当前地址 | 32 | PC（程序计数器）→ PC + 4（程序计数器加四加法器） | 0 |
| 顺序下一地址 | 32 | PC + 4（程序计数器加四加法器）→ PC MUX（程序计数器多路选择器） | 4 |
| PCSrc（程序计数器来源选择），代码 `pc_sel`（程序计数器选择） | 2 | Control Output / Pipeline Gating Matrix（控制输出与流水门控矩阵）→ PC MUX（程序计数器多路选择器） | `00`，选择顺序地址 |
| PCWrite（程序计数器写使能），代码 `pc_en`（程序计数器更新允许） | 1 | Control Output / Pipeline Gating Matrix（控制输出与流水门控矩阵）→ PC（程序计数器） | 1，允许上升沿更新 |

在 75.001 ns（纳秒）上升沿，程序计数器变为 4；同一上升沿取指/译码寄存器保存的是上升沿之前地址 0 的指令。本条指令不会因此变成地址 4 的指令。

**为什么加四？** 本项目每条指令固定为 32 位，也就是 4 字节，地址按字节计数。所以顺序执行从地址 0 到地址 4，再到地址 8。图中的这个加法器用于地址推进，与后面执行“1 + 2”的算术逻辑单元用途不同。

## 8. 第 3 步：取指/译码流水寄存器保存指令和它的地址

硬件：IF/ID（取指/译码流水寄存器），其中包括 IR（指令寄存器）。发生在 75.001 ns（纳秒）上升沿。

| 信号或数据 | 位宽 | 发出者 → 接收者 | 本次值和结果 |
|---|---:|---|---|
| IFIDWrite（取指/译码写允许），代码 `if_id_en`（取指/译码使能） | 1 | 流水门控矩阵 → IF/ID（取指/译码流水寄存器） | 1，允许接收新指令 |
| FlushIFID（取指/译码冲刷），代码 `if_id_flush`（取指/译码清空请求） | 1 | 流水门控矩阵 → IF/ID（取指/译码流水寄存器） | 0，不清空 |
| `instr_d`（译码级机器码） | 32 | IF/ID（取指/译码流水寄存器）→ 主译码器、算术逻辑译码器、寄存器编号提取线路 | `0x00208333` |
| PC_IFID（取指/译码保存的指令地址），代码 `pc_d`（译码级指令地址） | 32 | IF/ID（取指/译码流水寄存器）→ 后续地址与流水路径 | 0 |
| PC4_IFID（取指/译码保存的顺序下一地址） | 32 | 图中的取指路径 → 后续流水路径 | 图上为 4；模型未单独保存此字段，后续根据本条指令地址加四表示该功能 |
| valid（有效标志），代码 `valid_d`（译码级有效位） | 1 | IF/ID（取指/译码流水寄存器）→ 控制器及后续流水级 | 1，说明这里是一条真实有效指令 |

**为什么必须暂存？** 取指端接下来会去读地址 4，但译码端仍需要处理地址 0 的这条机器码。暂存站把本条指令留下，避免后面取到的新指令覆盖当前译码内容。有效位则告诉后级“这里是有效工作，还是空位”。

## 9. 第 4 步：拆出操作码和寄存器编号，送给不同硬件

所在阶段：ID（译码阶段）。

硬件连接：IR（指令寄存器）分别连接主译码器、算术逻辑译码器、寄存器堆和冒险检测单元。

| 信号或字段 | 位宽 | 发出者 → 接收者 | 本次值 |
|---|---:|---|---|
| opcode（操作码） | 7 | IR（指令寄存器）的 [6:0] → Main Decoder（主译码器）、ALU Decoder（算术逻辑译码器） | `0110011` |
| funct3（三位功能字段） | 3 | IR（指令寄存器）的 [14:12] → ALU Decoder（算术逻辑译码器） | `000` |
| funct7（七位功能字段） | 7 | IR（指令寄存器）的 [31:25] → ALU Decoder（算术逻辑译码器） | `0000000` |
| `rs1_d`（译码级第一源编号） | 5 | 指令位 [19:15] 的提取线路 → 控制器冒险单元；同一编号也选寄存器堆第一读端 | 1 |
| `rs2_d`（译码级第二源编号） | 5 | 指令位 [24:20] 的提取线路 → 控制器冒险单元；同一编号也选寄存器堆第二读端 | 2 |
| rd（目标寄存器编号） | 5 | 指令位 [11:7] → ID/EX（译码/执行流水寄存器）的目标编号输入 | 6 |

图上算术逻辑译码器简写为读取 `funct7[5]`（七位功能字段的第 5 位）；当前代码读取完整七位字段，以同时检查编码是否合法。当前主译码器端口接收完整机器码，再在内部提取操作码，功能上对应图中主译码连接。

**为什么源和目标各要五位？** 图中的寄存器堆有 32 个位置，五位可以表示 0～31。编号线只说明选哪个位置，随后读出的数据线才有 32 位。

## 10. 第 5 步：主译码器发出“读两个寄存器、允许写回、不访问存储器”

硬件：Main Decoder（主译码器）→ Control Output / Pipeline Gating Matrix（控制输出与流水门控矩阵）→ 数据通路。

当前代码将控制字汇集到组合顶层再输出，下面列的是译码阶段的实际输出。标记“进入流水”的字段先由 ID/EX（译码/执行流水寄存器）接收，后续按用途继续往后传。

| 图中含义与代码信号 | 位宽 | 发出者 → 接收者 | 本次值 | 为什么这样设置 |
|---|---:|---|---|---|
| RegWrite（寄存器写允许），`regwrite_d`（译码级写回允许） | 1 | 主译码器经控制器顶层 → 进入流水，最终到寄存器堆写使能 | 1 | 加法结果要保存到目标寄存器 |

| MemWrite（存储器写允许），`memwrite_d`（译码级存储允许） | 1 | 主译码器经控制器顶层 → 进入流水，最终到加载存储单元 | 0 | 结果写进寄存器，不写入数据存储器 |
| ALUSrcA（算术逻辑第一输入来源），`alu_src_a_sel`（第一操作数选择） | 2 | 主译码器经控制器顶层 → 进入流水，到执行级输入选择逻辑 | `00` | 第一输入取第一源寄存器数值 |
| ALUSrcB（算术逻辑第二输入来源），`alu_src_b_sel`（第二操作数选择） | 2 | 主译码器经控制器顶层 → 进入流水，到执行级输入选择逻辑 | `00` | 第二输入也取寄存器数值 |
| ResultSrc（写回结果来源），`wb_sel_d`（译码级写回来源选择） | 2 | 主译码器经控制器顶层 → 进入流水，到写回数据选择路径 | `00` | 最后要写回算术逻辑结果 |
| `uses_rs1_d`（使用第一源标志） | 1 | 主译码器经控制器顶层 → 冒险单元，并进入流水 | 1 | 这条指令真的要用第一源寄存器 |
| `uses_rs2_d`（使用第二源标志） | 1 | 主译码器经控制器顶层 → 冒险单元，并进入流水 | 1 | 这条指令真的要用第二源寄存器 |
| `imm_type_d`（立即数类型） | 3 | 主译码器经控制器顶层 → Immediate Gen（立即数生成器）；类型也进入流水 | `000` | 这条加法指令没有立即数 |
| `branch_type_d`（译码级分支类型） | 3 | 主译码器经控制器顶层 → 进入流水，执行级送分支控制器 | `000` | 本条指令不是条件分支 |
| `jump_d`（译码级跳转类型） | 2 | 主译码器经控制器顶层 → 进入流水，执行级送分支控制器 | `00` | 本条指令不是跳转 |
| `load_type_d`（加载数据类型） | 3 | 主译码器经控制器顶层 → 进入流水，到加载存储单元 | `000`，本例无操作意义 | 加载允许为 0，不执行加载 |

**为什么写允许现在是 1，却不能现在就写寄存器？** 译码阶段还没有得到运算结果。“允许写”是一份随指令携带的任务说明，等这条指令走到写回级、结果和目标编号都准备好，才执行真正的写操作。

这里编码 `00` 的含义取决于是哪根选择线：第一输入的 `00` 表示第一寄存器源，写回来源的 `00` 表示算术逻辑结果。不能把所有 `00` 都解释成“关闭”。

## 11. 第 6 步：算术逻辑译码器确认这次运算是加法

硬件：ALU Decoder（算术逻辑译码器）→ 控制器顶层 → ID/EX（译码/执行流水寄存器）。

| 信号或数据 | 位宽 | 发出者 → 接收者 | 本次值和作用 |

| ALUCtrl（算术逻辑运算控制），代码 `alu_ctrl`（译码级运算选择） | 4 | 算术逻辑译码器经顶层安全限定 → ID/EX（译码/执行流水寄存器） | `0000`，当前项目编码代表加法 |

**为什么分成两个译码器？** 主译码器先判断“寄存器运算这一类需要读谁、写谁、访问什么”；算术逻辑译码器再判断“这一类中到底执行加法、减法还是其他运算”。相同的操作码可以包含多种运算，只看操作码不够。

合法性检查还能避免把不支持的编码当成普通加法。控制器只有在复位已解除、译码有效、两个合法性检查均通过时，才输出本条指令的有效控制字。

| WriteData（存储写数据） | 执行级存储数据路径 → 执行/访存寄存器 | `store_m`（访存级存储数据）＝2，但本例写存储器允许为 0，不会使用 |
| valid（有效标志） | 执行级 → 执行/访存寄存器 | `valid_m`（访存级有效位）＝1 |

图里该寄存器还携带 WB ctrl（写回控制信息）。本模型把完整控制字继续保存为 `ctrl_m`（访存级控制字），其中包含本条指令的写允许和结果选择。

**为什么结果必须与编号一起保存？** 如果只传 3、不传目标编号，后面不知道该写给谁；如果只传编号、不传写允许，后面又不知道该不该写。三者必须一直属于同一条指令。

## 19. 第 14 步：经过访存级，但加载存储单元不发起访问

所在阶段：MEM（访存阶段）。

图中硬件：EX/MEM（执行/访存流水寄存器）的输出送到 LSU + Decode（加载存储单元与地址译码），同时结果路径继续送往 MEM/WB（访存/写回流水寄存器）。

| 信号或数据 | 发出者 → 接收者 | 本次意义 |
|---|---|---|
| 保存的结果 3 | 执行/访存寄存器 → 访存级结果路径；图中也可接加载存储单元地址输入 | 对本条指令是加法结果，不是有效数据访问请求 |
| `valid_m`（访存级有效位） | 执行/访存寄存器 → 访存级提交门控 | 1 |
| `memread_m`（访存级加载标志） | 执行/访存寄存器 → 加载存储单元 | 0，不发起加载 |
| `memwrite_m`（访存级存储标志） | 执行/访存寄存器 → 加载存储单元 | 0，不发起存储 |
| 最终存储器写允许 | 有效位与存储标志的门控 → 数据存储器写端 | 1 与 0 相与为 0，所以不能写 |
| 写回来源 `00` | 执行/访存控制字 → 后级结果选择路径 | 保留结果 3，不选择数据存储器读出值 |

**为什么普通加法也经过访存级？** 图采用统一五级流水线，运算指令和访存指令都按固定阶段推进。这个阶段只是“具备访存能力”，不表示每条指令必须访问存储器。加法在这一阶段继续传递计算结果，可以保持流水结构一致。

**结果是 3，为什么没有触发地址未对齐错误？** 因为本条不访问数据存储器。只有有效加载或存储请求时，模型才检查访问地址。不能把线上出现一个数字等同于存储器真的接受了一次请求。

原始通用波形中有 load data（加载数据）线路变化，这是模型对数组的组合计算，不代表有效加载事务。该线路既没有有效加载请求，也没有被本条指令选为写回来源；报告附带的中文波形省去了这条容易误读的闲置线路。

## 20. 第 15 步：访存/写回流水寄存器保存可写回的结果

硬件：MEM/WB（访存/写回流水寄存器）。发生在 105.001 ns（纳秒）上升沿。

| 信号或数据 | 发出者 → 接收者 | 本次值 |
|---|---|---|
| ALUResult（算术逻辑结果） | 访存级结果路径 → 访存/写回寄存器 | 3 |
| rd（目标寄存器编号） | 执行/访存寄存器 → 访存/写回寄存器 | `rd_w`（写回级目标编号）＝6 |
| RegWrite（寄存器写允许） | 访存级控制字 → 访存/写回寄存器 | `regwrite_w`（写回级写允许）＝1 |
| ResultSrc（写回结果来源） | 访存级控制字 → 访存/写回寄存器 | `00`，选算术逻辑结果 |
| valid（有效标志） | 访存级 → 访存/写回寄存器 | `valid_w`（写回级有效位）＝1 |

**为什么这里还要一组寄存器？** 访存级接下来会处理下一条指令，写回级需要稳定保持本条的结果与目标。暂存以后，本条指令的写回端不会因为访存级变化而马上被覆盖。

图中把算术逻辑结果、存储器读数据、顺序链接地址分别画进访存/写回寄存器，再由后面的选择器选择。模型对这部分做了功能合并：在进入写回级时已按来源选择，将最终数值保存到 `wb_value`（最终写回数值）。所以模型功能对应图，内部没有逐字逐块复制图上的三个暂存字段和独立选择器模块。

## 21. 第 16 步：写回多路选择器选加法结果，寄存器堆收到三样东西

所在阶段：WB（写回阶段）。

图上的硬件顺序：MEM/WB（访存/写回流水寄存器）→ WB MUX（写回多路选择器）→ Register File（寄存器堆）。

| 信号或数据 | 位宽 | 发出者 → 接收者 | 本次值及作用 |
|---|---:|---|---|
| ResultSrc（写回结果来源） | 2 | 本条指令保存的写回控制 → WB MUX（写回多路选择器） | `00`，选择算术逻辑结果 |
| WD3（第三端口写数据），模型 `wb_value`（最终写回数值） | 32 | 写回选择后的数据路径 → 寄存器堆写数据端 | 3 |
| rd（目标寄存器编号），`rd_w`（写回级目标编号） | 5 | 访存/写回寄存器 → 寄存器堆写地址端 | 6 |
| RegWrite（寄存器写允许），`regwrite_w`（写回级写允许） | 1 | 访存/写回寄存器 → 寄存器堆写入门控 | 1 |
| `valid_w`（写回级有效位） | 1 | 访存/写回寄存器 → 寄存器堆写入门控 | 1 |

图上写回选择器的候选是 ALU/MEM/PC4（算术逻辑结果/数据存储器结果/程序计数器加四链接值）。本例选第一路。模型中最终选择在上一小步已经合并完成，写回期间稳定提供数值 3。

真正允许写的条件是：`valid_w`（写回级有效位）为 1，`regwrite_w`（写回级写允许）为 1，并且 `rd_w`（写回级目标编号）不为 0。本例目标为 6，三个条件都满足。

**为什么不能只有“写允许”这一个信号？** 无效流水空位不能产生副作用，所以还要检查有效位；0 号寄存器必须始终为 0，所以还要屏蔽目标编号 0。最后寄存器堆必须同时知道“写入哪个位置”“写入什么数”“这次是否真的写”。

## 22. 第 17 步：写回上升沿把 3真正写入 6号寄存器

硬件：Register File（寄存器堆）。发生在 115.001 ns（纳秒）上升沿。

| 上升沿之前准备好的内容 | 接收者 | 上升沿之后的结果 |
|---|---|---|
| 写数据 3 | 6 号寄存器的数据输入 | 6 号寄存器从 0 变为 3 |
| 写地址编号 6 | 寄存器堆写地址译码 | 选中 6 号位置 |
| 有效写使能 | 寄存器堆写控制 | 完成一次写入 |

模型的 `commit_count`（寄存器提交次数）从 0 变成 1，`store_count`（存储器写入次数）仍为 0。随后直接读取仿真寄存器得到：1 号寄存器＝1，2 号寄存器＝2，6 号寄存器＝3。

**为什么不是 105.001 上升沿就已经写入？** 在那一沿，本条指令才从访存级进入写回级。寄存器堆的同步写逻辑在这一沿读取的是沿前的旧写回状态；本条的新写回数据随后才稳定。到 115.001 上升沿，寄存器堆才接收本条准备好的写回信息。报告把“写回数据已经有效”和“寄存器已经完成写入”分开，避免把两件事混淆。

本条仍然只经过五个流水阶段；最后的上升沿是写回阶段的提交边界，不是又增加了第六种运算阶段。

## 25. 报告时最容易被问到的几个问题

**控制器有没有亲自做 1 + 2？** 没有。控制器发出加法控制、输入来源、写回允许等信号，数据通路中的 ALU（算术逻辑单元）执行运算。

**为什么没有暂停？** 本次两个输入已准备好，前方没有有效加载依赖或其他未就绪结果。这是独立指令案例，不是所有加法序列的通用结论。

**为什么写回允许在译码阶段就出现？** 它先作为任务说明生成，随后跟随本条指令跨级保存；直到写回阶段才产生实际寄存器写入。

**为什么结果要经过两个暂存站才写回？** 图的统一五级结构要求指令按阶段推进，结果、目标编号、控制信息保持配对，后面才能正确提交。

**图中的存储器有没有读取 3号地址？** 本条没有有效存储器访问。3是加法结果，访问允许为 0。模型中闲置读计算的变化不算有效加载事务。

**图上有卷积神经网络加速器，为什么本例不经过它？** 普通加法在处理器的算术逻辑单元完成。加速器由普通访存指令配置其寄存器后启动，不会自动接管每条处理器指令。

**能不能说整个真实处理器已通过？** 本次可以说“真实控制器与验证模型连接，单条加法的五级阶段、自身结果及一次写回已验证”；真实生产数据通路与加速器联调仍未运行。

## 26. 可以直接用于口头汇报的讲稿

> 我用一条 ADD（加法指令）演示图中的五级流水线。指令是把 1号和 2号寄存器相加，结果写到 6号寄存器。本次两项输入设置为 1和 2。
>
> 第一个阶段是 IF（取指阶段）。PC（程序计数器）给出地址 0，指令存储器返回机器码，同时地址加四线路准备下一个顺序地址。
>
> 第二个阶段是 ID（译码阶段）。指令被拆成操作码、功能字段和寄存器编号。主译码器决定读取两个寄存器、允许最终写回、关闭数据存储器读写；ALU Decoder（算术逻辑译码器）确认运算是加法。寄存器堆读出 1和 2，数据与控制一起进入阶段间暂存站。
>
> 第三个阶段是 EX（执行阶段）。冒险单元确认本例不需要前递或暂停，两个输入选择器选择原寄存器数值。ALU（算术逻辑单元）完成 1加 2，得到 3。由于本条不是分支，程序继续顺序取指。
>
> 第四个阶段是 MEM（访存阶段）。本条加法不需要加载或存储，所以结果 3只继续向后传递，存储器读写使能均为 0。
>
> 第五个阶段是 WB（写回阶段）。结果选择路径选中加法结果，寄存器堆收到目标编号 6、数据 3和有效写允许，在写回上升沿把 3存入 6号寄存器。
>
> 本次单条指令的阶段测试 23项检查全部通过，直接读取最终寄存器也确认结果为 3，寄存器只写一次，数据存储器没有写入。验证使用真实控制器与数据通路模型，真实系统联调还需要其他负责人的生产模块。
