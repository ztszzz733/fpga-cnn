# CNN 中间缓冲区复用接口

本版为隔离入口 `quant_network_buffered`。算子仍为两个NEureka、一个后处理/Add、一个DW7、一个补边，存储接口仍23客户端。新增 `network_dispatch_buffered` 和 `network_buffer_leases`，不改变生产CPU、输入桥或DATASRAM。

## 分配与释放

采用编排器预先规划地址、硬件运行时预约的方式。8个物理槽各有占用标记、当前结果代号和未结束消费者的完成掩码。代号用本批次的生产任务编号表示，因此即使地址相同，也能区分不同图片、不同层的结果。

任务发射条件为：前驱完成、对应算子空闲、输出槽空闲、所有声明的输入槽仍保存指定代号的数据。缺少任何条件就继续扫描其它任务。预约和任务分配发生在同一上升沿。当前不支持原地覆盖输入槽，也不支持运行时从任意空闲地址段寻找内存。

生产任务自身和所有声明的消费者都完成后才发出buffer_release；下一上升沿清掉占用标记。实际算子done必须代表最后存储响应已经结束。NEureka各输出通道组可共享一个原始INT32槽：第一组预约，后续组按代号验证所有权，最终后处理消费完后才释放。

残差旁路的消费者既包含主分支卷积，也包含较晚的Add。主分支先完成不会释放旁路；Add仍能读取原结果。单元测试还检查两个消费者以不同顺序结束，不能只认某个编号较大的消费者或第一个完成者。

## 新增配置和观察端口

新增配置字段与原program_command在同一个 `program_valid && program_ready` 上升沿接收。旧1024命令、两个前驱、start/clear语义保持。下面是内部配置接口，CPU侧的32位寄存器/DMA适配还需对接。

| 端口 | 位宽 | 用途 |
|---|---:|---|
| program_allocate_valid | 1 | 本任务是否创建新的缓冲区代号 |
| program_allocate_slot | 3 | 预约的物理槽，0～7 |
| program_hold_mask | 1024 | 所有必须完成才能释放的任务位图；硬件自动加入生产任务自己 |
| program_use_valid | 3 | 最多三个需要检查代号的槽 |
| program_use_slots | 9 | 每3位一个槽编号 |
| program_use_owners | 30 | 每10位一个期望的生产任务号 |
| buffer_live | 8 | 每槽当前是否占用 |
| buffer_owners | 80 | 每槽10位当前生产任务号；仅live时有效 |
| buffer_allocate | 8 | 已预约槽的单拍通知 |
| buffer_release | 8 | 所有消费者完成的释放通知，在下一上升沿清空live |
| wait_buffer | 1 | 扫描到依赖已满足、但缓冲区条件不满足的未发射任务 |

最多三个槽检查满足当前算子需要：卷积输入与已有输出、后处理输入、Add两个输入。权重和量化参数仍为只读地址，不由中间缓冲管理器分配。此管理器不是总线地址防护单元；地址和依赖元数据必须由编排器正确生成。错误的持有关系可能导致过早释放或一直等待，当前没有通用死锁检测。

## 内存布局与防止资源死锁

本次工作池有两组，每组四槽，单槽大小依次为10,304、4,160、4,160、1,088字节，两组共39,424字节（38.5KiB）。这些大小包含各自64字节尾部保护区：NEureka的288位读取可能访问逻辑张量末端之外，不能让最后一笔读取落到未映射地址或其它对象。

一组运行一帧。下一帧进入同组前，要等上一帧最后Add完成，避免多个帧各占一部分槽、互相等待剩余槽。两组独立，因此仍可交错运行。单帧内部会复用原始卷积槽：前层后处理结束后，后层卷积可以写到同一地址。残差旁路占用独立槽直到Add完成。

39,424字节只是本例中间工作池，不包括输入图片、模型权重、量化参数、任务表和最终结果持久保存。测试保留预加载只读区域，物理地址从0x400000开始放工作池，不能把测试地址空间直接作为生产SRAM容量要求。本版命令的1024位生命周期掩码表也有明显控制存储开销；尚未综合，后续应压缩为消费者列表或引用计数。

最终结果在Add完成时由测试台检查并复制出来，然后对应工作槽可释放。真实系统必须增加输出消费握手：输出接收方尚未读完前，最终槽不能释放。当前没有把最终结果交给生产CPU/UART，不能直接照搬“最后算子done即回收”用于异步外部读取。

## 验证工作负载

6帧输入，交替使用两张不同真实人脸的ROI数据。每帧先运行前三层真实权重卷积与后处理，再增加一次中间层结果与末层结果的Add，用于检查残差生命周期。该Add是压力测试图，不是宣称MobileFaceNet前三层原本有这条残差。共60命令，所有计算由真实RTL完成。

各任务完成时立即与独立整数参考比较；不能在全部结束后只检查同一地址最后留下的内容。每次释放都检查声明消费者已完成、没有该槽的未完成存储请求，然后测试台立即用0xD7覆写整槽。这是故意破坏已释放数据的检查，不是软件代算。六帧最终输出在释放前分别保存，用于不同压力场景之间的哈希比较。

主回归包含正常双核、仅实例1、实例0限速加存储反压、中途clear后取消事务并复位/重装。单独协议测试覆盖占用时等待、代号不匹配拒绝、消费者乱序完成、生产者自身未完成不释放、重复使用同一槽以及cancel清空。

数据生成 `scripts/gen_network_buffered.py build/network_buffered_data`；WSL主回归 `scripts/run_network_buffered.py --data build/network_buffered_data`，缓存匹配可加`--reuse`；协议单测 `scripts/run_buffer_leases_test.py`。运行结果以result.json为准，汇总见[交付说明](../deliverables/network_buffered/README.md)。
