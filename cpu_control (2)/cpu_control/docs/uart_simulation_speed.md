# UART 仿真加载提速

原波形中长时间等待来自资料串行传输：需要加载 8192 字节，UART 每字节包含起始位、8 个数据位和停止位，共 10 位。原配置每 64 字节数据就执行一次请求/回复，每轮另有 16 字节请求和 16 字节回复头/CRC，总共 128 轮。

本次只调整完整 SoC 仿真的 UART 参数及外部设备模型，系统时钟仍为 100 MHz。CPU 程序、19 个任务、数据规模及硬件架构不变。

| 项目 | 原仿真参数 | 新默认仿真参数 |
|---|---:|---:|
| UART 波特率（收发一致） | 12.5 Mbps | 25 Mbps |
| 每位持续时间 | 80 ns | 40 ns |
| 每位系统时钟数 | 8 | 4 |
| 每包有效资料 | 64 字节 | 256 字节 |
| 请求/回复轮数 | 128 | 32 |
| 加载耗时 | 997,505 周期 / 9.97505 ms | 378,145 周期 / 3.78145 ms |
| 上电到 CPU 验证完成 | 1,019,610 周期 / 10.19610 ms | 400,248 周期 / 4.00248 ms |
| CNN 队列执行 | 3,613 周期 | 3,613 周期 |

加载阶段快约 **2.64 倍**，完整演示快约 **2.55 倍**。这些时间是仿真中的设计时间，不是运行仿真程序的电脑耗时。

当前 UART 接收器要求分频系数至少为 4，因此 100 MHz 系统时钟下使用 25 Mbps。桥已有每包最多 256 字节的参数支持。本次未删掉起止位、握手或 CRC，也没有通过测试平台直接向 SRAM 填数据；资料仍经过真实 UART 接收和图像桥写入内存。25 Mbps 验证针对本项目的理想时序仿真，未把结果当作物理串口设备的速率验收。

测试平台原先固定校验 64 字节请求，现按配置校验地址、长度和最后一包；256 字节回复的长度高字节正确发送为 1。命令行入口：

```powershell
# 默认高速参数，包含状态故障/恢复用例并生成完整顶层波形
.\scripts\run_overlap_sim.ps1 -Cases overlap,observer_fault,restart -TopWaves

# 同一次运行比较原参数和新参数
.\scripts\run_overlap_sim.ps1 -Cases uart_baseline,overlap -TopWaves

# 恢复旧的仿真参数
.\scripts\run_overlap_sim.ps1 -Cases overlap -UartBaud 12500000 -ChunkBytes 64
```

本次基准与高速对照运行：`build/runs/20261009_222856_065280_overlap_integration`。数据逐字检查、CPU 校验和、包 CRC、整批 CRC、19 个任务、桥超时故障及软复位恢复均通过。第二组随机数据另用 255 字节分包检查不足整包的末尾：运行 `20261009_223140_571773_overlap_integration`，共 33 包，末包 32 字节，同样通过全部数据检查。
