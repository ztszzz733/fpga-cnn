# 第二轮卷积优化：预取、写回队列与3×3流水

本轮维持K3×2、K1×4、DW7/Post/Add/Pad各1。每套K1仍有四条空间乘加通路，没有增加乘法器数量；改变的是计算与访存的组织。最终数据和源码验证见[验证报告](../deliverables/conv_overlap/README.md)。

## 1×1的执行方式

新模块`rtl/cnn_self/self_pw4_overlap_engine.sv`延续上一版的四位置输入缓存、32位对齐读取及精确字节尾部处理，增加两个机制：

1. **两份权重缓存轮换。** 当前输出通道使用A缓存计算时，B缓存加载下一个输出通道的权重。B全部读回后才允许计算；A计算结束后才允许覆盖。缓存标签和读计数由硬件管理，软件不需要逐次切换。
2. **八字写回队列。** 四路累加结果连同各自的绝对HWC地址逐项入队。下一通道可以开始计算，存储接口同时把队列中的旧结果写入SRAM。队列满时暂停入队，绝不丢结果；最后一笔写响应到达、队列和未完成请求全部排空后，才产生`done`。

```text
                       ┌→ 权重缓存A ─┐
SRAM读接口 → 权重预取 ──┤             ├→ 四路乘加 → 写回队列 → SRAM写接口
                       └→ 权重缓存B ─┘       ↑
                                    四个位置的输入缓存
```

SRAM读写共用原来的单请求接口，每套引擎仍最多一笔未完成事务。这里的重叠是“本地乘加与外部搬运同时发生”，不意味着同一个接口能同拍读写两笔事务。当前输入块仍要加载完成才能计算；下一空间块的输入预取没有实现。

仲裁优先当前块输入，之后在权重预取和结果写回间选择；队列达到四字时优先排出结果，否则按完成事务轮换。请求可以直接提交，避免人为插入一拍；出现反压时锁定请求，直到接受。接受后的类型、字节使能、地址保留至响应，支持零延迟同拍响应。写队列条目在写响应后才回收，不能在请求接受时就释放。

对于不足四个位置的边界块，只生成实际存在的位置；不足四字节或未对齐的输入/权重逐字节读取，不向张量尾部之外多读。宽读的合法性由通道字序号比较确定，两个加载器分别生成计数，避免穿过共享仲裁产生长控制路径。

## 3×3与DW3的执行方式

新模块`rtl/cnn_self/self_conv_pipe_engine.sv`保留旧版输入块/halo复用和权重缓存，使用同步读取、寄存乘法、INT32累加三级流水。流水填满后每拍退休一个有效MAC；每个输出位置的最后一个乘积携带结束标记，排空后才保存结果并切换下一个位置。

普通3×3的一个输出位置有`9×输入通道数`个MAC，DW3有9个MAC。计算阶段可以连续进行，但加载和写回仍有时间开销，不能宣称整层必然两倍加速。此模块保留普通/DW的1×1支持，方便保持旧接口的合法配置集合。

## 接口和接入

数据类型、布局、描述符及外部端口不变：UINT8输入、INT8权重、INT32原始输出；后处理单独完成偏置/零点校正、量化及激活。本轮没有做卷积与后处理融合。

`self_fixed_network_top`、`self_stream_top`和仿真顶层新增生成参数`CONV_OVERLAP`：

| 配置 | K1 | K3 |
|---|---|---|
| `CONV_OVERLAP=0, PW4=0` | 原始串行引擎 | 原始引擎 |
| `CONV_OVERLAP=0, PW4=1` | 上一版四位置流水 | 原始引擎 |
| `CONV_OVERLAP=1` | 四位置＋双权重缓存＋写回队列 | 新乘加流水 |

两个参数默认均为0，便于保留历史入口。六图runner使用`--conv-overlap`启用本轮组合，并自动记录`PW4=1`；新缓存为`.self_six_overlap_build`，旧缓存和证据保留。参数在生成硬件时选择，不是运行时的CPU模式寄存器。

`mac_fire/operator_work`只在有效累加时拉高。新K1每拍MAC计数增加实际活动位置数，K3每拍增加1；`busy`仍包含访存等待。加载和写回计数的字节单位不变。新K1状态编码为：IDLE=0、SETUP=1、CHECK=2、TILE_BEGIN=3、IREQ=4、WREQ=5、MAC_RUN=6、OREQ=7、OWAIT=8、DRAIN=9、FINISH=10、FAIL=11；其中OREQ表示入队，真正的SRAM写回可能发生在其他计算状态。

`clear`清除流水有效位、缓存就绪标记、队列指针/计数及请求状态，不清空整块RAM；系统必须同时取消旧存储请求和迟到响应。这与旧接口约定相同。

## 验证与复现

WSL工程目录执行：

```sh
python3 scripts/run_conv_overlap_unit_wsl.py
python3 scripts/run_conv_overlap_unit_wsl.py --k3
python3 scripts/run_self_six_wsl.py --data build/self_six_small --conv-overlap
python3 scripts/run_self_six_wsl.py --data build/self_six_small --pw4
```

前两项使用独立标量参考和随机数值，验证读写范围、尾部保护、结果、MAC次数、反压保持、同拍响应、clear重启和非法描述符。新增队列满和长响应延迟用例，记录MAC与读/写响应同拍次数，用于证明实际重叠。K3测试涵盖普通与DW3、两种步长、边界块及512通道。

后两项使用同一六图8×8 ROI首三层数据和真实bai SRAM，运行并行、逐帧串行、预加载、CPU访存竞争/慢结果读取四场景。每项48任务、614400 MAC、107784检查字节，最终6144字节输出；本数据不包含Add或DW7任务。默认RTL和所有算子均真实执行，不向SRAM注入参考中间结果。

Windows Python可用`scripts/synth_self_cnn.py --top self_pw4_overlap_engine --max-kernel 1`或`--top self_conv_pipe_engine --max-kernel 3`完成单模块OOC综合。资源与时序结论以报告中的最终run为准。

本轮未运行完整六图MobileFaceNet、整机布局布线、CPU/UART或层内条带输入；32MiB测试SRAM不代表512KiB板上容量已经适配，也不据小图结果推算全网实际时间。
