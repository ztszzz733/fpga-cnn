# CNN 当前能力与模块对接说明 v0.1

日期：2026-10-22。面向 CNN、CPU、DATASRAM、IMAGE_BRIDGE 负责人。

本文说明当前已经验证的 CNN 能力、首次联调方法与双方边界。**“现有”表示代码中已有并经过所列测试；“计划/建议”表示待实现或待双方确认，不能直接当作现有端口。** 本文不修改 RTL，不重新运行仿真。

## 1. 先明确：当前能输入和输出什么

**CNN 已能从 SRAM 读取数据，执行真实卷积、激活等运算，再把特征结果写回 SRAM。** 后层读取前层硬件实际计算出的结果，没有在中间结果区预填参考答案。

目前保留两种已验证的实验入口，尚未合成一个从图片开始的完整网络入口：

| 项目 | 图片前三层入口 | 最新残差入口 |
|---|---|---|
| 用途 | 验证图片小区域→局部特征 | 验证卷积、残差汇合、多消费者释放 |
| 输入内容 | 真实人脸 RGB 小区域经软件归一化、量化和边界填充后的字节 | 软件执行网络前缀后得到的量化中间特征 |
| 本例输入形状 | 每图13×13×3，共507字节，含填充 | 每图6×6×128，共4,608字节 |
| 计算 | 3×3普通卷积步长2＋ReLU6 → 3×3逐通道卷积＋ReLU → 1×1卷积＋ReLU | Conv_5 → Conv_6＋ReLU6 → Conv_7逐通道＋ReLU6 → Conv_8 → 残差Add |
| 本例最终输出 | 每图4×4×64，共1,024字节 | 每图4×4×64，共1,024字节 |
| 硬件入口 | `quant_triple_scheduler` | `quant_residual_scheduler` |
| 输出位置 | 描述符指定的SRAM结果区 | 描述符指定的SRAM结果区 |

前三层测试的13×13输入由12×12 RGB局部区域及上/左边界填充构成，不是要求外部摄像头产生13×13图片。完整网络的目标输入仍是已裁剪、对齐的112×112 RGB人脸。

**最新残差入口不能直接接收RGB字节。两种入口的参数、任务表、地址图不能混用。** 当前输出都是局部特征图，还不是最终128维人脸特征向量。人脸相似度比较、身份判定暂不属于本次 CNN 交付范围。

JPEG/PNG文件需要先解码；文件字节、原始RGB字节、归一化后的量化字节、中间特征字节是不同格式。传入数据必须与该任务的数值约定一致。

## 2. 当前 CNN 内部包含什么

- 两个真实 NEureka 卷积实例，任务根据依赖与空闲情况自动分配。
- 一个共享后处理单元，承担偏置修正、重定量、ReLU/ReLU6或双输入Add；同一时刻处理一个任务。
- 三个INT32临时槽，供卷积结果与后处理交接。三个槽不是三个后处理实例。
- 有限任务图调度：生产者最后一次结果写响应完成后，才允许依赖该结果的任务启动。
- 残差入口提供中间特征释放通知：所有声明消费者均完成后，才允许回收该结果。

可出现“两路卷积＋一路后处理”重叠，但依赖、存储冲突或资源占用仍可能造成等待，不保证每拍所有单元都工作。

最新封装一次最多32个节点；卷积输出按32通道分组，本入口输出通道上限128，已验证64/128通道。每个卷积条带的INT32结果不得超过8 KiB。末端7×7卷积、全网更大通道配置、在线任务补充和完整网络仍待完善。

## 3. 各方负责什么

| 负责人 | 负责内容 | 与CNN交接的内容 |
|---|---|---|
| CNN | 算子、内部调度、临时槽、依赖与数据生命周期、完成/错误报告 | 任务接受规则、存储访问请求、计算完成、可回收结果集合 |
| CPU/系统控制 | 初始化、选择流程、配置任务、启动、处理完成/错误、安排外部读取结果 | 将合法描述符送入CNN；不能在运行中改写正在使用的配置和权重 |
| 输入/IMAGE_BRIDGE | 接收与校验数据，按约定格式写入指定地址，报告写入完成 | 当前先交付“整个输入已写好”；后续增加已提交行通知 |
| 存储/地址管理 | SRAM与仲裁、响应时序、容量与地址划分、外部区域分配/复用 | 保证合法访问与完成时序；依据CNN通知回收中间区 |
| 联合确认 | 模型版本、量化格式、正式地址表、错误恢复、时钟复位 | 用同一份版本化配置，不能各自猜测 |

外部输入区、中间特征区和最终输出区，第一版建议由系统统一分配，再把地址写进任务描述符。CNN内部管理自己的INT32临时槽。**动态地址分配器不要求由CNN负责人一并实现。** 若地址分配由其他负责人承担，CNN需提供清晰的释放信息及映射约定。

CPU侧的MMIO地址表、命令寄存器适配与固件尚未接入新实验入口；下面的 `program_*` 是现有RTL编程端口，不是CPU已经可以直接访问的寄存器。

## 4. 最新残差入口：现有控制端口

方向相对于CNN。全部在同一 `clk` 域内；跨时钟域必须另加可靠CDC。

| 信号 | 位宽 | 方向 | 功能 |
|---|---:|---|---|
| clk / rst_n | 各1 | 输入 | 时钟、低有效复位 |
| clear | 1 | 输入 | 清除本批任务/状态并取消执行；不是暂停后续算 |
| program_valid / program_ready | 各1 | 输入/输出 | 同拍为1时写入一个节点描述符；未接受时保持描述符稳定 |
| program_index | 5 | 输入 | 节点编号0～31 |
| task_count | 6 | 输入 | 本批节点数1～32，节点编号连续使用0到N−1 |
| engine_enable | 2 | 输入 | bit0/bit1启用对应卷积实例；本例为二进制11 |
| slot_limit | 2 | 输入 | 本批使用2或3个临时槽；本例为3 |
| start | 1 | 输入 | 配置完成后脉冲启动，接受条件为program_ready；不要与最后一个描述符同拍提交 |
| busy / done / error | 各1 | 输出 | 批次运行中、全部节点完成、故障状态 |
| completed_mask | 32 | 输出 | bit i=1：节点i最终写响应已完成 |
| release_pulse | 32 | 输出 | bit i脉冲：节点i产生的中间结果可以回收，可能同拍多个bit为1 |
| released_mask / live_mask | 各32 | 输出 | 本批累计已释放结果／已完成但仍保留的结果 |

运行期间 `program_ready=0`，目前不能边运行边补任务。`done`、`error`不是一次性软件消息队列，本批结束/故障后需要按清除复位流程恢复。异步软件不应直接轮询短暂的 `release_pulse`；可读取适配层保存的状态，或利用本批累计的 `released_mask`。当前没有现成的CPU中断映射。

描述符字段如下：

| 字段 | 位宽 | 含义 |
|---|---:|---|
| program_add | 1 | 0：卷积及后处理；1：双UINT8输入Add |
| program_deps | 32 | 所有前驱节点完成位；卷积halo与残差旁路都必须列入 |
| program_config | 32 | NEureka配置表的字节基址；Add不用 |
| program_params | 32 | 后处理逐通道参数表字节地址 |
| program_dst | 32 | 本节点输出字节地址 |
| program_elements / program_channels | 各32 | 输出元素总数／通道数，元素数应是通道数的整数倍 |
| program_src_a / program_src_b | 各32 | Add两个输入地址；卷积输入地址在NEureka配置表中 |
| program_tag | 32 | 任务标记，本例编码为帧[23:16]、层[15:8]、行[7:0]；不是已冻结的系统帧ID协议 |
| program_layer | 3 | 层优先级，调度时使用 |
| program_keep | 1 | 1：保留输出，不自动发布释放；本例最终Add结果为1 |

节点输入、输出、权重及配置不能非法重叠；依赖图必须无环且完整。当前没有全面的任务图/地址合法性检查器，不能把外部任意描述符直接当作可信输入。

## 5. 与存储侧的现有接口

最新实验入口有21个CNN客户端，地址与数据按 `[i*32 +: 32]` 打包，**不要求新增21个SoC顶层模块**。

| 信号 | 位宽 | 方向 | 功能 |
|---|---:|---|---|
| cnn_valid / cnn_write / cnn_byte | 各21 | CNN→存储 | 请求有效、写/读选择、单字节/32位访问选择 |
| cnn_addr / cnn_wdata | 各672 | CNN→存储 | 每路32位字节地址／写数据 |
| cnn_ready | 21 | 存储→CNN | 与valid同拍为1，表示请求接受 |
| cnn_response | 21 | 存储→CNN | 对应事务完成；读、写都必须有响应 |
| cnn_rdata | 672 | 存储→CNN | 每路32位返回数据 |
| cnn_cancel | 1 | CNN→存储 | 统一取消旧事务，不能让旧响应进入新批次 |
| memory_fault | 1 | 存储→CNN | 全局存储故障；接当前存储模块的cnn_mem_fault |

0～8为卷积0数据、9为其配置；10～18为卷积1数据、19为其配置；20为后处理。每路最多一笔在途事务。当前模型接受后下一周期返回，没有响应端ready；增加存储延迟需要联调验证，不能随意改变响应归属。

反压时CNN保持请求字段；32位访问要求4字节对齐，字节写只更新低8位对应的目标字节，小端排列。当前SRAM字节读会符号扩展，UINT8使用者必须取返回低8位。**请求被接受不等于写完；依赖发布必须等写响应。**

每个NEureka的288位读取在桥内拆成9笔32位请求；不能绕过现有桥，将任意延迟的SRAM直接接入NEureka核心。

## 6. 输入输出数值与生命周期

输入、UINT8中间特征和输出按HWC排列：先通道、再列、再行，每元素1字节。INT32临时值为小端4字节。UINT8是存储容器，**不代表实际值一定非负**：实数近似值为 `(q − zero_point) × scale`。

最新残差例的初始输入采用scale=6/255、zero_point=0；线性投影与最终Add输出zero_point=128，scale从该例 `workload.json` 取得。前三层图片入口采用另一套预处理与尺度，详见输入要求文档。两图共用固定诊断尺度，尚未完成准确率校准。

生命周期约定：

1. 输入方完成数据、权重、参数和配置写入，确认存储可见，再允许本批启动。
2. 中间结果由CNN写入；所有消费者用完前，外部不能覆盖。
3. `release_pulse[i]`只给节点位，外部通过描述符中的 `program_dst/program_elements` 查到可回收地址和长度；现有端口不直接输出一条“地址＋长度”消息。
4. `program_keep=1`的最终结果不自动回收。外部读走结果并确认后，再按批次恢复流程复用。当前没有单帧结果消费确认端口。
5. 本例外部预加载输入不是一个生产者节点，不能把中间节点的释放位误当成整张输入图释放。第一版保守地等本批done后，再回收该批输入区。

clear会清除任务状态但不会替外部保存结果，也不能使被中断任务的部分输出自动变成有效结果。已经验证的恢复方式为clear取消、系统复位、重装所需SRAM内容和任务表，再重新启动；不是断点续算。

## 7. 推荐首次联调流程

第一轮先使用**已有三槽前三层入口**，验证“图片小区域→特征写回”；第二轮使用**最新残差入口**，验证旁路与回收通知。两者各自使用对应生成文件，不要自行拼接。

1. 共同选定实验入口、时钟复位、地址图、模型与数值格式版本。
2. 外部加载方写入对应输入、打包权重、量化参数和配置表；等待真实写完成。`.bin`是测试文件格式，RTL端口并不直接读取文件。
3. 控制方经适配逻辑逐个提交描述符，最后一项接受后撤销program_valid；随后单独脉冲start。
4. CNN自主分配算子并访问SRAM。外部遵守所有权，不修改正在使用的区域。
5. 控制方观察error或done。首次联调先使用整批done，不自行猜测某张图何时算完。
6. 外部从约定结果地址读出UINT8特征，对照该例参考结果。对外传输由CPU/输出桥负责，CNN当前不提供UART发送接口。
7. 测试反压、错误恢复后，再接真实输入协议。更换为CPU/输入桥真实并发访问时，重新验证仲裁和数据一致性。

前三层资料：[三槽报告](../deliverables/mobilefacenet_triple/README.md)。残差资料：[残差报告](../deliverables/mobilefacenet_residual/README.md)、[节点与地址表](../deliverables/mobilefacenet_residual/task_map.csv)、[机器参数](../deliverables/mobilefacenet_residual/workload.json)。

测试数据目录分别为 `build/mobilefacenet_triple_data`、`build/mobilefacenet_residual_data`。`memory.bin`用于预加载；`golden.bin`用于测试端核对，**不能加载到硬件结果区代替计算**。`nodes.hex`是各自测试脚本使用的表格式，两种入口字段数量不同，正式CPU协议仍需封装。

## 8. 地址和容量不能直接照搬

前三层三槽实验使用256 KiB模型，scratch为0x38000/0x3A000/0x3C000；最新残差实验使用512 KiB模型，scratch为0x70000/0x72000/0x74000，均每槽8 KiB。扩大实验容量是为保留两个帧的中间数据和对照区，**生产SoC的256 KiB基线没有因此改变**。

这些实验地址不是正式部署内存图。实际地址空间改变时，必须同步CNN临时槽参数、NEureka配置、任务输入输出和加载数据。还需为宽读取的实际访问范围预留合法空间，不能只分配数学上有效的像素字节数。

## 9. 后续接口：待实现，不能现在直接接

| 后续能力 | CNN侧工作 | 外部侧工作 |
|---|---|---|
| 分块输入后立即计算 | 接收帧/行已提交事件，判断窗口与halo是否齐全 | 可靠写入、校验、报告真实写完成，支持暂停/背压 |
| 连续多图 | 在线任务队列、完成队列、帧/代次区分 | 持续提交，处理结果取走与异常 |
| 中间空间实际复用 | 提供完整可回收信息并保护所有消费者 | 分配地址、接收通知、安排复用 |
| 完整人脸特征提取 | 补大通道与7×7等、全网调度、量化验证 | 加载完整模型和一致格式的图片，提供容量/带宽 |

行就绪通知、在线队列、单帧消费确认都不是当前 `quant_residual_scheduler` 已存在的端口。现有 `program_deps`仅表示任务之间的完成依赖，不能直接表示“外部某行已经输入”。

## 10. 本次可验收的标准与证据

当前残差独立仿真：正常、实例0限速＋释放后覆盖、Add中断后复位重跑，三项均PASS。每项28节点、8次Add、20次中间特征释放，逐字节检查101,888字节，最终输出哈希一致。证据见 [运行结果](../deliverables/mobilefacenet_residual/result.json)。这证明计算与内部控制，不等于CPU/UART/完整SoC已验收。

首次模块联调的验收要求：合法数据算对；忙时不误收新描述符；写完成前不发任务完成；反压时请求稳定且不重不丢；外部只能回收真正不再使用的区域；最终结果被取走前保持有效；故障时停止继续消费无效数据，复位重跑结果一致。

共同确认表：

| 待确认项 | 当前建议／填写内容 |
|---|---|
| 首轮计算入口 | 三槽前三层；残差作为第二项 |
| 输入数值与预处理负责人 | 沿用对应测试profile，发送侧先预处理；双方确认负责人 |
| 正式内存容量、地址表 | 存储/系统负责人提供，CNN同步配置；不可混用两个实验图 |
| CPU控制适配 | 共同冻结命令格式与映射，CNN侧明确接受/完成语义 |
| 存储读写响应与取消 | 按第5节核对；更换时延需补联调 |
| 输出形式 | 当前局部特征；目标完整特征向量；比较暂不纳入 |
| 结果取走与地址回收负责人 | CPU/输出侧与存储管理方共同确认 |
