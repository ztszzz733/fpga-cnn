## 如何判定10ms

1. 实际相邻结果读完时间之差，14个间隔的平均值是否小于10ms。
2. 同时报告最短/最长、全部14间隔和首张等待，不能延迟读取或攒结果人为缩短间隔。
3. 单独报告整批时间/15；有限批次平均间隔即使达标，也不等于持续100帧/秒。

当前四bank在100MHz时，每bank每拍最多一个32位CNN/IO访问，总理想带宽1.6GB/s。旧版CNN实际读808461840字节、写290059380字节，共1098521220字节。仅这些流量的理想整批访存下限686.576ms，平均45.772ms/张；未计字节传输、bank冲突、输入/结果读回等额外代价。因此保持相同搬运量和存储接口时，单纯增加算子不能持续10ms/张。这个下界约束持续吞吐及整批平均，不约束有限批次某段集中输出的相邻间隔。

后续如追求持续10ms/张，需要CNN内部融合/分块缓存降低中间结果搬运，或与存储合作人协商增加bank/带宽。本轮先只测扩容，不擅自更换存储架构，也不声称板上资源充足或达到100MHz。
