# 1×1 卷积四位置并行试验

本次优化每套 1×1 引擎的内部计算，保留 K3×2、K1×4、DW7/Post/Add/Pad 各1的六图测试配置。四套 K1 仍由原调度器独立分配任务；没有变成四套3×3，也没有增加调度器。

实测结果与证据见 [验证报告](../deliverables/self_pw4/README.md)。本轮只运行单层和六图小数据回归，没有重跑完整 MobileFaceNet。

## 数据怎样复用

旧 K1 已有2×2分块缓存，但计算时逐个位置执行，每次乘加经过读取、累加两个阶段。新 `self_pw4_engine` 将这四个位置放在四个独立输入缓存中，用同一个权重同时计算四个位置。

例如四个像素都有64个输入通道，需要计算某个输出通道时：先把这四个像素和该输出通道的64个权重缓存起来，然后逐通道广播权重。流水填满后，每拍四条通路各完成一次乘加；64拍连续累加后，得到四个像素在这个输出通道上的结果。换下一个输出通道时，四份像素输入继续复用，只更换权重。

```text
SRAM → 32位/字节读取 → 四个像素缓存 + 一份权重缓存
                              ↓ 同步读取一个通道
                         乘法寄存器（四路）
                              ↓
                         INT32累加（四路）
                              ↓ 所有输入通道累加完
                         四份结果逐字写回SRAM
```

计算流水有同步读、乘法、累加三段；流水启动和结束有开销，但填满后可每拍累计四个有效MAC。1×1、1×2、2×1等边界块只启用实际存在的位置。四套引擎满载时合计最多16个MAC/拍，这是计算阶段的峰值，不是全程吞吐保证。

输入和权重的外部地址、内部通道索引均对齐，且至少还剩4个通道时，一次读32位；其余情况精确读单字节，不越界读取尾部。stride=2直接选取需要的像素，不加载跳过的位置。每套仍只有一笔外部未完成访存，加载、该输出通道的计算和写回依次执行；本次没有新增DMA与计算的重叠。

## 保持的接口与数值约定

- 普通1×1卷积，输入UINT8、权重INT8、输出原始INT32；HWC输入/输出、OHWI权重。步长1或2，输入/输出通道均为1～512。
- 该引擎不处理depthwise、偏置、量化零点校正、激活；原有DW3、DW7和后处理路径继续处理对应任务。
- `start`锁存描述符。`valid && ready`接受请求，`response`完成该请求，支持同拍接受和响应。反压时请求地址和数据保持稳定。
- `done`在最后一笔写响应之后出现；不能只收到写请求就发布结果。`clear`同时要求外部存储系统取消旧请求和迟到响应。
- `input_reads`、`weight_reads`统计字节数，宽读加4、字节读加1；不是请求数。`mac_count`每个有效累加拍增加实际活动位置数。
- `operator_work`/`mac_fire`表示该拍有有效累加，不能直接按“一拍一个MAC”统计；测试程序已改为读取MAC计数器增量。
- `phase`枚举属于新引擎，不能套用旧引擎状态编码解释。

## 接入及复现

`self_fixed_network_top` → `self_stream_top` 增加编译参数 `PW4`。`PW4=1`时所有K1实例使用新引擎，K3不变；`PW4=0`保留旧引擎作对照，默认仍为0。它是硬件生成参数，不是运行时CPU寄存器。

本机WSL中的小回归命令（工程目录执行）：

```sh
python3 scripts/run_pw4_unit_wsl.py
python3 scripts/run_self_six_wsl.py --data build/self_six_small --pw4
python3 scripts/run_self_six_wsl.py --data build/self_six_small
```

六图runner显式选K3=2、K1=4、六帧上下文，两个版本使用独立缓存。`--reuse`只接受源码、工具和可执行文件哈希完全匹配的缓存。完整网络还需`--full`与匹配的小回归`--gate`，本轮未启动。

Windows Python可执行单引擎综合：

```text
python scripts/synth_self_cnn.py --top self_pw4_engine --max-kernel 1
python scripts/synth_self_cnn.py --top self_conv_engine --max-kernel 1
```

## 验证范围

单层测试用独立标量整数参考校验；包含奇数通道、尾块、未对齐、步长、正负极值、变化的反压/响应延迟、clear重启、描述符锁存、非法配置及同拍响应。六图小回归用真实bai SRAM与实际卷积、后处理和补边算子执行首三层，共48任务；运行正常并行、串行对照、预加载和压力四种场景。本数据没有DW7或Add任务，不将其列为本轮覆盖。

综合针对XC7Z020-CLG484-1、10ns，只有单引擎OOC综合，没有整机布局布线；综合满足时序也不等于板上100MHz已通过。本轮不证明512KiB容量适配、完整网络新速度、真实人脸准确率、CPU/UART接入或层内条带输入。大图端到端收益需要后续完整六图回归实测。
