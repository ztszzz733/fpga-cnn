# 第三轮优化：K3宽读取与后处理流水

目标是降低现有算子的访存和控制开销，保持 K3×2、K1×4、DW7/Post/Add/Pad各1，不增加算子实例。K1沿用上一轮四位置并行、权重预取和写回重叠结构。

## 启用方法

`self_fixed_network_top` / `self_stream_top` / `tb/self_full_sim_top`新增默认0的`WIDE_PIPE`参数。使用本轮完整配置时设`PW4=1, CONV_OVERLAP=1, WIDE_PIPE=1`。运行器`--wide-pipe`自动启用三个参数，使用独立缓存`.self_six_wide_build`。旧三个卷积版本及原`quant_post_engine`均保留。

## 3×3/DW3

`self_conv_wide_engine`延续2×2输出位置的输入块缓存，输入块跨输出通道复用，一个输出通道的权重跨块内位置复用；读缓存、乘法和累加流水保持上一版的算术顺序。

外部地址和本地缓存索引都对齐，且当前像素还有至少4个通道时，一笔32位读取装入四个通道字节。权重同样按四字节读取；非对齐或尾部回退为字节读取，不允许多读有效区域之外的数据。内部缓存改成具有固定字节写使能的32位RAM，读取时保存字节选择位置。3通道RGB首层输入仍主要按字节读，后续大通道层更受益。

保持一个未完成的外部请求，支持反压、延迟响应和接受请求当拍返回。输入与权重计数仍表示实际读取字节数，MAC总数不变。没有新增K3加载与MAC同时进行的双缓冲。

## 后处理与Add

`quant_post_pipe_engine`保持五字/通道的参数格式：bias、multiplier A、multiplier B、零点/移位、上下限。Post将INT32卷积结果加偏置、缩放、舍入、裁剪为UINT8；Add对两个UINT8输入去零点、分别乘缩放系数、相加后只舍入一次。

参数分为五个同步读RAM银行。七级寄存流水依次完成参数/输入采样、输入调整、乘法、求和、绝对值与半LSB、移位恢复符号、输出零点，再裁剪并装入输出组。连续元素的运算可与后续元素的输入读取重叠。

输出地址对齐且剩余至少四个元素时，用一个32位写请求保存四个UINT8结果；非对齐头部和不足四个的尾部逐字节写。每组写响应完成后再开始下一组，不跨组预取。**这是四元素分组的后处理流水，不是卷积结果直接流入后处理的跨算子融合。** 中间结果仍经共享SRAM传递。

33位有符号调整量乘32位有符号系数产生65位乘积，两个乘积用66位求和和舍入通路。合法模式下数值范围足够覆盖原96位表达式实际可达值，包括INT32输入与偏置的和、shift=0～63及负数半值舍入。独立C++参考采用128位整数，未复制RTL流水实现。

`done`仅在最后写响应收到后发布。描述符在start时锁存；clear清除本单元所有有效标记，互连也必须取消在途请求和迟到响应。当前网络使用不重叠的输入/输出缓冲区；未扩展任意地址别名语义。

## 观察信号

- `operator_work[0:5]`：六个卷积实例的实际MAC推进；K1一次可推进最多四次MAC，精确总数看`conv_mac_count`增量。
- `operator_work[6]`：DW7实际MAC推进。
- `operator_work[7:9]`：Post、Add、Pad接受写请求，表示输出推进，**不是每个乘法或每个像素各一拍**。Post/Add打包后一次推进可能写四个元素，因此不能把此计数减少解释为算术计算减少。
- `mem_valid & mem_ready`：请求接受；同时`mem_write=1`为写入；`mem_byte=0`表示32位，否则为单字节。
- `mem_response`：该实例存储请求返回/写完成；`unit_active`含计算与等待。

## 复现

在工程目录、WSL既有Verilator环境运行：

```text
python3 scripts/run_conv_wide_unit_wsl.py --k3
python3 scripts/run_post_pipe_unit_wsl.py
python3 scripts/run_self_six_wsl.py --data build/self_six_small --wide-pipe
python3 scripts/run_self_six_wsl.py --data build/self_six_full --wide-pipe --reuse --full --gate <匹配的小回归目录>
```

完整运行复用小门槛的同一可执行程序，核对源码、编译参数、数据和可执行文件哈希。不要为查看结果重复启动全网。
