## 1. 我们在做什么、为什么改变方案

最终希望得到一个 CNN 子系统：多张已裁剪、对齐的人脸图片依次进入，按预先配置的网络流程计算，输出每张图片的特征信息；流程可以重新配置。运行中根据数据依赖和空闲算子自动分配任务，让同类算子、不同阶段以及不同图片尽可能重叠执行。图片不必全部收到才开始，长期目标包含分块/条带输入后尽早计算，并减少中间特征反复写回、读出外部存储。

当前模型基线是 MobileFaceNet，输入112×112 RGB，输出128维特征。用户暂不负责特征比较、身份库与识别决策；输出特征不等于已经完成人脸识别准确率验收。

此前先后探索了 NEureka、NVDLA、Vicuna。当前路线已经放弃 Vicuna，不恢复 NVDLA 路线。本次用户因开发板资源不足决定**替换 NEureka，使用自写的卷积结构，并参考 NEureka 的数据复用方式**。保留已有调度、缓存生命周期、结果交接经验，避免重新从零写完整系统。

板型按用户此前提供的 XC7Z020-CLG484-1 作为暂定目标。资源不足是本次调整的动机；本文没有新综合报告，不填写未经验证的资源占用或性能收益。

## 5. 新卷积的功能与资源要求

### 5.1 以当前网络实际算子为基础

现有模型记录：33个1×1普通卷积、16个3×3深度卷积、1个普通3×3卷积、1个全局7×7深度卷积，共51卷积；另有32 ReLU6、2 ReLU、12 Add，BN已折叠。这里是网络节点数量，不是要实例化51个硬件卷积模块。

覆盖普通1×1、普通3×3、DW3×3、DW7×7；按实际层支持步长1/2、输入输出通道、空间边界、尾块和量化规则。DW7按当前模型需要的步长1验证。配置范围必须从模型清单逐层核对，不把“任意 N×N 卷积”作为现成能力。当前网络不需要普通 MaxPool，不因早期演示讨论过池化就额外加入。

沿用现有整数基线作为起点：UINT8激活、INT8权重、INT32卷积输出，后处理做偏置、缩放、舍入、零点及夹紧。必须明确输入零点校正的位置、带符号乘法、累加溢出规则、补边值、残差两分支不同尺度的处理，逐字节核对独立整数参考。

### 5.2 参考复用思想，不搬回大阵列

- 输入复用：行缓冲或分块缓存保存邻域，邻近输出共享输入；普通卷积不同输出通道尽量共享输入块。
- 权重复用：一次加载的权重计算多个空间位置；明确何时替换权重与缓存失效。
- 部分和复用：内部累加，避免每次乘加都写回 SRAM；完整累加结束后再输出。
- 深度卷积：每通道独立，利用滑窗/行缓冲减少重读，不错误套用普通卷积的通道求和。
- 若后续采用双缓冲，只有实际存在加载与计算重叠并经验证，才称搬运计算重叠。

MAC并行度、输出块大小、缓存大小、通道分块、引擎是否统一由接手者结合资源报告决定。曾考虑“一MAC/实例、2×2输出块”，它只是面积优先候选，不是用户确定的规格，也不是已实现设计。不得为了低资源让效率退化为逐MAC外存读写。

用输入/权重实际读取字节数、MAC次数和缓存命中/重用计数验证复用。不同卷积类型分开统计，与相同任务不复用的读量比较，不能只写“参考了NEureka”。若借用上游源码，保留许可证及来源。

### 5.3 资源必须全量核算

预算包含两份算子、局部缓存、后处理乘法器、调度队列、依赖表、存储端口与缓冲，不只计算卷积MAC数量。避免大数组异步多口读取或整块复位导致难以推断BRAM。

旧1024命令表和宽生命周期掩码可能本身很大；必要时用有界窗口、紧凑依赖/引用计数等方案，但保持数据安全。旧约5.36MiB整层缓存池需要外部存储或分块计划；更换卷积本身不会消除它。

后续综合需报告器件、配置、LUT/FF/BRAM/DSP、时钟约束与时序，并为CPU和其他大模块预留资源。没有综合数据不得宣称已满足上板资源要求。

## 6. 每类两份与自动分配

默认按独立算子类别列出两个实例：普通卷积×2、深度卷积×2（3×3/7×7可否合并需评估）、量化/激活后处理×2、残差Add×2、补边×2。最终清单应对应实际 RTL 的独立执行引擎，而不是机械复制每一层。

ReLU/ReLU6如果已融合在后处理夹紧中，可以由两个后处理实例覆盖，需明确融合关系。普通卷积与深度卷积全部合并为仅两份通用卷积的方案会减少两类之间并行度，属于可讨论的资源折中，不是本次已确定的替代要求。不要直接把“总计8实例”当成用户已批准的固定数量。

调度至少检查：任务有效、输入区域已就绪、前驱完成、输出空间已保留、适配该任务的实例空闲。发射时锁定帧号、层/任务号、读写范围、参数；完成需等待最后写响应，不能发出最后写请求就提前通知后继。

两图可以交错执行，帧内维持真实依赖；Add须等待两个分支，不能覆盖仍被残差使用的数据。公平仲裁避免某帧长期饥饿，反压时不能丢请求或重复写。支持禁用/限速某实例来验证调度不依赖固定绑定。

外部还没有读完最终结果时，保持帧号、结果地址与长度稳定，禁止回收相应槽。区分计算结束和全部结果取走；沿用结果确认语义前先阅读既有接口文档。

## 7. “两张图进来”和流水的分阶段定义

第一阶段可把两张不同小图片预加载到仿真 SRAM 后同时通知就绪，验证真实算术、自动分配与并行。这只证明“双图任务就绪后并行”，不证明UART接收期间计算。

第二阶段用测试台分行/条带供给图片，输入区域收到并落存储后发布就绪范围；卷积拥有足够窗口和边界数据即可计算，后续行继续输入。核跨度、步长、halo与末尾补边影响何时就绪，不能对所有层统一套用“第三行第三个像素开始”。必须有反压和输入缓存释放规则。

第三阶段在完整网络中按条带/块发布中间结果就绪，使卷积、后处理、后续层以及两张图重叠，减少整层来回读写。先通过SRAM共享缓冲实现流水也可以，但应统计流量；后续再评估直接流接口或融合，不能默认已经消除了SRAM往返。

长期扩展为连续N张图，必须有有限在途数量、帧号、缓冲循环与背压。两图通过不代表无限图已验证，不要求所有算子每拍满负荷；网络依赖和存储带宽都可能限制并行度。

## 8. 与同学对接需要明确什么

用户的责任是 CNN 内部计算、任务调度、局部缓冲与对外接口实现。外部团队负责图片/权重/配置写入、CPU发起或配置、生产存储仲裁和最终读出。第一阶段可用TB替代外部，但需明确只是接口模型。

接口文档至少给出：任务/帧号，图像形状与HWC布局，权重布局，量化参数，地址/步长/对齐，配置有效与接受，输入区域就绪通知，存储请求接受及响应，错误/清除，输出描述及读完确认。字节写、写掩码、响应顺序、最大在途数和复位后旧响应处理都需明确。

新卷积不再照搬NEureka寄存器命令或打包权重。可考虑普通卷积OHWI、深度卷积[通道,核高,核宽]连续INT8布局，但应在实现前定稿并版本化；旧二进制不能直接当新格式使用。具体命令位域/字序尚未定稿，本文不承诺兼容旧word布局。

## 9. 后续实施顺序与验收

在获得用户实施授权后，按以下顺序推进，不直接启动完整大图。

1. 核对当前模型算子/维度，形成双实例清单、接口和资源估算，明确所有合并方案的并行能力。
2. 单个自研卷积单元及后处理数值测试；覆盖普通/DW、1/3/7核、步长、尾块、零点、负权重、夹紧、Add。
3. 集成双实例与旧调度/租约/结果协议，完成两张不同小图片真实数值测试。
4. 补充分实例限速、存储反压、慢读、clear/错误等回归，证明不是忙信号的假并行。
5. 做资源综合检查，再决定并行度/缓存；适配完整模型导出，先完整单图，再完整双图。
6. 最后补分块输入、跨层块级流水、连续帧及外部接口联调；准确率作为独立阶段。

| 验收项 | 必须提供的证据 |
|---|---|
| 真正替换 | 新入口编译清单不依赖NEureka；卷积由可综合自写RTL执行，TB不代算、不向运行内存注入参考中间结果 |
| 数值正确 | 每个检查点和最终输出匹配独立整数参考；记录输入、权重、源码、输出哈希 |
| 两图隔离 | 两张不同输入，有明确帧号；输出不串帧，完成顺序和输出归属可追踪 |
| 两份均使用 | 每类两实例都有任务记录；可并行的测试中出现真实有效执行重叠 |
| 计算并行 | 两卷积MAC有效同拍计数；其他算子记录有效运算或数据推进。busy含访存等待，不能单独证明计算重叠 |
| 跨类流水 | 卷积/后处理等跨类有效工作重叠；说明是跨图、跨层还是同层分块 |
| 动态分配 | 单实例禁用或限速后，另一空闲实例可接受符合条件任务；无固定帧绑定或饥饿 |
| 数据安全 | 消费者完成后回收；释放槽覆写测试、边界保护、残差依赖、最终读确认都通过 |
| 反压及异常 | 延迟/仲裁等待不丢事务；clear和非法配置有明确定义，无旧响应误完成新任务 |
| 数据复用 | 实测读取量与MAC次数，说明哪些维度实现复用、哪些尚未实现 |
| 资源适配 | 综合报告和配置，包含控制/缓存，不仅展示仿真PASS |
| 阶段边界 | 小图、整图、全网、流式输入、SoC、准确率分别记录，不相互替代 |

性能报告可比较同一新实现的单实例与双实例，但不要求承诺比旧NEureka快多少。电脑运行耗时、硬件周期、时钟频率换算应分开报告；100MHz下硬件毫秒=周期数/100000，100MHz只是换算条件，实际可达频率须由时序报告支持。
