# 3×3 / DW3 四位置并行优化

本轮目标：缩短两套K3引擎的计算时间，减少后续层等待；保留四套PW8和DW7/Post/Add/Pad各一套，继续以15张相同图片完整MobileFaceNet验证。不是增加四套独立3×3算子。

## 数据复用与并行

新增 `self_conv_spatial4_engine`。一次缓存2×2输出块及其所需输入邻域，四条通路分别累加左上、右上、左下、右下输出，广播同一个权重。普通卷积遍历九个核位置和全部输入通道；DW3每个输出通道只使用对应输入通道。

输入分成四个真实RAM银行，每个输入字节只写到其中一个。步长1按空间坐标最低位选银行，步长2按第二位选银行，确保四个同时读取的位置不冲突。删除选银行的坐标位后形成银行内位置；每银行按3×3×MAX_CHANNELS保留地址空间，因此资源比原单RAM增加，但不需要四份完整输入副本。

边界只有一行或一列时屏蔽多余通路，每拍有效MAC数量为1/2/4；计数器累加实际数量。输出仍通过原32位接口逐字写回，外部最多一个未完成请求。四位置并行不意味着输入搬运、写回和整个网络都加速四倍。

保留DW_CACHE：每个DW命令完整权重只读一次，空间块重复利用；新命令和clear使缓存有效标志失效。支持UINT8输入×INT8权重、INT32结果；激活、量化仍交给Post。普通权重OHWI，DW权重C/KY/KX。现实现限定TILE=2、MAX_CHANNELS为4的倍数，实际配置512；运行时通道数可以不是4的倍数，支持精确字节尾部、非对齐地址、stride1/2、kernel1/3。

## 控制与接入

`K3_PAR4=0`保留原K3选择，`K3_PAR4=1`选择新引擎，经过self_full_sim_top → self_fixed_network_top → self_stream_top传递。它是RTL编译参数，没有新增CPU运行时寄存器。运行器 `--k3-par4`启用独立缓存；`--cache-suffix`允许独立验证旧模式，不覆盖历史程序缓存。

综合发现权重结束判断的组合链过长，最终版本在CHECK阶段预计算末字节、末整字和整字数量，运行时使用相等判断；没有增加运算周期。保留前两次时序失败报告，不能把它们当作100MHz成功证据。
