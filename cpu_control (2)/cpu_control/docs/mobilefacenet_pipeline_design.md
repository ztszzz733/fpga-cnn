# 真实权重条带流水：调度与缓冲约定

本模块位于 CNN 计算侧，原 SoC 六大模块划分不变。实现文件 `rtl/cnn_quant/quant_stripe_scheduler.sv`，包含一套原 NEureka 封装、一套已验证的 `quant_post_engine`，以及两槽生命周期控制和小型依赖表。还没有接入生产 CPU 或 UART。

## 任务与层间依赖

一个任务表示一张图、某一层、两行输出、完整64输出通道的条带。实际先发射两份32输出通道的卷积配置，再对整个条带量化激活。任务完成不是卷积算完，而是**后处理最后一个写事务得到响应**。

三层局部网络是首层6×6×64、DW4×4×64、PW4×4×64，每张图3+2+2=7个任务，两张图14个任务。帧标识0/1，对应 `person_1.jpg` / `person_2.jpg`，不表示身份。两张图使用同一套数值尺度；这套尺度仍是局部调试值，不是准确率校准结果。

- 首层每两行输出的输入跨度为5行，因为核3×3、stride2；相邻条带共享1行原始输入。
- DW第一条带计算输出第0、1行，需要首层第0～3行，所以依赖首层条带0、1。DW第二条带需要首层第2～5行，依赖首层条带1、2。
- PW为1×1，同一个输出条带只依赖对应DW条带。
- 不同图片的任务之间没有数据依赖，但共享同一套卷积与后处理资源。

任务表记录一个32位依赖掩码。仅当 `deps & completed_mask == deps` 才能占用空闲临时槽；completed位仅由后处理完成设置。已经满足依赖的任务中，优先下游层，其次表内编号。任务表在启动前固定装载，运行中不能改动；最多32个任务，不是无限在线提交系统。无环、地址不重叠等合法性由任务生成器保证，本实现尚无通用硬件DAG合法性检查。

## 临时槽状态

```text
FREE → READY → CONV(通道0..31)
               → READY → CONV(通道32..63)
                         → POST_READY → POST → FREE
```

每个槽保存当前任务编号。卷积引擎只有一套，同一任务的两个通道组依次执行；后处理可以同时处理另一槽。槽不能在卷积完成时释放，要等其全部量化输出写响应完成。清除任务同时向存储系统发出取消信号，避免旧响应被新任务接收。

临时槽固定地址0x38000、0x3A000，各8KiB；最大实际条带为2×6×64×4=3072字节。任务配置的输出地址必须与槽一致。这些是当前小实验的约定，不是全模型统一内存布局。

量化后的特征区按图片和层分别保留，后层直接从它们读取相邻行。本轮没有循环输入行缓冲、特征区重用、完整内存分配器或DMA搬运引擎。输入图像已在SRAM中，不能据此宣称UART边收边算。

## 调度接口

装载期 `program_valid && program_ready` 写入一个表项，`program_index`是任务编号：

| 字段 | 内容 |
|---|---|
| program_deps | 必须先完成的任务位掩码 |
| program_config | 四份NEureka配置起始地址，各24个32位字 |
| program_params | 量化后处理逐通道参数地址 |
| program_dst | 该条带最终UINT8写回地址 |
| program_elements / program_channels | 条带元素数与通道数，当前生成器64通道 |
| program_layer | 调度优先级使用的层号 |
| program_tag | `[23:16] frame, [15:8] layer, [7:0] stripe` |

配置排列为槽0通道组0、槽0通道组1、槽1通道组0、槽1通道组1，地址公式 `config_base + slot*192 + group*96`。内部预取仍关闭，沿用上一轮的保守配置，不涉及修改第三方核心。

装载所有表项后，用start提交task_count和overlap_enable。overlap_enable在启动时锁存；0是同一任务图的顺序对照，1允许卷积与后处理重叠。done保持到clear；error或memory_fault触发取消，重新装载前需要clear。表项输入目前由测试平台驱动，未来CPU寄存器/命令队列可对接此边界，但本轮不假称CPU已经会提交这些任务。

## 验证边界

两张图片先分别计算完整局部层的整数参考，再独立生成条带寄存器配置。真实RTL逐条带核对32位卷积结果和8位量化结果，并将所有最终条带输出导出；并行、顺序、反压复位三个版本必须与金标准一致且输出哈希相同。

测试额外检查：后层启动时依赖条带已写完；同一槽不能被两个任务同时占用；每条带恰好两次卷积发射和一次后处理完成；图片和层标签正确；所有不可写区域保持不变；确实出现后处理写请求与NEureka计算阶段重叠；并行模式至少有一次后层在前层全部条带完成前启动；两张图任务有交错执行。反压复位用例在卷积和后处理同时忙时clear，再复位、重新装载完整任务表验证。

“core_state=4”仅表示计算阶段，不证明每个PE每拍都有效工作。调度重叠以状态、存储握手及完整结果对照共同证明；具体周期和波形以对应运行交付报告为准。
