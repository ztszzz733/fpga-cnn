## 已完成

1. DW3×3 + stride2：相同小例关闭内部预取后通过，两帧、四任务、96输出字节全部正确。默认任务生成策略已对该组合关闭预取，其他模式保持原策略。原预取开启时卡顿仍未根治，这是配置绕行；原失败目录保留。见 [绕行验证](dw_stride2_workaround.json)。
2. 新增 `rtl/cnn_quant/quant_post_engine.sv`：逐通道偏置补偿、乘数/移位重定量、ReLU6/普通ReLU夹紧，以及两个不同尺度输入的残差加法。保留宽位宽中间值，写响应完成后才发 done。
3. 使用 `D:/code/facemodel/person_1.jpg` 与已固定的真实 MobileFaceNet 权重，保留原网络64个通道，跑通首层卷积→ReLU6→DW卷积→ReLU→PW卷积→ReLU。全部数据来自 SRAM；下一层读取上一层真实硬件写回的结果，没有由 Python 填入中间金标准。

最终运行：`build/runs/20261021_234938_mobilefacenet_chain`。正常与确定性内存反压两项均 PASS，每项检查 **21,792 个输出字节**，另检查全部不可写区域未变、错误通道数被拒绝、clear 可以取消正在读取参数的任务。末尾残差独立测试包括零点、不同乘数、饱和及正负半整数舍入，不是把前三层误称为残差网络。

## 实际算了哪一块

模型输入仍是112×112的人脸，这次只计算一个可与整网对应的小区域以控制仿真成本：

| 阶段 | 输入 | 输出 | 说明 |
|---|---|---|---|
| 首层3×3、stride2 | 13×13×3 | 6×6×64 | 对应整层左上6×6；顶部/左侧包含真实零填充，其量化字节为128 |
| 深度3×3、stride1 | 6×6×64 | 4×4×64 | 对应整层位置 `[1:5,1:5]` |
| 1×1卷积 | 4×4×64 | 4×4×64 | 保留全部64输入与64输出通道 |

每层分两次发射，每次32个输出通道。最后得到1024个量化特征元素，**不是最终128维人脸向量**。新增后处理目前仍在独立 CNN 计算侧测试中，任务由测试平台发射，CPU固件接入未完成。

浮点局部计算已与 ONNX 整网中相应位置对比，三层最大绝对误差分别约 `4.01e-7`、`6.86e-7`、`1.28e-6`，确认裁剪邻域正确。硬件与整数参考逐字节相同；相对于浮点局部链条，三层累积量化 RMSE 约0.00653、0.01960、0.02798。后两层的尺度只根据本次局部样本确定，这些误差不代表全模型识别准确率。

| 信号 | 来源 → 使用方/观察方 | 含义 |
|---|---|---|
| job | 测试任务驱动 → 波形 | 当前执行任务编号，见下表 |
| conv_start | 测试任务驱动 → NEureka封装 | 提交一份卷积寄存器配置 |
| core_busy | NEureka核心 → 封装/波形 | 核心处于任务中，不等于每个周期都有效乘加 |
| core_state | NEureka内部控制器 → 波形 | 4为MATRIXVEC计算阶段；卡住时也可能持续为4 |
| accum_done | NEureka内部累加控制 → 主状态机 | 当前内部计算步的累计完成条件，不是整层完成 |
| prefetch_done | NEureka预取控制 → 主状态机 | 预取完成条件；本小链条关闭预取，所以高电平也可表示无需等待，并不表示刚读到数据 |
| conv_read_fire | NEureka存储桥 ↔ DATASRAM | 至少一笔输入/权重读取请求获得接受；不包含配置端口 |
| conv_write_fire | NEureka存储桥 → DATASRAM | 至少一笔32位累加结果写请求获得接受 |
| cdone | NEureka封装 → 任务驱动 | 本次卷积任务完成，待写事务已经排空 |
| post_start | 测试任务驱动 → 量化后处理 | 锁存后处理参数表地址、输入/输出地址、数量和模式 |
| mode_add | 测试任务驱动 → 量化后处理 | 0为卷积INT32结果重定量；1为两路UINT8残差加法 |
| pbusy | 量化后处理 → 波形 | 参数加载或数据处理期间为高 |
| post_read_fire | 量化后处理 → DATASRAM | 读请求接受；先读逐通道参数，再读特征数据 |
| post_write_fire | 量化后处理 → DATASRAM | 一个UINT8结果的写请求接受 |
| pdone | 量化后处理 → 任务驱动 | 最后一笔写响应完成后发出 |
| memory_fault | DATASRAM → 波形/检查器 | 存储访问故障；通过用例全程为0 |

| job | 工作 |
|---:|---|
| 0、1 | 首层卷积的前32/后32个输出通道，写INT32 |
| 2 | 首层偏置补偿、重定量、ReLU6，写UINT8 |
| 3、4 | 深度卷积的两组通道，写INT32 |
| 5 | 深度卷积后重定量与ReLU |
| 6、7 | PW卷积的两组输出通道；每组均累加全部64输入通道 |
| 8 | PW卷积后重定量与ReLU |
| 9 | 独立残差算术边界向量测试 |

本轮为了逐层排错采用顺序执行，图中卷积与后处理交替工作是预期行为。上一轮两槽重叠调度仍在，但尚未与本轮量化后处理联合验证；不宣称此图证明了层间流水或UART边收边算。

## 仿真实际耗时

| 项目 | 电脑执行时间 | 100MHz对应硬件时间 |
|---|---:|---:|
| 首次新模块编译 | 289.57秒（约4分50秒） | 不适用 |
| 最终正常小链条 | 27.10秒 | 68,635周期＝686.35µs |
| 最终带反压小链条 | 26.54秒 | 70,434周期＝704.34µs |
| 最终两项总流程，复用程序 | 54.84秒，重新编译0秒 | 两次独立仿真，不相加当作单次延迟 |
| 默认DW stride2绕行小例 | 4.20秒，重新编译0秒 | 8,849周期＝88.49µs |

此前初次构建后另跑过一对通过用例（29.16秒、23.86秒），之后增加正负半整数测试向量并复用同一程序得到上述最终结果。不是隐瞒的反复大图重跑。硬件时间包含寄存器配置、顺序调度与本轮检查用流程；正常波形末尾约686.405µs还包含初始复位时间，不能与电脑运行27秒混淆，也不是完整人脸网络耗时。

## 文件及复现

数值格式和参数表见 [整数约定文档](../../docs/mobilefacenet_quant_contract.md)。新代码主要为后处理模块、小链条测试平台以及数据/运行/制图脚本，未修改第三方 NEureka 核心。

Windows生成数据（工程目录）：

```powershell
& 'C:/Users/windows/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' scripts/gen_mobilefacenet_chain.py build/mobilefacenet_chain_data_v2 --image D:/code/facemodel/person_1.jpg
```

WSL运行已有匹配程序：

```text
python3 scripts/run_mobilefacenet_chain.py --reuse --data build/mobilefacenet_chain_data_v2
```

仅RTL或监视器变更时去掉 `--reuse` 重新构建。数据、权重或尺度变化可复用程序，但仍要重新比较金标准。每次结果在独立运行目录。未连接GPU/test1，本轮不需要GPU。
