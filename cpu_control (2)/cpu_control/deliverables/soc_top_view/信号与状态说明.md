# 六模块顶层波形与信号说明

本交付对应新版 face_soc_overlap_top。波形来自本次真实 CPU/UART/19 任务仿真，从复位开始记录；第一层只显示六个大模块的接口及顶层状态，不展开 CPU 流水级、CNN 算子或 PE 内部状态。

当前仿真 UART：25 Mbps，每包 256 字节；收发两端使用一致设置，保留起止位、包 CRC 和整批 CRC。系统时钟仍为 100 MHz。

## 第一层状态机

顶层新增六路并行寄存状态机，不增加第七个模块实例，也不参与功能控制。各路可同时 WORK。状态从上升沿前的真实接口/忙信号采样，在该上升沿后更新，不能将其与边沿后已经变化的组合请求直接逐值比较。
GTKWave 使用 state_names.txt 将两位状态显示为 RESET / IDLE / WORK / FAULT；原始值仍为 0/1/2/3。

| 状态 | 数值 | 含义 |
|---|---:|---|
| RESET | 0 | 复位中 |
| IDLE | 1 | 本模块没有被监测到的工作；CLOCK 表示复位释放等待 |
| WORK | 2 | 模块活动或事务在途；CLOCK 表示内部复位已释放 |
| FAULT | 3 | 观测到该模块支持的故障 |

| 状态信号 | WORK 的依据 | FAULT 与恢复 |
|---|---|---|
| cpu_state | imem_re、数据存储访问、MMIO 访问或 load_req 任一有效 | 当前无 CPU 异常检测输入；FAULT 保留 |
| cnn_state | cnn_status_busy；包括调度、执行、访存排空 | 队列错误或存储故障；监测状态保持至软/硬复位，存储故障本身仍需硬复位 |
| sram_state | CPU 请求、CNN 请求/响应或桥请求/读响应 | cnn_mem_fault；硬复位恢复 |
| imem_state | imem_re 被采样为 1 | 当前无独立 ROM 故障输入；FAULT 保留 |
| bridge_state | bridge_busy | bridge_error；硬复位恢复 |
| clock_state | rst_n 已释放 | 不包含停钟/PLL 失锁检测；FAULT 保留 |

CPU 在轮询或执行末尾自跳转时仍然取指，因此可持续 WORK。这不表示有效业务计算一直发生。IMEM 的状态反映同步读取；SRAM 的 WORK 包括等待仲裁，不能据此判定已完成访问。CPU 数据读取没有独立返回有效线。

soc_active、soc_fault 的 bit0～5 顺序均为 CPU、CNN、DATASRAM、IMEM、IMAGE_BRIDGE、CLOCK。soc_module_state 的 [1:0]、[3:2]、[5:4]、[7:6]、[9:8]、[11:10] 按同样顺序打包。

## 全部信号：功能、源端和目的端

以下名称为顶层连线名。CPU 内部 MMIO 端口名 mmio_* 对应顶层 cnn_mmio_*；CNN 的 status_* 输出对应顶层 cnn_status_*。顶层监测状态是内部可观察寄存器，没有增加封装引脚。每个功能模块的 clk/rst_n 来自 CLOCK。

| 信号 | 位宽 | 从哪里输出 | 到哪里输入/使用 | 功能 | 有效条件 |
|---|---:|---|---|---|---|
| sys_clk | 1 | 外部 | CLOCK | 外部输入时钟；本次仿真周期 10 ns。 | 连续时钟 |
| rst_n_in | 1 | 外部 | CLOCK | 外部低有效复位。 | 0=复位 |
| clk | 1 | CLOCK | CPU CORE,CNN,DATASRAM,IMEM,IMAGE_BRIDGE | 内部工作时钟，当前为 sys_clk 直通。 | 所有同步事务在上升沿采样 |
| rst_n | 1 | CLOCK | CPU CORE,CNN,DATASRAM,IMEM,IMAGE_BRIDGE | 异步置复位、三拍同步释放后的内部低有效复位。 | 0=复位 |
| imem_addr | 32 | CPU CORE | IMEM | 取指字节地址，程序计数器对应的访问地址。 | imem_re=1 且地址有效 |
| imem_re | 1 | CPU CORE | IMEM | 取指读取使能。 | 上升沿为 1 时读取 |
| imem_rdata | 32 | IMEM | CPU CORE | 同步返回的 32 位指令；复位/非法地址返回 NOP。 | imem_re 被采样后的数据 |
| dmem_addr | 32 | CPU CORE | DATASRAM | CPU 数据访问字节地址。 | dmem_re 或 dmem_we |
| dmem_wdata | 32 | CPU CORE | DATASRAM | CPU 写入的数据。 | dmem_we |
| dmem_wstrb | 4 | CPU CORE | DATASRAM | 字节写掩码；bit i 控制数据位 [8i+7:8i]。 | dmem_we |
| dmem_re | 1 | CPU CORE | DATASRAM | CPU 数据读取使能，固定一拍响应。 | 上升沿采样 |
| dmem_we | 1 | CPU CORE | DATASRAM | CPU 数据写入使能。 | 上升沿采样 |
| dmem_rdata | 32 | DATASRAM | CPU CORE | CPU 固定一拍读返回值；没有单独 ready/rvalid。 | dmem_re 被采样后有效 |
| cnn_mmio_addr | 32 | CPU CORE | CNN | CNN 寄存器字节地址，基址 0x40000000。 | cnn_mmio_re 或 cnn_mmio_we |
| cnn_mmio_wdata | 32 | CPU CORE | CNN | 寄存器写数据；CONTROL=0x3D 启动队列，bit1 软复位。 | cnn_mmio_we && cnn_mmio_ready |
| cnn_mmio_re | 1 | CPU CORE | CNN | CNN 寄存器读使能。 | cnn_mmio_ready=1 时完成 |
| cnn_mmio_we | 1 | CPU CORE | CNN | CNN 寄存器写使能。 | cnn_mmio_ready=1 时接受 |
| cnn_mmio_rdata | 32 | CNN | CPU CORE | 寄存器读返回值；STATUS bit0 busy、bit1 done、bit2 error。 | cnn_mmio_re && cnn_mmio_ready |
| cnn_mmio_ready | 1 | CNN | CPU CORE | 地址选中且有 MMIO 请求时的组合就绪信号。 | 与 re/we 同周期 |
| load_req | 1 | CPU CORE | IMAGE_BRIDGE | CPU 请求加载一批资料；完成后 CPU 拉低确认。 | 四阶段握手中的请求电平 |
| load_complete | 1 | IMAGE_BRIDGE | CPU CORE | 本批加载已经结束，成功和失败都会结束；必须同时检查 load_error。 | 保持到 CPU 撤销 load_req |
| load_error | 1 | IMAGE_BRIDGE | CPU CORE | 加载失败标记，如 CRC、超时、内存错误。 | load_complete=1 时判断结果 |
| cnn_valid | 11 | CNN | DATASRAM | 11 个客户端的独立请求有效位。 | valid[i] && ready[i] 在上升沿接受 |
| cnn_write | 11 | CNN | DATASRAM | 对应通道为 1 写、为 0 读。 | 对应通道 valid=1 |
| cnn_byte | 11 | CNN | DATASRAM | 对应通道为 1 表示字节访问，0 表示对齐的 32 位字访问。 | 对应通道 valid=1 |
| cnn_addr | 352 | CNN | DATASRAM | 11×32 位字节地址；通道 i 使用 [32i+31:32i]。 | 对应通道 valid=1，未接受前保持 |
| cnn_wdata | 352 | CNN | DATASRAM | 11×32 位写数据；字节写使用该通道最低 8 位。 | 对应通道 valid && write |
| cnn_cancel | 1 | CNN | DATASRAM | CNN 软复位取消请求/未消费响应；不回滚已经写入的 SRAM。 | 高有效 |
| cnn_ready | 11 | DATASRAM | CNN | 每个通道获得对应存储体服务的就绪位。 | 与 valid 同周期为 1 才接受 |
| cnn_response | 11 | DATASRAM | CNN | 逐通道完成响应，读和写都有响应。 | 请求接受后的寄存完成周期 |
| cnn_rdata | 352 | DATASRAM | CNN | 11×32 位读返回值；字节读取符号扩展。 | response[i]=1 且对应事务是读 |
| cnn_mem_fault | 1 | DATASRAM | 顶层 | CNN 非法地址/非对齐字访问故障锁存；送状态监测和 LED 组合逻辑。 | 保持到系统复位；软复位不清除 |
| io_mem_req | 1 | IMAGE_BRIDGE | DATASRAM | 图像桥存储请求。 | req && gnt 在上升沿接受 |
| io_mem_we | 1 | IMAGE_BRIDGE | DATASRAM | 1=写入 SRAM，0=读取；当前主动加载流程主要写。 | io_mem_req |
| io_mem_addr | 32 | IMAGE_BRIDGE | DATASRAM | 对齐的 32 位字访问地址。 | io_mem_req |
| io_mem_wdata | 32 | IMAGE_BRIDGE | DATASRAM | 桥写入 SRAM 的字数据，配合 be 选择目标字节。 | req && we |
| io_mem_be | 4 | IMAGE_BRIDGE | DATASRAM | 写字节使能；读请求要求为 0。 | req && we 时不得全零 |
| io_mem_gnt | 1 | DATASRAM | IMAGE_BRIDGE | 桥访问已被接受；当前写操作在该接受边沿完成。 | 与 io_mem_req 同周期 |
| io_mem_rvalid | 1 | DATASRAM | IMAGE_BRIDGE | 桥的读返回有效；写操作不用该信号。 | 对应已接受的读请求 |
| io_mem_rdata | 32 | DATASRAM | IMAGE_BRIDGE | 桥读回的 32 位数据。 | io_mem_rvalid=1 且 error=0 |
| io_mem_error | 1 | DATASRAM | IMAGE_BRIDGE | 桥访问错误；写错误与 gnt 同期，读错误与 rvalid 同期。 | 写 gnt 或读 rvalid 有效期 |
| uart_rx | 1 | 外部 | IMAGE_BRIDGE | 外部设备向 SoC 发送串口回复。 | UART 空闲为高，8N1 |
| uart_tx | 1 | IMAGE_BRIDGE | 外部 | SoC 向外部设备发送 IMIO 请求。 | UART 空闲为高，8N1 |
| bridge_ready | 1 | IMAGE_BRIDGE | 顶层 | 桥的就绪状态，用于顶层 led_ready。 | 实际 ready 输出 |
| bridge_busy | 1 | IMAGE_BRIDGE | 顶层 | 桥正在执行加载事务。 | 实际 busy 输出 |
| bridge_error | 1 | IMAGE_BRIDGE | 顶层 | 桥失败锁存状态，用于监测和 led_error。 | 系统复位恢复 |
| cnn_status_busy | 1 | CNN | 顶层 | 新增观测输出，队列、执行单元或访存排空仍忙。 | 高=存在未完成工作，不等于 PE 每周期乘加 |
| cnn_status_done | 1 | CNN | 顶层 | 新增观测输出，队列完成脉冲。 | 不是 MMIO 中的 sticky done |
| cnn_status_error | 1 | CNN | 顶层 | 新增观测输出，队列错误脉冲。 | 顶层 cnn_state 保持 FAULT 至软/硬复位 |
| led_ready | 1 | 顶层 | 外部 | bridge_ready && !cnn_mem_fault。 | 高有效；不是 CNN 完成标志 |
| led_busy | 1 | 顶层 | 外部 | 等于 bridge_busy。 | 不代表 CNN busy |
| led_error | 1 | 顶层 | 外部 | bridge_error || cnn_mem_fault。 | 未包含 CNN 描述符错误 |
| cpu_state | 2 | 顶层监测逻辑 | 波形观察 | CPU CORE 的寄存观测状态：0 RESET、1 IDLE、2 WORK、3 FAULT。 | 每个上升沿采样后更新；不控制功能模块 |
| cnn_state | 2 | 顶层监测逻辑 | 波形观察 | CNN 的寄存观测状态：0 RESET、1 IDLE、2 WORK、3 FAULT。 | 每个上升沿采样后更新；不控制功能模块 |
| sram_state | 2 | 顶层监测逻辑 | 波形观察 | DATASRAM 的寄存观测状态：0 RESET、1 IDLE、2 WORK、3 FAULT。 | 每个上升沿采样后更新；不控制功能模块 |
| imem_state | 2 | 顶层监测逻辑 | 波形观察 | IMEM 的寄存观测状态：0 RESET、1 IDLE、2 WORK、3 FAULT。 | 每个上升沿采样后更新；不控制功能模块 |
| bridge_state | 2 | 顶层监测逻辑 | 波形观察 | IMAGE_BRIDGE 的寄存观测状态：0 RESET、1 IDLE、2 WORK、3 FAULT。 | 每个上升沿采样后更新；不控制功能模块 |

| soc_module_state | 12 | 顶层监测逻辑 | 波形观察 | 每模块两位，低到高：CPU、CNN、DATASRAM、IMEM、IMAGE_BRIDGE、CLOCK。 | 六路并行状态打包 |

## CNN 的 11 路通道

三条 352 位总线均为 11×32 位。通道 i 位于 [32i+31:32i]；11 位控制向量中 bit i 对应该通道。低位是通道 0。

| 通道 | 使用者 |
|---|---|
| 0 | 描述符读取 |
| 1 / 2 | 计算上下文 0 加载 / 写回 |
| 3 / 4 | 计算上下文 1 加载 / 写回 |
| 5 | ReLU6 |
| 6 | ADD |
| 7 | ReLU |
| 8 | PReLU |
| 9 | MaxPool |
| 10 | Requant |

看 cnn_valid & cnn_ready 确认哪一路请求在该边沿接受；看 cnn_response 确认完成。地址、写数据、读数据在无有效事务时可以保持旧值，不能把总线上任意数值当作一次访问。四个 bank 同周期最多接受四路 CNN/桥访问，CPU 优先占用其命中的 bank。

图中 cnn_valid/write/byte 合计 33 位，cnn_ready/response 合计 22 位；cnn_addr、cnn_wdata、cnn_rdata 各 352 位。旧图中的单路 mem_* 接口已不适用于新版。
