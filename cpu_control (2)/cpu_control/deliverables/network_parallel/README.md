## 波形

- [正常双核](dual.png)，双击open_dual.cmd打开GTKWave。
- [实例0限速](skew_stall.png)，双击open_skew_stall.cmd打开GTKWave。

每个视图15条不重复信号，已用GTKWave加载验证。蓝色属于卷积核0，绿色属于卷积核1，橙色属于后处理，紫色DW7，青色补边。*_busy高表示该算子执行中；同组*_node为任务号，*_frame为图片号，仅在busy期间有意义。正常图可看到同一个卷积核先后处理不同帧。限速图中核0仍忙时，核1和后处理继续推进另一帧。

completion_pulse为5位完成掩码，位0/1卷积核，位2后处理，位3 DW7，位4补边；表示该任务写回已经结束。completed_count是累计完成条数，结束应为26。done升高发生在最后采样点，图中标注边界，不延长原始波形。短脉冲和末端计数请在GTKWave放大。帧号由实际任务号与命令表解码，*_busy来自实际operator_busy位，不是手绘时序。原始control.vcd、事件与分配表另有保存。

## 必须区分的验证范围

小数据测试是两张不同真实人脸的前三层ROI链，加独立Add、DW7和补边探针。DW7使用真实7×7×512前缀特征，**不是三层ROI后直接算完整网络**。只在容量测试中使用746条全网命令；该测试算子为延迟模型，不进行卷积数值计算。

新入口暂时保留全部中间结果，没有旧三槽释放逻辑，没有生产容量约束、动态地址复用或UART边收边算。原来的完整单图顺序PASS和旧残差并行入口均保留。设计与对接细节见[接口说明](../../docs/network_parallel_design.md)。下一步应落实中间缓冲生命周期和容量，再扩大实际数值验证。
