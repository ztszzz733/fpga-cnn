# 存储侧阶段改动与联调状态（供 CPU／PS／CNN 方同步）

日期：2026-11-11

开发分支：`bai-datasram`
对应存储实现提交：`ab7f2c0aaa26a4c793c61500d07debfacfbd8e78`

## 先看结论

本轮约定的**可独立开发的存储模块及验证**已经形成可复现交付：可下载 IMEM／CPU RAM、最小 DATA MOVER、按行 tile 搬运、本地 tile BRAM 和参数化加载器 CSR 均有 RTL、测试及 XC7Z020 独立综合结果。`tile_dma_system` 和 `program_loader_top` 两个**存储子系统验证顶层**通过仿真。

**生产 SoC 顶层尚未接入这些新模块，尚无“真实 CNN＋新 MOVER＋PS DDR＋CPU／加载服务”的同顶层测试，也未上板。** 现有生产 filelist 仍编译原存储模块。因此本交付应称为“存储侧独立开发与子系统联调通过”，不能称为“整机顶层联调或硬件验收通过”。

## 与改造前相比

| 项目 | 改造前基线 | 本分支新增、已验证的能力 |
|---|---|---|
| IMEM | 初始化内容的同步 ROM | 可停机下载、回读、字节写，CPU 取指仍固定一拍；8／16／64 KiB 档位通过测试 |
| CPU 本地数据 | 旧存储系统中的固定时序本地 RAM | 独立可下载 16 KiB RAM；真实 Control＋Datapath 执行下载的 RV32I 程序，验证 `.data/.bss`、字节访存和应用重启 |
| 大数据搬运 | 旧 DDR/cache 路线可作诊断基线 | 新增单命令 DDR↔本地 DATA MOVER，支持本地非对齐 byte 起址、短尾、4 KiB 边界、背压、错误和在途排空 |
| 分块数据 | 缺少新 MOVER 对真实 tile 布局的联调 | 新增逐行命令控制器和 32 KiB 双端口 tile BRAM；计算端同字访问优先于 DMA；两组 CNN 交接 tile 的真实搬运表已通过存储链路测试 |
| 程序加载控制 | 无本方案的独立 PROGRAM_LOADER | 新增可参数化的 CSR 服务端，连接真实 IMEM／CPU RAM，验证下载、回读、拒绝非法访问与复位保留 |

这些新文件放在 `storage_v2/` 下。原生产 Datapath、Control、CNN 算子及生产 filelist 没有被替换；新旧入口不能混称为同一个已验收系统。

## 验证依据与边界

| 验证层次 | 本次结果 | 不能推出的结论 |
|---|---|---|
| 旧 DDR/cache 诊断 | 826 项检查通过；128 KiB cache＋旧真实 CNN＋模拟 DDR 的两种 tile、8 场景通过 | 不能代替新 MOVER 的完整 CNN 联调；四图完整网络缺少匹配的冻结数据，未复跑 |
| 新 MOVER 单元 | 136 个交接包搬运、100 个随机跨页搬运，以及非法命令、错误和超时用例通过 | 单元本地端是时序模型，不是实际 PS DDR |
| 新 tile 存储子顶层 | 两种 tile，12 组、40 行搬运通过；真实本地 BRAM 与模拟 AXI3 DDR 的目标和保护字节均核对；包含同字冲突、配置变化、撤销准入和末行越界检查 | CNN 运算未在这条新链路执行；输出由冻结 golden 经计算端写入后再搬回 |
| 加载器子顶层 | CSR＋真实 IMEM／CPU RAM 的下载、回读、边界、运行中拒绝和复位保留通过 | 尚无 GP0 AXI3 从设备、RFW1/RDL1 安装服务及硬件安全停机接线 |
| XC7Z020 OOC 综合 | 最新 tile 链路为 1223 LUT、662 FF、8 RAMB36、0 DSP；加载器＋64 KiB IMEM＋16 KiB CPU RAM 为 354 LUT、250 FF、20 RAMB36、0 DSP | 两项是各自独立综合，不能直接相加作为整机占用；无布局布线、时序签核和上板结果 |

复现命令、接口语义和测试清单见 [README.md](README.md)，机器可读状态见 [verification_summary.json](verification_summary.json)，仿真和综合摘录见 `evidence/`。目标板按 EES331／XC7Z020-CLG484-1 检查。

## 仍需对接的工作

1. **PS／板级：**确认 DDR 物理保留区、HP0／GP0 地址与时钟复位、DDR 初始化及缓存所有权交接；将新 AXI3 主机接真实 HP0，完成板级往返、自检和错误恢复。当前仿真中的 DDR 基址只是模型配置。
2. **CPU／软件：**将可下载 IMEM、CPU RAM 与生产 CPU 安全停机、应用／服务复位连接；确定 GP0 加载窗口与寄存器偏移，完成 AXI 从设备、RFW1/RDL1 安装、回读校验、更新失败重试和 SD 提交。现有 CSR 只是在 GP0 桥后级的候选接口。
3. **CNN／存储：**确定正式 CNN→MOVER 适配 RTL 和 tile 缓冲所有权、完成条件、错误传递；运行真实 CNN 算术经过新 tile 搬入／写回链路的同顶层测试。旧 cache 路线的算术通过记录不能替代这一项。
4. **系统整合：**选定唯一生产顶层和 filelist，完成 CPU＋CNN＋新存储＋PS 的系统仿真、整机综合、布局布线、时序及上板验收。四图完整网络需补齐匹配的冻结数据后再复跑。

算子数量和整板资源容量优化按此前约定留到最终整合阶段；本说明不把独立综合数字解释为整机可装入结论。
