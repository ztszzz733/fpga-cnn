# 什么时候等，什么时候继续

CPU 会同时处理几条处在不同阶段的指令。前一条结果还没准备好时，后一条不能直接使用旧数据。

## 情况一：结果已经算好

前一条算出 11，后一条马上要把它写入内存。如果结果已可用，就直接送给后一条使用，不必等它先写进寄存器。这叫“前递”。

若两个较早指令都写同一个寄存器，要使用其中较新那条的结果。当前约定优先用访存阶段的非读内存结果，其次用写回阶段的最终结果，最后才用原寄存器值。

两个操作数各自选择来源，写内存的数据也需要检查依赖。跳转指令可传递的结果是返回地址，不是跳转目标。

## 情况二：结果还在读取中

先读内存得到 42，再加 7。读取尚未完成时：

1. 后一条先等一拍，取指位置也保持。
2. 读内存的前一条继续前进，不能一起停住。
3. 下一拍数据已经进入写回阶段，后一条取得 42，算出 49。

中间空出的位置叫“气泡”，不会改变寄存器或内存。这个一拍等待只在当前固定时序条件下成立，真实存储器还需验证。

特别注意：读内存时算出的地址不是读到的数据；若最新数据仍未到达，也不能退回使用更早指令写出的旧值。

## 情况三：决定跳转

CPU 提前取了后面的指令，但执行阶段发现要跳到别处。这时要更新取指地址，并取消错误路径上的年轻指令，让它们不能写寄存器或内存。

当前执行的跳转指令本身仍向后推进，保留它应写入的返回地址。通过寄存器计算跳转目标时，目标最低位按指令要求清零。

## 同时发生几件事，谁优先

| 顺序 | 处理 |
|---|---|
| 1 | 复位，清空执行状态并输出安全控制 |
| 2 | 已确定跳转，切换路径并取消错误指令 |
| 3 | 数据尚未就绪，让后续指令等待 |
| 4 | 正常推进 |

判断依赖时只检查指令真正使用的寄存器；不能把立即数中的数字误当作寄存器编号。无效指令和寄存器 0 不应引起错误等待。
