# 协作时遵守哪些约定

> 2026-09-14 P1 更新：M / Control 已正式接受 C1 v1.0 开发基线；当前确认及待办以 [P1 正式回复](../../docs/control_reply_to_P1.md) 为准，验证以 [本次报告](../../docs/verification_report.md) 为准。下文保留此前说明，不作为最新冻结状态。

这些约定用于避免不同负责人各改一套。根目录 `AGENTS.md` 仍是工具读取的原位置，本页是给人阅读的解释。

## 开发范围

你负责控制模块。正式数据通路和 CNN 实现由其他负责人提供，不能把测试模型当成他们的成品。

原始规格和任务书保留；后续选择通过对接说明和改动记录补充，不回头把建议改写成“早已确定”。

## 代码保持怎样的分工

控制模块直接根据当前输入产生输出，所有跨阶段保存由数据通路负责。CNN 调用流程属于软件，不给控制模块新增直接读取 CNN 状态的硬件端口。

当前接口已获对方原则接受，但公共地址、系统复位和真实存储时序尚未最终确定。精确接线以同一版本的共享定义和接口表核对。

## 测试怎样记录

统一使用项目的 Python 测试入口。默认设置下按 [测试教程](test.md) 的短命令即可完成完整检查和绘图。

每次产生独立结果目录，用本次日志和波形判断，不能把旧图片当作新结果。真实数据通路未接入时，只报告控制和测试模型通过。

## 网络怎样处理

复用已经确认的代理设置；只在实际请求失败或要求排查时诊断。配置子进程代理不代表修复了已运行桌面应用的连接。具体见 [联网说明](联网说明.md)。
