# 怎样核对结果对应的是哪份代码

> 2026-09-14 P1 更新：M / Control 已正式接受 C1 v1.0 开发基线；当前确认及待办以 [P1 正式回复](../../docs/control_reply_to_P1.md) 为准，验证以 [本次报告](../../docs/verification_report.md) 为准。下文保留此前说明，不作为最新冻结状态。

除了文字报告，项目还保存了一份 JSON 记录，方便核对测试日期、工具、结果和代码版本。平时只看 [测试结果说明](测试结果说明.md) 就够了。

## 需要追查时看这些字段

| 字段 | 中文含义 |
|---|---|
| `date` | 这份记录的日期 |
| `primary_runs` | 主要测试结果文件的位置 |
| `result` | 场景数、检查数和失败数 |
| `versions` | 使用的工具版本 |
| `sha256` | 每个文件当时的校验值，用于比较内容是否改变 |
| `historical_baseline` | 以前的验证记录，不能当成本次新增用例的证据 |

校验值可以理解为文件内容的指纹。两份内容相同的文件应有相同值；代码后来改过，就不能直接用旧日志声称新代码已通过。

## 使用时注意

记录中写着“未运行”的项目仍然未运行。JSON 中的项目相对路径以 `D:\cpu_control` 为起点，不是以本说明文件夹为起点。

本次只整理文档，保留已有代码测试结论。说明整理本身的对应表和检查结果在 [总目录](../README.md) 下提供。
