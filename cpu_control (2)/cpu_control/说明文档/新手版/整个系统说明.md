# CPU 与 CNN 怎样合作

## 2026-10-08 六模块实际实现更新

当前板级顶层为 `rtl/soc/face_soc_top.sv`：六个平级大模块 `cpu_core / cnn / datasram / IEM / image_bridge / clock_unit`。CNN 的原生 mem_* 直接接 datasram，**不经过 CPU**；B 口仲裁和读写完成时序已写进 datasram 内部，不再实例化旧 CPU 存储子系统、独立适配器或系统 B 仲裁器。CPU A 口保留固定一拍，Control C1 和原 Datapath 计算模块不变。

UART 图像桥和时钟复位模块本次已有实际 RTL。图像桥为 IMIO 分块读写 + CRC32；时钟直通、复位三拍同步释放。封装 7 根数字 I/O，busy 灯是图像桥忙，不是 CNN busy。CNN 自带 MMIO：QUEUE_BASE=+0x08、TASK_COUNT=+0x18、START=0x3D；图像桥 error 保留，CNN 存储错误锁存 cnn_mem_fault，恢复需系统复位。

当前接线以 [顶层三组线小白说明](../../SoC顶层连线与总体IO说明_小白版.md) 为准；另见 [六模块图](../../docs/SoC芯片封装与内部IO层级连接图.md)、[修改说明](../../docs/CNN实际代码整合修改说明_小白版.md)、[UART 协议](../../docs/uart_image_bridge_protocol.md)、[本次验证](../../docs/soc_six_module_verification_20261008.md)。编译清单 `rtl/filelists/system_cnn.f`；测试 `python scripts/run_cnn_integration.py`。

## 三部分各做什么

| 部分 | 职责 |
|---|---|
| CPU 控制模块 | 识别指令、安排运算、等待和跳转，是你负责的部分 |
| CPU 数据通路 | 保存指令和数据、执行运算、访问内存、连接 CNN 寄存器 |
| CNN 加速器 | 搬运图片和权重，做卷积等运算，把输出写回内存 |

程序和数据使用不同存储器。CPU 采用五级流水线，就是把取指、识别、执行、访存、写回分成五步，使不同指令可以交错推进。

## 一次计算的大致过程

1. 测试平台先放入程序、图片、权重等数据。
2. CPU 写入 CNN 需要的地址、图片尺寸、通道数和计算参数。
3. 最后发出启动命令。
4. CNN 从数据内存读取输入，执行计算，再把结果写回指定位置。
5. CPU 查询状态，完成后配置下一层；出错或长时间不完成时由软件处理。
6. 最终由 CPU 读取分类分数，或用特征向量完成数据库匹配。

固定 CNN 接口没有数据库地址、人员编号或匹配分数专用端口，因此不能默认 CNN 已经承担数据库匹配。

## CNN 为什么有九个寄存器

一个用于发命令，一个用于读状态；其余七个保存输入、输出、权重、偏置地址，图片尺寸、通道数和计算参数。

CPU 使用普通读写指令访问它们。启动和软件复位由数据通路转成一拍脉冲；CNN 提供忙、完成和出错状态。具体参数位域、完整访问地址及状态清除规则需要共同确认。

CPU 与 CNN 推荐分别使用双口数据内存的 A、B 口。CNN 搬运真实数据还有自己的内存访问接口，不能靠九个配置寄存器传输整张图片。

## 三方必须说清楚的数据格式

原草案建议图片特征和权重使用有符号 8 位整数，偏置和累加使用 32 位整数；张量和权重按约定顺序排列。颜色顺序、字节打包、量化、饱和、激活和池化顺序都要一致。

最好先共同手算一个很小的例子，确认每个字节放在哪里、每个输出是多少，再扩大到完整网络。原版保留所有推荐位域和布局表，建议值不能自动当成最终确认值。

## 推荐怎样验收

先确认接口；各自用测试模型开发；再接真实 CPU；然后验证 CPU 与 CNN 寄存器和内存访问；最后比较一层卷积和完整图片的结果。

第一版不包括操作系统、缓存、多核和浮点等功能。当前 Control 先支持约定的 37 条基础指令，乘法扩展、最终识别模式和真实系统验收另行确定。现有控制测试通过不能跳过后面的系统验证。
